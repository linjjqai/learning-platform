## 速览（30 秒看完）

- 写 5–7 条，一条一个结论，让人不点开视频也知道这一课讲什么
- 每条控制在 40 字以内，能用「谁 + 做什么 + 结果」表达最好
- 这一节是首页 / 天数页卡片的摘要来源，也是搜索命中最多的区域

## 核心要点

- **要点名**：一段解释。用「**加粗短语**：展开说明」的写法，页面会自动变成编号卡片
- 一条只讲一个知识点，能独立看懂，不要写“如上所述”“接着讲”
- 关键数字、口径、判断条件要写全（例如 ARR 只算周期性费用、多年合同按年折算）

## 结构与流程

适合放 ASCII 结构图、步骤链、对比表。代码块会保留等宽排版：

```
业务流程
├─ 售前：获取客户 → 客户跟进
├─ 售中：商机跟进 → 签订合同
└─ 售后：实施交付 → 服务运营
```

## 术语表

必须写成两列表格，第一列术语、第二列含义；页面会把每行渲染成术语卡片，
并自动汇总到「术语总表」，同时用于自动生成随堂自测题。

| 术语 | 含义 |
| --- | --- |
| ARR | 年度周期性合同金额，只统计周期性费用，多年合同按年折算 |
| POC | Proof of Concept，方案验证测试，只在大型项目里做 |

## 需要注意的点

1. 用有序列表写“最容易搞错/最容易踩坑”的地方，页面会渲染成警示卡片
2. 每条写清「错在哪 → 正确做法」，比只写“注意 XXX”有用
3. 建议 3–6 条

每张图一行，图片说明末尾用括号写视频时间点，页面会自动生成时间角标：

## 使用说明（写完可删掉这一段）

1. 新建课时用脚手架：`pnpm new lesson <课程ID> L99 "课时标题" --day 1`，会生成到 `content/courses/<课程ID>/lessons/L99.md`
2. `day` 字段决定它归到第几天（导航、天数页、进度条都按它分组）
3. `order` 决定目录里的排序，脚手架会自动取最大值 +1
4. `video` 填 mp4/webm 直链会渲染 `<video>` 播放器；填网页地址（如 B 站/云盘嵌入页）会渲染 iframe
5. `quiz` 可以留空——平台会用本课术语表自动出 3–5 道选择题；手写题目会排在最前面
6. 章节标题不用完全照抄，平台按关键词识别：「速览 / 核心要点 / 结构与流程 / 术语 / 注意 / 截图 / 时间轴」，缺哪节就不渲染哪节
