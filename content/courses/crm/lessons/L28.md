# 速览（30 秒看完）

- 权限分三层：管理功能权限管"能进后台做什么"，业务功能权限管"CRM 里能操作哪些对象和字段"，数据权限管"能看哪些数据"。
- 管理功能权限入口：管理后台 → 角色权限管理 → 管理功能权限；预置角色权限固定不可改，自定义角色可自由勾选。
- 业务功能权限入口：管理后台 → 角色权限管理 → 业务功能权限，下分员工角色分配、角色权限设置、审批权限三块；一人多角色，权限叠加。
- 字段权限四种：读取、编辑、导出、显示；主属性字段不能取消读取，销售订单里的提成字段可以设为"不显示"。
- 数据权限五类＋"其他"：基础数据权限、部门内数据权限、数据共享、相关团队数据权限、临时权限，外加无权限时星号脱敏。
- 数据共享按四种范围选数据：基于数据负责人、基于数据归属组织、基于数据归属部门、基于条件；来源部门默认含子部门，共享到的部门默认不含。
- 临时权限只给待处理的审批流和待处理的业务流程，不能当日常数据范围用。
- 查某人对某条数据为什么有/没有权限，用 管理后台 → 数据维护工具 → 数据权限查询工具。

## 核心要点

- **"用多少"就是权限**：一套系统由四块组成——谁能用（部门、人员、岗位、角色）、用什么（模块，模块由字段组成）、用多少（增删改查、能用哪些模块、能看哪些数据）、怎么用（业务在系统里的流转顺序）。本课讲"用多少"，主体是管理功能权限和业务功能权限，数据权限是其中"能看哪些数据"的部分。
- **管理功能权限**：决定员工在系统里能执行哪些管理操作，包括系统设置、组织架构管理、角色权限分配等核心管理功能，侧重于系统层面的管控能力。配置位置：管理后台 → 角色权限管理 → 管理功能权限。
- **预置角色与自定义角色**：系统提供两类管理角色——预置管理角色（系统默认，如系统管理员、组织架构管理员、集成管理员、服务通管理员）和企业自建的自定义管理角色（如"测试管理角色"）。给员工分配管理角色后，才能设置对应模块，也才能看到该角色有哪些权限；预置管理角色的权限是固定的，改不了。
- **业务功能权限**：决定员工能执行哪些具体业务操作，包括查看、编辑、删除等基础操作，以及业务流程相关的特殊操作，与数据权限共同构成完整的权限体系。配置位置：管理后台 → 角色权限管理 → 业务功能权限，下面分员工角色分配、角色权限设置（对象操作＋字段权限）、审批权限三块。
- **员工角色分配**：员工要用 CRM，必须在这里被加到对应角色上；角色具备哪些操作权限，要到"角色权限设置"里配。典型场景：新销售入职、开通员工账号后，在"销售人员"角色下把该员工添加进来。
- **一人多角色，权限叠加**：一个人可以同时拥有多个角色，权限自动累加；自定义角色还能勾选"复制"，直接复制其他角色的权限（如复制销售人员、布局人员的权限）。
- **角色权限设置**：左侧是系统预置的 CRM 角色，右侧是这个角色具备的功能权限和字段级权限。要禁止导出客户数据，就在这里对每个角色取消勾选客户对象的"导出"。
- **字段权限四种操作**：读取——既能看见也能编辑；编辑——是否可以编辑该字段；导出——是否可以导出该字段；显示——该字段是否出现在对象列表页的"筛选项"和"字段设置项"里。
- **主属性字段不能取消读取**：主属性（对象名称）字段不支持取消读取权限，想靠字段权限把名称藏起来做不到。字段权限的实用场景是：销售订单里加了一个算提成的字段但不想让销售看到，就在销售人员角色下把该字段设为"不显示"。
- **综合案例（张三 / 李四）**：张三做销售，只需客户、商机、销售订单，要能录入和修改、不允许导出、不用销售线索；李四做售后，只能查看这三类对象，不能录入和修改，且看不到销售订单的"订单金额"和订单产品里的金额。落到配置上就是：张三给新建＋编辑、不给导出；李四只给读取，再把订单金额、订单产品金额两个字段收回读取。
- **FAQ：看不到 CRM 模块**：说明这个人还没被加 CRM 角色，到 管理 → 角色权限管理 → 业务功能权限 → 员工角色分配 里加上即可。
- **FAQ：删除权限不在角色里**："删除销售线索"这类操作不对角色开放，删除只能由 CRM 管理员在管理后台回收站里做。销售人员角色可以配置更换负责人/处理人、发起业务流程、编辑相关团队成员。
- **FAQ：字段级差异化控制**：售后人员能编辑客户的"规模"但不能改"联系电话"——在 角色权限设置 → 客户 → 设置字段权限 里，给"规模"开编辑、给"联系电话"不开，两个字段分开配就行。
- **FAQ：只允许线索转化新建**：在销售人员角色权限设置里取消客户、商机、联系人的"新建"权限，销售就只能靠线索转化产生这三类数据，不能手动新建。
- **数据权限管"能看多少数据"**：主要设置包括基础数据权限、部门内数据权限、数据共享、相关团队数据权限、临时权限，另有"其他"一项。基础数据权限针对全公司 CRM 模块、遵循负责人逻辑；部门内权限针对部门统一设置数据的查看；数据共享是把某人名下的一批数据给指定部门或人员看；相关团队权限按团队成员角色设；临时权限给待办处理人临时赋权。
- **基础数据权限三档与私有的可见人**：分公开只读、公开读写、私有。例：客户信息仅负责人可见（私有）、产品信息全员可见（公开）。私有数据谁能看见——数据负责人本人、他的汇报对象、部门负责人、相关团队成员、CRM 管理员。
- **部门内数据权限**：按部门统一设置数据的查看。场景：某销售部门的客户由部门销售一起联合跟进，需要互相看到彼此名下的客户。配置页每个选项后面有小问号，点开就是该选项的含义。
- **数据共享的四种范围**：①基于数据负责人——按负责人、负责人主属部门、用户组或 CRM 角色确定数据范围；②基于数据归属组织——把指定组织作为归属组织的数据共享给其他人员/部门；③基于数据归属部门——从数据归属部门的角度确定共享范围；④基于条件——按对象里符合某些条件的数据共享。其中"基于数据归属组织"需要开通多组织才能使用。
- **共享设置的子部门规则（易错）**："数据来源于"选的部门默认包含其下子部门（选销售中心，销售中心下的子部门算在内）；"数据共享到"选的部门默认不包含子部门。场景：售后要看销售部的客户，用基于数据负责人共享；财务要看销售中心的订单和回款但不能编辑，用基于数据归属部门共享；来源是"客户介绍"的线索要给市场人员看，用基于条件共享。
- **主属部门 ≠ 归属部门**：销售在华北大区新建一条销售订单，主属部门和归属部门都是华北大区；之后他调岗到华南大区，这条老订单的主属部门自动变成华南大区，归属部门仍是华北大区。这样设计是为了业绩核算准确——历史业绩不会因为人调岗被带走。
- **相关团队数据权限**：相关团队有三个系统预置角色——普通成员、联合跟进人、售后人员。可以按不同相关团队角色，分别设置他们对关联对象（如该客户下的下级客户、退货单）的查看权限。场景：销售要申请售前顾问介入，把售前加进客户的相关团队，售前就能看客户详情。
- **临时权限只覆盖待办**：仅针对待处理的审批流、待处理的业务流程。处理人本来没有权限看这条待办数据时，临时赋权让他短期能看。场景一：销售订单审核由财务做，但不希望财务审完还能看；场景二：合同盖章申请，法务审完合同就不需要再看。
- **"其他"里的星号脱敏**：勾选后，对线索、客户、商机2.0、拜访、产品名称这五类对象没有查看权限的员工，在工作界面看到对应数据时，关键信息显示为星号。
- **数据权限查询工具**：想知道某位同事对某条数据到底有没有权限、为什么，去 管理后台 → 数据维护工具 → 数据权限查询工具，输入对应信息查询。

## 结构与流程

权限体系（三层）：

```
第一层 管理功能权限（系统层面管控能力）
 配置入口：管理后台 → 角色权限管理 → 管理功能权限
 系统预置：系统管理员、组织架构管理员、集成管理员、服务通管理员（权限固定不可改）
 自定义：可勾选任意管理能力组合，如"测试管理角色"
 员工分配：给员工分配管理角色后才可设置对应模块

第二层 业务功能权限（对象级操作权限 + 字段级权限 + 审批权限）
 配置入口：管理后台 → 角色权限管理 → 业务功能权限
 员工角色分配：加角色才看得到对应 CRM 模块（新销售入职走这里）
 角色权限设置：左侧预置 CRM 角色，右侧该角色的功能权限与字段级权限
   · 对象操作：查看列表/详情、新建、编辑、作废、导入、导出、更换负责人等
   · 字段权限：读取 / 编辑 / 导出 / 显示（主属性字段不可取消读取）
 审批权限：配置审批部门范围（当前部门+下属部门）
 一人多角色权限叠加；自定义角色可复制其他角色权限

第三层 数据权限（能看到哪些具体数据）
 配置入口：管理后台 → 数据权限管理
 ① 基础数据权限：公开只读 / 公开读写 / 私有
    私有可见人：负责人本人、汇报对象、部门负责人、相关团队成员、CRM 管理员
 ② 部门内数据权限：按部门统一设置数据的查看
 ③ 数据共享：四种范围选一
     基于数据负责人（负责人 / 主属部门 / 用户组 / CRM 角色）
     基于数据归属组织（需开通多组织）
     基于数据归属部门（按业绩归属口径）
     基于条件（对象里符合条件的数据）
     数据来源于：默认含子部门；数据共享到：默认不含子部门
 ④ 相关团队数据权限：普通成员 / 联合跟进人 / 售后人员，按角色设关联对象权限
 ⑤ 临时权限：仅待处理的审批流、待处理的业务流程
 ⑥ 其他：无查看权限时关键信息显示星号（线索、客户、商机2.0、拜访、产品名称）
```

数据权限配置场景→方法映射：

| 场景 | 推荐方式 |
| --- | --- |
| 产品标准价全公司可见 | 基础数据权限 → 公开只读 |
| 客户信息仅负责人可见 | 基础数据权限 → 私有（负责人、汇报对象、部门负责人、相关团队、CRM 管理员可见） |
| 【案例库】全员可见但不可改 | 基础数据权限 → 公开只读 |
| A/B 部门及下属看归属部门数据 | 部门内数据权限 |
| 财务看全公司销售订单 | 数据共享（基于数据归属部门，共享全部订单给财务） |
| 财务看销售中心订单和回款、不能编辑 | 数据共享（基于数据归属部门） |
| 售后看销售部客户 | 数据共享（基于数据负责人） |
| 技术人员帮销售跟进客户 | 相关团队数据权限（加为只读成员） |
| 法务审批合同时临时可见 | 临时权限（限审批期间，审完收回） |
| 教育行业团队看教育行业客户 | 数据共享（基于条件：客户行业=教育） |
| 来源为客户介绍的线索给市场人员看 | 数据共享（基于条件：线索来源=客户介绍，共享给市场人员角色） |
| 审批流处理人看订单详情 | 数据共享（比临时权限、加相关团队更简便） |
| 业务流程处理人每次提示无权操作 | 临时权限 |

| 数据共享到 | 数据共享设置项，选中的部门默认不包含子部门 |
| 主属部门 | 数据负责人当前任职的部门，随人员调岗自动变化 |

| 相关团队 | 数据上的一组成员，分普通成员、联合跟进人、售后人员三个预置角色 |

## 需要注意的点

1. **管理角色和 CRM 角色不在同一页配**：管理功能权限配"能不能进后台、管什么"，业务功能权限配"CRM 里能做什么"，两个子页各管一段，别在错误的页面找配置项。
2. **预置管理角色权限固定不可改**：要调整只能新建自定义管理角色，把需要的管理能力逐项勾上。
3. **主属性字段不能取消读取**：客户名称这类主属性字段任何角色都得能读到，想靠字段权限把名称藏起来做不到；真正能藏的是普通字段，靠收回"读取"。
4. **"显示"和"读取"不是一回事**："显示"只管该字段在对象列表页的"筛选项"和"字段设置项"里出不出现；要让人根本看不见这个字段，动的是"读取"。
5. **删除不在角色权限里**：删除由 CRM 管理员在管理后台回收站操作，角色里勾不到"删除"项不是配漏了。
6. **共享的"来源"和"共享到"子部门规则相反**：来源部门默认含子部门，共享到的部门默认不含，保存前回头核对一遍范围。
7. **主属部门会随调岗变、归属部门不变**：按历史业绩、归属部门算提成或做统计，要用"基于数据归属部门"共享，用主属部门会把老数据算到新部门去。
8. **销售一部负责人看到销售二部订单，先查数据共享**：课件原题答案就是这个——问题出在数据共享设置，不是相关团队数据权限。
9. **审批流处理人点开待办提示无权限，最佳方案是数据共享**：临时权限只解决待办期间的短期查看；加相关团队会把数据长期挂在他名下；改对象的基础数据权限或开放全公司风险最大。
10. **业务流程处理人每次都提示无权操作、加联合跟进又太麻烦**：给他配临时权限，只覆盖待处理的那几条待办。
11. **"看不到 CRM 模块"先查员工角色分配**：员工没被加 CRM 角色，前台就没有模块入口，这不是权限没生效。
12. **相关团队和数据共享的分工别混**：相关团队是按角色给"这条数据的关联对象"授权（谁在这个客户的团队里，就按他的角色看）；数据共享是按范围把"一批数据"给一批人。
13. **"基于数据归属组织"有前提**：这种共享方式需要开通多组织才能使用，没开通就别选它。
