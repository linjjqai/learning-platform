# 速览（30 秒看完）

- 本课是课时 6–10 对象管理系列的配套练习讲解，题目分三组：客户管理题 14 道（单选、多选、判断）、基础配置题 5 道、挑战配置题 2 道。
- 题目入口是一个在线练习链接，点开后要先申请数据权限，才能看到题目、答题卡和解析。
- 一个人有多个角色时，前端只看"主角色"分配的布局；一个业务类型只能对应一个布局，但一个布局可以分配给多个业务类型。
- 每个对象都预置"生命状态"字段，五个取值：未生效、审核中、正常、变更中、作废；审核中的数据被自动锁定，解锁前不能编辑。
- "不同角色看不同布局"用多业务类型 + 多布局解决；"同一布局里按条件控制字段"用布局规则解决。
- 布局规则管显示/隐藏、必填/非必填、只读，验证规则管保存前的数据校验（如手机号必须 11 位），两者不能互相替代。
- 布局规则只在手动新建/编辑和详情页显示时生效，导入、OpenAPI、工作流后动作、批量更新都不生效。
- 挑战配置题（销售订单分类型、开票申请分类型）都有两种解法：布局规则，或分业务类型 + 分布局；配完一定到前端新建/编辑一条数据验证。

## 核心要点

- **课程定位与题目入口**：本期讲对象管理的"客户练习题"，分客户管理题、基础配置题、挑战配置题三组。学员点击练习链接、访问链接并申请对应的数据权限后，就能在答题卡里看到自己的作答与解析（截图里答题卡共 14 题）。
- **布局有四种，各管一段界面**：列表页布局管多视图展示、筛选和显示哪些字段；详情页布局管新建、查看数据时字段怎么排；移动端摘要布局管手机端列表显示哪些字段，最多 8 个、不支持扩容，开了"摘要高级布局"才能超出 8 个；待处理流程页布局的配置步骤和移动端摘要相同。
- **布局里能改什么、不能改什么**：把左侧字段拖到中间详细信息区即可，"小眼睛"按钮控制字段隐藏，字段顺序也在这里调；布局里可以新建字段，但不能禁用或删除字段——禁用、删除只能到对象的字段列表里做，删除要先"禁用"再"删除"，删除后平台内该字段下的值一并删除、不可恢复。后台改字段、改布局只有 CRM 管理员有权限，普通员工没有。
- **第一题：多角色时看到哪个布局**：小王同时拥有"销售人员"和"售后人员"两个功能权限角色，销售人员是主角色；"工单"对象有一种业务类型、两个布局，默认布局分配给销售人员，客户投诉布局分配给售后人员。问新建工单能看到哪个布局，答案是 B 默认布局。后台布局列表点"分配布局"，页面提示也写着"如果一个人有多个角色，前端所看见的布局是主角色分配的布局"。
- **第二题：生命状态是五个值，不是四个**：每个对象都预置"生命状态"字段——未生效＝设了新建审批且审批不同意；审核中＝正在走新建审批，数据会被自动锁定、解锁前不允许编辑；正常＝审批通过，或没设审批时保存后即为正常；变更中＝状态正常的数据走了编辑审批、正在审批中；作废＝数据被作废。所以"审批过程中被编辑仍显示审核中"是错的，选 C。
- **角色分两层，别只盯着业务角色**：管理功能权限决定能进哪个后台（系统管理员、组织架构管理员、CRM 管理员、互联管理员、开发人员、应用中心管理员、工作观察者等），有管理员权限都能进后台，区别是看到的内容不同；业务功能权限围绕 CRM 对象决定能做什么。业务角色里有几个预设角色，其中"所有员工"是所有 CRM 人员都带的角色——员工自己的角色没给某项权限却能操作，多半是"所有员工"给的。
- **第三题：两个事业部用不同客户布局**：两个事业部的角色都是销售人员，业务不同（一个面向 B 端咨询、一个面向 C 端产品销售）。做法是叠加多业务类型：让不同角色进入不同业务类型，不同业务类型再绑不同布局。业务类型有三条硬规则——一个业务类型只能对应一个布局，一个布局可以同时分配给多个业务类型，一个角色可以使用多个业务类型和多个布局。
- **第四题：关于客户布局的辨析**：一个角色并不是只能有一种布局，分配布局时一个角色可以挂多个布局；字段的显示、必填按布局分别设置；待处理业务流程的显示字段也有上限（课堂后台"显示的字段"显示为 15 个），所以"只能显示 5 个字段"的说法不成立。
- **第五题：网页端可用的字段类型**：只有计算字段和引用字段能在网页端使用。支付组件、签到组件都是移动端专用（签到涉及定位和签到码，支付涉及微信、支付宝等），网页端即使能看到这两个字段，逻辑和意义也完全不同。
- **字段类型自带数量和长度门槛**：单行文本最多 100 个字符、多行文本 2000 个、协同富文本 131,072 个；单选、多选的选项值最多 3000 个；每个对象最多加 20 个图片字段、50 个附件字段、1 个大附件字段（大附件指单个超过 100M 的文件，不支持资源包）、10 个查找关联、1 个主从关系、20 个引用字段、20 个计算字段、20 个统计字段，超出要买资源包。
- **第六、七题：对象能力与对象规则**：CRM 对象分预设对象（开箱即用）和自定义对象（预置对象解决不了的个性化业务）；对象里可以用多业务类型的布局、主从关系、自定义对象、支付组件字段，多业务类型对预设对象、自定义对象、从对象全都支持。主从关系是在从对象上加主从字段：1 个从对象只有 1 个主对象，1 个主对象最多 5 个从对象；从对象明细数据最多 200 条（可买资源扩容，但不建议超过 500），从对象的数据权限跟随主对象。另外每个对象都有主属性字段（客户名称、订单编号）承载唯一性，预设对象的主属性字段类型不支持修改；对象可以重名，但对象的 API name 唯一。
- **第八题：必填有两个入口，开了独立布局还要再配一遍**：A 在对象"字段列表"里编辑字段设为必填，对全部布局生效；B 在"客户"布局里对该字段设为必填，只对这套布局生效，两者都不需要额外条件。若对象开启了"新建/编辑页独立布局"，新建页、编辑页用的是另一套布局，字段的必填、显示必须到新建编辑页布局里再配一次，否则前端不生效。
- **第九题：验证规则只在新建、编辑时触发**：后台新建验证规则时，使用场景只有"新建""编辑"两项，没有作废等其它场景；规则是在保存数据前校验页面所填信息是否合法或符合业务要求，课件里的例子是手机号是否 11 位、客户是否通过工商查询、活动结束时间是否大于开始时间、注册资金小于 1w 的客户不允许录入。
- **第十、十一题：字段顺序由布局管，校验只能靠验证规则**：管理员在后台布局里调整字段展示顺序，前端新建、查看数据时就按调整后的顺序显示，判断题正确；"手机号不是 11 位不允许保存、用布局规则实现"则是错的，布局规则不具备数据校验能力。
- **第十二至十四题：引用字段与字段级差异**：引用字段和计算字段一样是实时取值，被引用字段的值一变，引用字段立即跟着变；客户、订单等对象都支持多业务类型、多布局；同一个字段可以在 A 布局必填、在 B 布局非必填，属正常支持。
- **字段依赖只做选项联动**：父字段只能是单选字段，子字段可以是单选字段或多选字段；当子字段必填且只剩一个选项时，系统会自动回填、把这个选项默认勾上。典型用法是客户等级决定客户资产的可选范围，以及客户级别决定能申请哪几级价格政策（小微客户只 A 级、标准客户 A/B、重要客户 A/B/C、VIP 客户 A/B/C/D），不做控制销售就可能选错，给公司带来损失。
- **基础配置题 1：布局规则做字段控制**：需求是"客户类型选老客户时，CSM 人员字段必填"。做法是新建布局规则、选客户布局、规则类型选字段控制，条件设为客户类型=老客户，动作为显示并必填 CSM 人员，配完到对应布局里新建数据验证。字段控制的适用范围要记牢：只在手动新建/编辑、详情页显示时生效，导入、OpenAPI、工作流后动作的字段变更、批量更新都不生效。
- **布局规则的另一种：页面控制**：按新建页、编辑页分别设置字段隐藏或只读——新建页只能设隐藏，编辑页可以设隐藏和只读。两个典型场景：工单的售后处理字段新建时不显示也不必填，到售后流程里再显示处理；报价申请新建时可填基本信息，编辑时锁住基本信息、其它信息仍可改。
- **基础配置题 2：两个角色两套布局**：销售人员和实施人员新建工单时字段要求不同，本质是"不同角色分配不同业务类型、不同布局"。给两个角色各建或各分配一个布局，在一个布局里把销售金额设为必填，在另一个布局里把它隐藏，再用两个角色的账号分别新建验证。
- **基础配置题 3：验证规则做位数校验**：电话不少于 11 位属于数据校验，要用验证规则。新建规则后插入 LEN 函数取字段长度，条件设为长度小于 11 时阻断，提示"电话少于 11 位，请重新检查提交"；前端填 9 位会被拦下，改到 13 位可以提交。
- **基础配置题 4：查找关联 + 引用字段**：新建自定义对象数据时要关联客户并自动带出客户类型，需要两个字段：先建查找关联字段指向客户（建立关联关系），再建引用字段指向"客户.客户类型"。必须先有关联字段，引用字段才建得出来；前端选客户后客户类型自动带出，换客户就跟着变。
- **基础配置题 5：默认值与计算字段的差别**：在自定义对象下加金额字段，默认值取商机的商机金额；另建一个计算字段，公式同样取商机金额。新建数据后把商机金额改掉再回看：默认值字段仍是原来的数，计算字段（以及引用字段）已经更新。
- **挑战配置题 1：销售订单分类型 + 联合跟进人**：安装单要填预计安装时间，租赁单要填租赁时长、超期后产品价格、预计到期时间。方法一是布局规则按订单类型控制显示与必填；方法二是建"安装单/租赁单"两个业务类型，各做一套布局分别隐藏或设必填。
- **联合跟进人靠相关团队角色**：订单有多人跟进时，在"相关团队角色"里新建"联合跟进人"团队角色，再给普通成员开回款计划等回款、开票相关数据的查看权限（只读即可），联合跟进人就能同步看到该订单的回款、开票信息。
- **挑战配置题 2：开票申请按发票类型控必填**：先建"开票类型"单选字段，选项为增值税专用纸质发票、增值税普通电子发票。专用纸质发票要求发票抬头、纳税识别号、开户行、开户行账号、开票地址、电话、收件人、收件人联系方式、收件地址必填；普通电子发票只需发票抬头、纳税识别号、收件邮箱必填，开户行、账号、开票地址、电话选填。演示用分业务类型 + 分布局实现，布局规则的做法与第一题同理，未再演示。

基础配置题（5 道 · 00:09:34–00:28:36）：

- 题 1 客户类型=老客户时 CSM 人员必填
- 考点：布局规则（字段控制）
- 做法：新建布局规则 → 选客户布局 → 字段控制 → 条件 客户类型=老客户 → 动作 显示 + 必填 CSM 人员 → 前端新建客户验证
- 题 2 两个角色新建工单，字段要求不同
- 考点：不同角色 → 不同业务类型 → 不同布局
- 做法：建两个业务类型/两套布局，各自"分配布局"；销售金额在一套布局必填、在另一套隐藏；用两个角色分别新建验证
- 题 3 电话字段不能少于 11 位
- 考点：验证规则 + LEN 函数
- 做法：条件 LEN(电话) < 11 → 阻断并提示"电话少于 11 位，请重新检查提交"
- 题 4 新建时关联客户并带出客户类型
- 考点：查找关联 + 引用字段
- 做法：先建查找关联字段指向客户，再建引用字段指向 客户.客户类型；前端选客户后自动带出
- 题 5 默认值与计算字段同时取商机金额
- 考点：默认值"只取一次" vs 计算/引用字段"实时重算"
- 做法：金额字段设默认值取商机金额；另建计算字段（公式取商机金额意图下对应数值字段）；改商机金额后对比：默认值不变、计算字段更新

挑战配置题（2 道 · 00:29:31–00:44:58）：

- 题 1 销售订单分安装单/租赁单，且联合跟进人要看到回款、开票
- 解法一 · 布局规则：条件 订单类型=安装单 → 预计安装时间 显示 + 必填；订单类型=租赁单 → 租赁时长、超期后产品价格、预计到期时间 显示 + 必填
- 解法二 · 分业务类型 + 分布局：业务类型建安装单、租赁单 → 两套布局各自隐藏/必填 → 保存后分配业务类型
- 联合跟进人：相关团队角色 → 新建"联合跟进人" → 普通成员对回款计划等回款/开票相关数据开只读或查看权限
- 题 2 开票申请按开票类型控制必填
- 前提：建"开票类型"单选字段，选项 增值税专用纸质发票 / 增值税普通电子发票
- 解法一 · 布局规则：按开票类型做条件，专用纸质发票九项全必填；普通电子发票仅抬头、纳税识别号、收件邮箱必填，开户行、账号、开票地址、电话选填
- 解法二 · 分业务类型 + 分布局：业务类型 专用纸质发票、普通电子发票，两套布局分别设必填/选填，再分配业务类型
- 验证：前端分别新建两种类型，检查必填与隐藏是否符合财务要求

## 术语表

| 术语 | 含义 |
| --- | --- |
| 客户管理题 | 本课第一组题，14 道单选/多选/判断，考对象、布局、字段相关概念 |
| 基础配置题 | 第二组题，5 道实操，覆盖布局规则、分角色布局、验证规则、查找关联、默认值/计算字段 |
| 挑战配置题 | 第三组题，2 道综合实操：销售订单分类型、开票申请分类型 |

| 自定义对象 | 预置对象满足不了的个性化业务，由管理员自建的对象 |
| 主属性字段 | 承载对象核心内容、体现唯一性的字段（客户名称、订单编号）；预设对象的主属性字段类型不可修改 |
| 对象 API name | 对象的唯一标识；对象名称可以重复，API name 不可重复 |
| 预制字段（标准字段） | 建对象时自带的字段，用于存储共性数据，不能删除，部分可编辑 |
| 主角色 | 用户拥有多个功能权限角色时，决定前端布局展示的那个角色 |
| 分配布局 | 把某个布局分配给指定角色/业务类型的操作，入口在对象布局列表右上角 |
| 业务类型 | 对象下的一层分类（如咨询工单/投诉工单、安装单/租赁单）；一个业务类型只能对应一个布局，一个布局可分给多个业务类型 |
| 生命状态（生命周期字段） | 每个对象预置的状态字段，取值为未生效、审核中、正常、变更中、作废 |
| 审核中 | 数据正在走新建审批时的状态，期间数据被自动锁定，解锁前不能编辑 |
| 变更中 | 状态为正常的数据在走编辑审批时的状态，易与"审核中"混淆 |
| 布局规则 | 按条件控制字段显示/隐藏、必填/非必填的配置，分字段控制与页面控制 |
| 字段控制 | 布局规则的一种，按条件控制字段的显示、隐藏、必填；导入、OpenAPI、批量更新不生效 |
| 页面控制 | 布局规则的一种，按新建页/编辑页分别设置字段隐藏或只读 |
| 验证规则 | 保存前对数据做校验的规则（如手机号必须 11 位），仅在新建、编辑触发 |
| 字段依赖关系 | 父字段（单选）决定子字段（单选/多选）可选范围；子字段必填且只剩一个选项时自动回填 |
| 引用字段 | 引用关联对象字段值的字段，属于实时计算，随被引用字段变化 |
| 计算字段 | 通过公式计算的字段，网页端可用，值随公式中的字段实时更新 |
| 统计字段 | 跨对象汇总数值的字段，如订单上的回款金额；每个对象最多 20 个 |
| 查找关联 | 建立对象之间关联关系的字段类型（如工单关联客户） |
| 大附件 | 上传单个超过 100M 文件的字段类型，每个对象最多 1 个，不支持资源包 |
| 支付组件 / 签到组件 | 仅移动端使用的字段组件，网页端不生效 |
| 相关团队角色 | 对象数据上参与人的角色配置（如联合跟进人），可单独配数据查看权限 |
| 新建/编辑页独立布局 | 对象级开关，开启后新建、编辑页使用独立布局，字段必填等需在该布局中配置 |
| 待处理业务流程 | 列表页中展示审批/处理中数据的视图，显示字段有数量上限（后台显示为 6/15） |
| 列表页布局 | 控制列表页多视图展示、筛选与显示字段的布局 |
| 移动端摘要布局 | 手机端列表展示字段的布局，最多 8 个、不支持扩容，开高级布局可超出 8 个 |
| CSM 人员 | 客户成功人员，基础配置题 1 中要求"老客户"时必填的字段 |

## 需要注意的点

1. **别按"角色数量"判断能看几个布局**：多角色用户前端只取主角色分配的布局，第一题正因如此只能看到默认布局；答题和给客户解释时都要先说"主角色"。
2. **布局规则 ≠ 数据校验**：11 位手机号、注册资金不能小于 1w 这类校验只能靠验证规则；布局规则能做的是显示/隐藏、必填/非必填、可编辑，且通常需要条件控制，不能替代校验。
3. **布局规则的生效范围有边界**：只在手动新建/编辑、详情页显示时生效，导入、OpenAPI、工作流后动作的字段变更、批量更新都不生效——用批量更新刷数据时，别指望它帮你拦字段。
4. **必填设置有两级、还可能有三处**：字段列表里设必填对全部布局生效，布局内字段设置只对当前布局生效；若开启了"新建/编辑页独立布局"，还必须到新建编辑页布局再配一次，否则前端不生效。
5. **默认值不是计算字段**：默认值只在新建那一刻取一次，源字段之后怎么改都不变；引用字段、计算字段才是实时重算，基础配置题 5 就是考这个差别。
6. **顺序不能颠倒**：引用字段必须先有查找关联字段（建立对象关联）才能创建；字段依赖关系只解决父子选项联动，解决不了"某条件下必填"。
7. **字段删了就回不来**：要在字段列表里先点"禁用"再点"删除"，删除后平台内该字段下的值一并删除且不可恢复；布局里只能新建字段，禁用、删除必须回字段列表做。
8. **生命状态是五个值，别漏"正常"**：未生效、审核中、正常、变更中、作废；审核中的数据被系统自动锁定，解锁前不能编辑，"审批中还能改数据"是常见误判。
9. **主从关系有硬上限**：1 个从对象只有 1 个主对象，1 个主对象最多 5 个从对象；从对象明细最多 200 条，可买资源扩容但不建议超过 500；从对象的数据权限跟随主对象。
10. **口播与练习题文档不一致时以文档为准**：口播把"生命周期字段"说成审批状态字段、把"租赁单"含混带过（转写成"族林单/作品单"）、开票类型选项也念得含糊；文档原文为"安装单、租赁单（租赁时长、超期后产品价格、预计到期时间）"与"增值税专用纸质发票 / 增值税普通电子发票"，字段清单也以文档为准。
