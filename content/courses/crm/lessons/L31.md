# 速览（30 秒看完）

- 数据维护工具在管理后台搜索即可进入，六个子模块：全部客户、迁移工具、回收站、清洗工具、CRM初始化、数据权限查询工具。
- 全部客户＝CRM 所有客户明细，场景里选"已停用员工客户"能一键筛出没负责人管的客户，批量换给在岗员工。
- 回收站收所有作废数据：客户、联系人能恢复；商机、销售订单、合同、产品、字段作废后没有恢复按钮，在回收站里再删除就彻底没了。
- CRM初始化＝删除 CRM 中所有数据，走"客服取表→打印盖章→纸质件寄回＋电子版报批→审批通过"四步，按钮放开后到次日凌晨 0 点前必须做完。
- 迁移工具批量改负责人、归属部门、归属组织、相关团队，源可以一个或多个、目标只有一个；立即执行，或定时（当晚 22:00 调度，晚于 22:00 顺延一天）。
- 清洗工具只支持客户、联系人、销售线索三个预设对象，范围是截至前一天凌晨之前的数据，预约后次日 0—6 点执行，完成后走 CRM 通知。
- 数据权限查询工具：选人＋对象＋具体记录，直接给出这个人为什么有、或为什么没有这条数据的权限。
- 回收站里没彻底删除的数据仍然参与查重，新建同名客户会被它挡住。

## 核心要点

- **模块入口与六项清单**：管理后台搜索"数据维护工具"进入，六个子模块各有分工——全部客户（查看及管理 CRM 中所有的客户明细）、迁移工具（批量变更负责人或归属部门）、回收站（作废数据的恢复与彻底删除）、清洗工具（查重并合并）、CRM初始化（删除 CRM 中所有数据）、数据权限查询工具（查询某员工对某条数据的权限）。
- **课程的四条主线**：①全部客户、回收站——日常数据查看与作废处置；②CRM初始化——高危清库；③迁移工具、清洗工具——批量处理；④数据权限查询工具——权限排查。听完这一课，每个模块至少要知道它解决哪类问题、入口在第几层菜单。
- **全部客户的两个用途**：一是查看及管理 CRM 中所有的客户明细；二是快速筛选出**已停用员工名下**的客户——注意它只管"全部客户＋停用员工"，作废的客户不在这个模块里。
- **已停用员工客户的处置路径**：管理后台－数据维护工具－全部客户－场景选"已停用员工客户"→列出所有负责人账号已停用的客户→勾选后批量更换负责人给在岗员工，把这些没人跟的客户重新分下去。
- **回收站收什么**：所有作废的 CRM 数据都会进入回收站，在回收站里只做两件事——恢复，或者彻底删除。课件在回收站这一页特别标了两句：涉及查重校验；数据删除后无法恢复，请谨慎操作。
- **恢复客户的操作链**：前端选中客户点"作废"→系统提示"若存在主从数据将同时作废，且会终止相关业务流程"→确认后客户进回收站→在回收站找到它点"恢复"→提示"确定恢复到作废之前的状态吗？"→确认并刷新，数据回到作废前的位置。
- **作废不等于删除**：作废只是把数据送进回收站，还救得回来；在回收站里执行删除才是真正的删除，删完没有任何入口能捞回来。客户误作废的处理办法就是去回收站点恢复，别急着重录。
- **可恢复 vs 不可恢复清单**：客户、联系人作废后可以恢复；商机、销售订单、合同、产品作废时系统提示"作废数据不可恢复，请谨慎操作"，进回收站后**没有恢复按钮**；字段属于另一类，删除后字段本身和平台内的值一起永久消失，连回收站都没有。
- **回收站与查重的联动**：回收站这一块的说明里写明"涉及到查重校验"，也就是作废但没彻底删除的数据仍会被查重规则比对——新建客户时若回收站里有相似客户名，照样弹出查重提示，所以数据整理完要顺手清回收站。
- **CRM初始化的定义与应用场景**：CRM初始化就是删除 CRM 中所有数据，注意是"所有"，不是只删测试数据；典型场景是系统里已经录入了大量测试数据，需要一次性批量清掉，重新开张。
- **初始化的四步流程**：①联系纷享客服，获取电子版**特殊申请表**；②打印纸质申请表，按要求填写后盖**公司公章**；③把纸质申请表寄给纷享，同时把电子版给纷享客服提交审批；④申请通过后，纷享服务人员会主动联系您，不是自己再去催按钮。
- **审批后只有一个操作窗口**：审核通过后技术把按钮放开、开通高危操作权限，有效期是"到次日凌晨 0 点前"——过了这个点按钮就回收，要用得重新走一遍申请，这也是防止误清库的保险。
- **迁移工具能迁什么**：把多个对象的大量数据，从一个或多个负责人、归属部门、归属组织，迁到另一个负责人、归属部门或归属组织；还能批量处理多个对象的相关团队。课件的说法是"显著提高数据迁移效率，降低操作风险"——源可以多个，目标只有一个。
- **迁移的两类典型场景**：①人员组织架构调整，业绩要算到 A 部门，但数据现在挂在 B 部门；②一批重要客户要交给小李负责，可现在散在很多销售名下，靠前端一条条改不现实，先按条件筛出来再统一换人。
- **迁移任务怎么建**：新建任务→选类型（迁移负责人 / 迁移归属部门 / 迁移相关团队）→选对象（如客户）→设筛选条件（如华北战区＋重要级别客户）→选新负责人或新归属部门→选执行方式（立即执行 / 定时执行）→保存。
- **定时的两个时间点**：定时执行在**当天晚上 22:00** 开始调度执行；如果提交任务的时间晚于 22:00，任务顺延到**次日晚上 22:00** 执行。急用就别选定时，直接选立即执行。
- **迁移结果怎么验**：执行完到前端刷新客户列表，负责人已经换成新人；如果是更换负责人，归属部门会跟着新负责人走——新人在客服部，客户归属就变成客服部，这个联动在跨部门交接时正好用得上。
- **清洗工具做什么**：按指定的规则找出 CRM 中重复的客户、联系人、销售线索数据并合并；场景是收集到大量客户线索后，把不重要、重复的数据洗掉，简化信息体量，留下的信息方便后续跟进使用。
- **清洗的三个硬限制**：①对象只支持预设对象里的客户、联系人、销售线索三个，商机、销售订单、合同做不了；②规则可以用系统预设的，也可以自定义（可加地址、级别、归属等字段条件）；③数据范围是**截至前一天凌晨之前**的数据。
- **预约清洗的执行与通知**：点"预约清洗"后，系统在**第二天 0 点—6 点**执行；清洗完毕后通过**CRM 通知**提醒结果；随时可以回来看上次的清洗结果。
- **清洗结果怎么看**：结果按重复分组合呈现，每组用颜色分区标识，勾选要合并的重复组执行合并即可，不需要的组不动。
- **数据权限查询工具**：用来查询指定用户对特定对象数据记录的访问权限——选人员、选对象、选一条具体记录，直接告诉你有还是没有权限、权限从哪来，不用去翻几十个配置页面。
- **权限查询的三组演示结论**：同一个客户，员工"小罗"作为相关团队负责人拥有读写权限；员工"小王"作为管理员拥有数据读写权限；换成一位跟该客户没有任何关系的员工，结果显示没有该客户的权限。排查权限问题先跑一遍这个工具，再谈改配置。
- **课末五道场景题的标准答案**：①转出停用员工客户→全部客户－场景：已停用员工客户；②客户误作废要恢复→回收站－恢复；③回收站里删掉的数据能不能恢复→不能；④合并重复销售线索→清洗工具－销售线索－设置清洗规则、预约清洗；⑤把张三的数据全转给李四→迁移工具－迁移负责人。

## 结构与流程

### 数据维护工具六模块总览

```
数据维护工具（管理后台搜索进入）
├── 全部客户
│ ├── 查看及管理 CRM 中所有客户明细
│ └── 场景：已停用员工客户 → 一键筛出负责人已停用的客户 → 批量换负责人
├── 迁移工具 ⭐（批量操作利器）
│ ├── 任务类型：迁移负责人 / 迁移归属部门 / 迁移相关团队
│ ├── 源：一个或多个负责人 / 归属部门 / 归属组织；目标：另一个
│ ├── 支持对象：客户 / 线索 / 商机 / 销售订单 等（可多个对象一起处理）
│ ├── 执行方式：立即执行 或 定时（当晚 22:00 调度，晚于 22:00 顺延次日 22:00）
│ └── 创建流程：新建→选类型→选对象→设筛选条件→选新负责人/部门→选执行方式→保存
├── 回收站
│ ├── 可恢复对象：客户、联系人
│ ├── 不可恢复对象：商机、销售订单、合同、产品（字段删除连值一起没）
│ ├── 两个动作：恢复 / 彻底删除（删除后无法恢复）
│ ├── 警告提示：作废前系统提示"作废数据不可恢复，请谨慎操作"
│ └── 关联：涉及查重校验，未彻底删除的数据仍会被查重比对
├── 清洗工具
│ ├── 支持对象：客户 / 联系人 / 销售线索（仅这三个）
│ ├── 规则：系统预设 + 自定义（可加地址/级别/归属等条件）
│ ├── 范围：截至前一天凌晨之前的数据
│ ├── 机制：预约后次日 0—6 点执行，完成后 CRM 通知
│ └── 结果：按重复分组合呈现 → 勾选合并
├── CRM初始化 ⚠️（高危，删除 CRM 中所有数据）
│ ├── 流程：客服取特殊申请表 → 打印填写盖公章 → 纸质件寄回＋电子版报批 → 审批通过
│ ├── 用时：按钮放开并开通高危操作权限后，到次日凌晨 0 点前
│ └── 过期：按钮回收，需重新申请
└── 数据权限查询工具 ⭐（排查利器）
 └── 选人员 + 对象 + 数据记录 → 直接输出有无权限及权限来源
```

### 作废对象恢复规则表

| 对象类型 | 作废后能否恢复 | 说明 |
| --- | --- | --- |
| 客户 | ✅ 可恢复 | 在回收站点"恢复"按钮，回到作废前的位置 |
| 联系人 | ✅ 可恢复 | 同上 |
| 商机 | ❌ 不可恢复 | 回收站中没有恢复按钮 |
| 销售订单 | ❌ 不可恢复 | 同上 |
| 合同 | ❌ 不可恢复 | 同上 |
| 产品 | ❌ 不可恢复 | 同上 |
| 字段 | ❌ 不可恢复 | 删除后字段与平台内的值一起永久消失，不经回收站 |

## 需要注意的点

1. **"作废"和"彻底删除"是两件事**：作废只是进回收站，客户、联系人还能恢复；在回收站里再执行删除，课件原话是"数据删除后无法恢复"。所以学员常问的"回收站里删错了能恢复吗"，答案是**不能**。
2. **能恢复的只有客户和联系人**：商机、销售订单、合同、产品作废时系统直接提示"作废数据不可恢复，请谨慎操作"，进回收站后根本没有恢复按钮；字段更彻底，删除后字段和平台内的值一起消失。
3. **清洗工具别把商机算进去**：课件写明"仅支持对预设对象中的客户、联系人、销售线索"三个，商机、销售订单、合同的重复数据在这个工具里找不到入口，别带客户在这儿绕。
4. **清洗范围只到"前一天凌晨之前"**：今天刚录进来的数据不在本次清洗范围内，当天产生的重复数据要等下一次预约，别以为点了预约就全库去重了。
5. **清洗结果走 CRM 通知**：清洗完毕后通过 CRM 通知提醒，不是企信、不是短信，别让客户去别处等结果。
6. **初始化的窗口是"到次日凌晨 0 点前"**：不是含糊的"当天"，按钮放开、高危权限开通后到次日 0 点前必须执行完；错过窗口按钮回收，整套申请要重走一遍。
7. **初始化删的是全部数据，不是只删测试数据**：定义就是"删除 CRM 中所有数据"，操作前必须确认该导的已导出、该留的已留，这是不可逆的清库动作，不能交给不清楚流程的人。
8. **申请要寄纸质件还要盖公章**：完整链路是"客服给电子版特殊申请表→打印填写盖公章→纸质件寄给纷享＋电子版交客服报批→审批通过后服务人员主动联系"，只发电子版走不完流程。
9. **迁移定时的 22:00 顺延**：晚于 22:00 提交的任务顺延到次日晚上 22:00 执行，急着生效就选"立即执行"。
10. **迁移的源可以多个、目标只有一个**：能把散在多个负责人、多个部门下的数据一次性收到一个负责人或部门；只想改部门不动人，就选"迁移归属部门"；如果要连带调相关团队，用"迁移相关团队"那个类型。
11. **迁移负责人会带着归属部门一起变**：新负责人在哪个部门，数据的归属部门就跟到哪个部门。跨部门交接时这是正好想要的效果，但如果只是换人、不想动部门归属，迁完要回头核对一遍。
12. **全部客户里看不到作废数据**：它管的是"所有客户明细＋停用员工客户"，作废数据只在回收站。找作废客户别在全部客户里翻，直接去回收站。
13. **接口径以界面为准**："回收站"在口播和旧资料里常写成"回收战"，"CRM初始化"常被写成"CRM重置"，指的是同一个模块；给客户讲、写文档时用界面上的名字。
