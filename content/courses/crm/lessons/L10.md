# 速览（30 秒看完）

- 本课讲挂在对象上的两块配置：按钮管理决定"数据能做什么操作"，场景管理决定"看到哪些数据、哪些字段、什么顺序"。
- 按钮分业务按钮与 UI 按钮：前者依附对象执行业务动作，后者不依附业务对象、只配跳转链接。
- 自定义按钮最多 20 个；不够就买"自定义按钮个数资源包"，每包 5 个、最多买 5 个包。
- 建按钮走七步：类型 → 基本信息 → 位置与显示条件 → 是否填内容 → 是否触发验证规则 → 执行动作 → 哪些角色可用。
- 显示条件只决定"看不看得见"：按钮显示出来也可能执行失败，报错先读提示——"不满足显示条件"或"数据被锁定了"。
- 预置场景按"与我的关系"分 8 个：全部、我负责的、我参与的、我负责部门的、我下属负责的、我下属参与的、共享给我的、我关注的。
- 企业级场景（课件里也叫"租户级"）后台配、个人级场景前台配，个人级优先；后台再改不跟随，用前台【场景设置 → 恢复系统默认】还原。
- 后台的对象配置（字段、按钮、场景、布局）只有 CRM 管理员能做，普通员工只能在前台做个人级调整。

## 核心要点

- **本课在课件里的位置**：本课对应《对象管理》课件的第 5 部分，5.1 按钮管理、5.2 场景管理。前四块——对象与字段、布局与业务类型、字段依赖/布局规则/验证规则、角色权限——在前面几课已经讲完，这一块讲的是对象上"能做什么操作、看到什么视图"。
- **按钮管理解决什么**：某个具体对象的标准操作不够用时，可以在对象上自建按钮完成特定业务。一个自定义按钮能配四件事——显示条件、前校验、点击后需要填写的内容、点击后的处理动作；另外还能用按钮批量更改字段值。
- **两类按钮的分工**：业务按钮依附于业务对象，执行改字段等业务动作；UI 按钮不依附业务对象，用来配置跳转到其他网站的链接。
- **自定义按钮的上限与资源包**：自定义按钮最多 20 个；要增加就得购买"自定义按钮个数资源包"，每个资源包包含 5 个自定义按钮，最多可购买 5 个资源包（即最多再加 25 个）。系统预设按钮不占这 20 个名额。
- **配置七步**：按钮类型 → 基本信息（按钮名称、API Name、描述）→ 按钮放在哪里（位置 + 显示条件）→ 点击后是否需要输入内容 → 字段变更时是否触发验证规则 → 点击后触发什么动作 → 哪些角色能看见并使用。
- **显示条件是第一道安全边界**：可设"总是显示"或"满足以下条件显示"（例：负责人 = 小王），也可在数据锁定态时禁用按钮。看不到按钮的人，即使知道有这个按钮也执行不成功。
- **"看得见"不等于"执行成功"**：显示条件选"总是显示"时，按钮对所有数据都出现，但负责人不匹配、数据被锁定，点击后都会失败。前端提示很直白——"不满足显示条件"说明负责人不对，"数据被锁定了"说明要先解锁。
- **点击后填内容、前校验、验证规则是三件不同的事**：第 4 步要求点击后先填字段（例：客户类型必填）；第 6 步可加前校验，让数据满足条件才允许执行；第 5 步决定字段改完是否再触发验证规则（演示里选"不触发"）。
- **执行动作用变量把输入带进结果**：执行"字段更新"，把客户类型变更为 `${客户类型变量}`，用户在弹窗里选什么，数据就被改成什么；动作可以继续叠加，还有"执行动作成功后"的分支。
- **批量改字段是按钮的高频用法**：列表页勾选多条数据（演示勾了小王的 2 条客户），点自定义按钮统一改成"政府机关"，一次成功，比逐条进详情页编辑省事。
- **按钮可指定角色**：第 7 步选择哪些角色能看见并使用该按钮——仅 CRM 管理员、指定角色或所有员工。角色决定"这类人能不能用"，显示条件决定"这条数据上出不出现"。
- **预设按钮与出现位置**：选中数据后出现的那排按钮都是系统预设。列表页顶部为批量操作（打标签、发邮件、合并、退回、转移、添加/移除相关团队成员、锁定、解锁、导出、更换合作伙伴、更换外部负责人等），详情页也有功能一致的按钮；"更换负责人"所有对象都有，选新人确认即可（演示把小王的客户改给了小罗）。
- **锁定/解锁，以及"被锁定"的另一个来源**：锁定后数据受保护、编辑类按钮消失，要有权限的人先解锁才能改；解锁弹窗可勾选"同时释放对象数据（主管人员的部门数据被解锁，不触发此变更项）"。另外，对象设置了新建审批时，审批中的那条数据生命状态为"审核中"并会被自动锁定，解锁前不允许编辑——所以编辑按钮不见了，不一定是按钮配错了。
- **标签、打印、导出**：标签用于打标签或改标签（如 VIP 改成"重要客户"）；打印要先选后台配好的打印模板，确认后进预览，按住 Ctrl 滚动滚轮缩放；导出时能隐藏不需要的字段（如电话）、按需带上订单与产品明细、选导出为 Excel，最后下载到本地。
- **合并与转移**：合并是客户对象下比较特殊的按钮，用来把重复数据合起来做数据清洗；转移可把客户转到其他公海，也可配合添加相关团队成员一起操作。
- **按钮显隐与排序在布局里做**：对象 → 布局配置 → PC 端选中列表页组件 → 下滑找到"批量操作"和"操作"列，用"小眼睛"图标隐藏/放出、拖拽调整顺序；详情页按钮同理在详情页布局里配。每次改完都要刷新前端才看得到效果。
- **多角色时前端只看主角色布局**：同一个人有多个角色，前端呈现的是主角色分配的那套布局。"为什么他有这个按钮我没有"，先看他的主角色对应布局里按钮有没有放出来、显示条件是否命中。
- **场景决定两件事**：看到哪些数据（数据范围）、能看哪些字段及字段的展示顺序（显示设置）。课件的例子就是让售前只看到咨询类工单、并把咨询相关字段优先展示，售后只看到投诉类工单、优先展示投诉字段。
- **预置场景按"与我的关系"划分**：共 8 个，判定依据都是相关团队的负责人/普通成员与我的关系，以及数据归属部门、共享、关注状态——"全部"是有权限的全部数据，"我负责的"是相关团队负责人为我，"我参与的"是普通成员中有我。
- **企业级场景与个人级场景**：企业级（课件里也称"租户级"）由管理员在后台配置，按适用范围推给命中的人；个人级由用户在前台自行配置。优先级：个人级场景 > 企业级场景。
- **后台新建场景的四要素**：对象管理 → 场景管理 → 新建场景。适用范围决定谁能看到（全公司或指定人员、部门、角色）；业务类型决定只展示该类业务数据；过滤条件（添加条件，演示为"锁定状态 = 未锁定"，可多条叠加）决定看哪些数据；排序设置（如按创建时间）决定默认排列顺序。
- **显示设置与前端验证**：从"全部字段"勾选字段到右侧，拖拽调整顺序，直接拖列宽（80–1000），勾选折行后长名称显示两行；配置可一键同步到其他场景，移动端可继承也可单独配置；保存后回前端刷新，折行与列宽效果立刻可见。
- **个人级调整与恢复系统默认**：前端列表页场景下拉 → 【场景设置】，可新建我的场景，设表格（每页条数、行高、序号、默认列宽）与字段（勾选、拖拽排序、隐藏），存为场景并可设为默认。个人调整过之后后台再改不跟随，要在【场景设置】里点【恢复系统默认】才与后台一致。场景的显示顺序同样在后台布局配置的列表页组件里设置。
- **本课总结**：按钮学的是"数据能做什么操作"，场景学的是"列表页数据怎么展示"，两者都是围绕对象做的配置。

## 结构与流程

按钮的类型与配置要素：

```
按钮（对象下的"按钮"模块，所有对象都有）
├─ 按钮类型
│ ├─ 业务按钮：依附于业务对象，执行改字段等业务动作
│ └─ UI 按钮：不依附业务对象，用于跳转链接（可跳到其他网站）
├─ 出现位置（按钮放在哪里）
│ ├─ 列表页单条操作
│ ├─ 列表页批量操作（勾选多条后出现，可批量改字段值）
│ ├─ 详情页
│ ├─ 相关列表页单条操作
│ └─ 新建页 / 编辑页
└─ 配置七步（对象管理 → 按钮 → 新建按钮）
 1 设置按钮类型：业务按钮 / UI 按钮
 2 基本信息：按钮名称、API Name、描述
 3 按钮放在哪里：按钮位置 + 显示条件
 · 总是显示
 · 满足以下条件显示（例：负责人 = 小王）
 · 数据锁定态时禁用按钮
 4 点击后是否需要输入内容：不需要 / 需要 → 选字段、勾"必填"
 5 字段变更时是否触发验证规则：否 / 是
 6 点击按钮后触发的操作
 · 前校验
 · 执行动作 → 执行步骤（例：字段更新，客户类型 变更为 ${客户类型变量}）
 · 执行动作成功后（可继续添加动作）
 7 哪些角色能看见并使用该按钮：指定角色 / 所有员工
```

按钮的数量与权限边界：

- 自定义按钮上限 20 个 → 超出需买"自定义按钮个数资源包"（每包 5 个，最多 5 个包）
- 显示条件控制"这条数据上出不出现"，角色设置控制"谁的角色能用"，前校验与锁定状态控制"能不能执行成功"
- 后台的按钮、场景、布局配置只有 CRM 管理员能做；多角色员工的界面按主角色布局展示

场景管理的编排结构：

```
场景（对象下的"场景管理"模块）
├─ 企业级场景（又称租户级场景，管理员在后台配：对象管理 → 场景管理 → 新建场景）
│ ├─ 基础信息：场景名称 / API Name / 描述
│ ├─ 适用范围：全公司 ｜ 指定人员、部门、角色（范围内的人才看得到）
│ ├─ 数据范围
│ │ ├─ 业务类型（如只看某类工单）
│ │ ├─ 基础数据范围
│ │ └─ 过滤条件（添加条件，可多条叠加，例：锁定状态 = 未锁定）
│ ├─ 排序设置：排序字段（例：创建时间 / 最后修改时间）+ 升序或降序
│ ├─ 显示设置
│ │ ├─ Web 端：显示字段、字段顺序（拖拽）、列宽（80–1000）、是否折行
│ │ └─ 移动端：可继承 Web 端，也可独立配置
│ └─ 列表操作：编辑 / 复制 / 删除 / 启用 / 禁用
└─ 个人级场景（用户在前台配：列表页场景下拉 → 场景设置 / 新建我的场景）
 ├─ 表格设置：每页显示条数、表格行高（紧凑/标准/宽松）、显示序号、表格默认列宽
 ├─ 字段设置：勾选字段、拖拽排序、隐藏字段
 ├─ 存为场景（可勾选设为默认）
 └─ 场景设置 → 恢复系统默认（放弃个人调整，回到后台配置）
```

生效逻辑：

```
后台配置企业级场景 → 按"适用范围"推送给命中的用户 → 用户在前端场景下拉里切换
 ↓
 用户在前台个人调整 → 生成个人级场景（覆盖后台）
 ↓
 优先级：个人级场景 > 企业级场景
 ↓
 后台再改配置，个人场景不跟随 → 需"恢复系统默认"才重新一致
```

预置场景与"与我的关系"（幻灯片定义，用于对照前端下拉）：

| 预置场景 | 数据范围 |
| --- | --- |
| 全部 | 我有权限的全部数据 |
| 我负责的 | 相关团队的负责人是我的数据 |
| 我参与的 | 相关团队的普通成员中有我的数据 |
| 我负责部门的 | 数据归属部门是我负责的部门（含级联）及我助理负责的部门（含级联）的数据 |
| 我下属负责的 | 相关团队的负责人是我下属的数据 |
| 我下属参与的 | 相关团队的普通成员中有我下属的数据 |
| 共享给我的 | 基于数据负责人、基于归属部门、基于条件共享给（我、我的用户组、我的部门、我的角色）的数据 |
| 我关注的 | 被设置为"关注"状态的数据 |

## 术语表

| 术语 | 含义 |
| --- | --- |
| 按钮管理 | 对象下用于完成特定业务动作的配置模块，所有对象都有 |
| 场景管理 | 对象下决定看到哪些数据、字段如何展示与排序的配置模块 |
| 显示条件 | 按钮的可见性规则，可设为总是显示、满足条件显示或锁定态禁用 |
| 前校验 | 点击按钮前对数据做的条件校验，满足条件才允许执行 |
| 自定义按钮 | 用户自行创建的按钮，可配显示条件、输入内容与后续动作，单个对象最多 20 个 |
| 自定义按钮个数资源包 | 超出 20 个后需购买的资源包，每包 5 个按钮，最多买 5 个 |
| 业务按钮 | 依附于业务对象、执行改字段等业务动作的按钮类型 |
| UI 按钮 | 不依附业务对象、用于跳转链接的按钮类型 |
| API Name | 按钮/场景的系统唯一标识，可自动生成 |
| 变量 | 按钮执行动作里引用的输入值，如 `${客户类型变量}`，把用户填的内容写进字段 |
| 锁定 / 解锁 | 锁定后数据受保护、编辑类按钮消失；需有权限的人解锁后才能修改 |
| 合并 | 客户对象特有的按钮，用于合并重复数据、做数据清洗 |
| 转移 | 把数据（如客户）转移到其他公海 |
| 导出 | 选字段、隐藏不需要字段后导出为 Excel |
| 布局配置 | 后台配置列表页/详情页组件的界面，按钮显隐排序与场景显示顺序都在这里 |
| 主角色 | 员工有多个角色时，前端按主角色分配的布局展示界面 |
| 相关团队 | 一条数据上的协作成员集合，区分负责人与普通成员，是"我负责的/我参与的"的判定依据 |
| 企业级场景 | 管理员在后台配置、按适用范围推送给用户的场景 |
| 租户级场景 | 企业级场景的另一种叫法，指管理员给整个企业配的那一套场景 |
| 个人级场景 | 用户在前台自行配置的场景，优先级高于企业级场景 |
| 场景设置 | 前端列表页场景下拉里的入口，用于个人级调整、新建我的场景与恢复系统默认 |
| 适用范围 | 场景的可见人群，可选全公司或指定人员、部门、角色 |
| 业务类型 | 场景内进一步切分数据的维度，如工单中的某类业务 |
| 过滤条件 | 场景的数据筛选规则，可多条叠加 |
| 排序设置 | 决定进入场景后数据的默认排列顺序 |
| 显示字段 | 场景中勾选出来展示的字段集合 |
| 列宽 | 单个字段列在列表中的宽度，取值范围 80–1000 |
| 折行 | 内容过长时换行显示，长名称会变成两行 |
| 默认场景 | 每次进入该对象列表时默认落到的场景 |
| 恢复系统默认 | 放弃个人场景调整、回到后台企业级配置的操作，入口在前台场景设置里 |
| 生命状态 | 每个对象都预置的状态字段，取值含未生效、审核中、正常、变更中、作废 |
| 审核中 | 新建审批进行中的数据状态，此时数据被自动锁定、解锁前不允许编辑 |
| 关注 | 数据被标记为"关注"状态，是"我关注的"场景的判定依据 |
| CRM 管理员 | 可配置对象、字段、布局、按钮、场景与权限的后台角色，普通员工没有这些权限 |

## 需要注意的点

1. **20 个是"自定义"按钮的上限，不是全部按钮的上限**：系统预设按钮不占这 20 个名额；资源包每包 5 个、最多 5 个，意味着靠购买最多再加 25 个。给客户讲方案时要先把数量算清楚。
2. **"按钮能看见"≠"按钮能执行成功"**：显示条件选"总是显示"时，按钮对所有数据都出现，但负责人不匹配、数据被锁定等情况点击后仍会失败。判断问题要先读失败提示（"不满足显示条件""数据被锁定了"），再去查显示条件与锁定状态。
3. **后台改完必须刷新前端**：按钮显隐、顺序、场景配置保存后，前端页面不刷新是看不到变化的。演示中每次改完都回前端刷新确认，这是新手最容易漏的一步。
4. **个人级场景会覆盖企业级场景**：用户在前台调过字段顺序或隐藏字段后，后台再修改配置，该用户的前台不会跟着变。此时不是配置没生效，而是被个人场景覆盖了，要到前台【场景设置】→【恢复系统默认】里还原——这个按钮不在后台。
5. **"我负责的"和"我负责部门的"不是一回事**：前者看相关团队负责人是不是我，后者看数据归属部门是否属于我负责的部门（含级联，也含我助理负责部门的级联）；同理"我参与的"和"我下属参与的"差别在下属。讲场景时不能笼统说成"我相关的数据"。
6. **按钮/字段"不见了"先看主角色布局**：员工有多个角色时，前端只呈现主角色那一套布局。对象级配置都对，但主角色布局里没放出来，这个人在前端就是看不到——不要一头扎进按钮配置里反复改。
7. **"审核中"是被自动锁定的，不是按钮坏了**：给对象开了新建审批后，审批中的数据显示"审核中"并自动锁定，这期间编辑类按钮消失、点击报"数据被锁定了"，都是设计如此。等审批通过变"正常"后才恢复。
8. **后台对象配置只归 CRM 管理员**：字段、按钮、场景、布局这些入口都在后台，普通员工账号看不到；员工能做的只有前台个人级场景。所以"这个按钮/场景是谁配的"这类问题，范围只在 CRM 管理员里。
9. **术语与路径按界面口径统一**：课件把企业级场景也叫"租户级场景"，是同一个东西；还原个人调整走前台【场景设置】→【恢复系统默认】，别让学员在后台找。
10. **口播与幻灯片不一致时以幻灯片为准**：口播把按钮位置说成"详情页、列表页单条、列表页批量"，幻灯片还列出"相关列表页单条操作""新建页/编辑页"；口播里"全部 13 条、我负责的 18 条"等数据量是演示环境当时的数字，换环境会不同，不要当结论记。
