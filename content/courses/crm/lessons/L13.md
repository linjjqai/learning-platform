# 速览（30 秒看完）

- 本课是课时12「线索管理」的配套练习题讲解：10 道基础配置题、2 道挑战配置题、1 道思考题，全部在 CRM 测试账号里现场演示。
- 题目顺序就是线索全流程：新建／导入 → 线索池 → 分配 → 提醒／收回 → 转化／领取／无效 → 跟进规则。
- 判重是两套规则，入口挨在一起：查重设置管新建和扫名片，唯一性规则管导入、智能表单、API 对接，题2 要配的是后者。
- 线索池的管理入口集中在 管理后台 → 线索和线索池管理，页签里有线索池管理、线索转移设置、线索设置、线索跟进规则、线索基础设置。
- 一个池要配全五类规则：线索池类型、领取上限、超时提醒、分配规则、收回规则；分配规则按"优先级 + 筛选条件"匹配。
- 题4 的条件字段用的是「手机归属」（北京→营销一部、上海→营销二部）；超时提醒管"提醒谁"，收回规则管"把线索收回来"。
- 挑战题1 是电销场景（成员不可见、管理员分配、按产品类型／区域循环分配、24 小时提醒、2 天收回）；挑战题2 是展会场景（智能表单 → 工作流按城市转池 → 总经理人工分配 → 1 天提醒 → 30 天／3 天收回）。
- 思考题的结论：线索指"人"、客户指"企业"，同一个客户的多个人就是多条线索，被判重复也只是打了标签。

## 核心要点

- **本课定位**：承接课时12 的线索管理，题目本身带答案，讲师直接演示操作路径，重点在"后台配什么、前台怎么点"。全课分基础配置题（10 题）、挑战配置题（2 题）、思考题三块，顺序正好对上线索流程的进入、清洗评估、分配、跟进、转化五段。
- **题1 新建线索**：CRM → 销售线索对象列表 → 右上角点「新建」，只填必填信息即可提交。线索的进入方式有三种：手动新建、批量导入、手机端扫名片。
- **题1 更换负责人（两个入口）**：详情页右上角点「更换负责人」，选新负责人、决定原团队的处理方式后点确认；也可以在销售线索列表勾选这条线索，用上方工具栏的「更换负责人」统一换人，两条路径结果一致。
- **题2 唯一性规则**：后台 → 对象管理 → 预设对象管理 → 找到销售线索 → 唯一性规则，把校验方式设为"从外部导入时，需要根据唯一规则进行校验"，线索名称重复的数据导入时才会被拦下。
- **查重设置和唯一性规则是两套**：同一页面上还有「查重设置」，它只在新建线索、扫名片时生效；唯一性规则才管导入、智能表单、API 对接。题2 是导入场景，所以配的是唯一性规则；要让手动新建也防重名，查重设置得另外配一遍。
- **重复只打标签，不删数据**：命中规则后系统在新建、编辑保存时自动判定，重复数据在列表页、详情页都显示【重复】标签，并按"重复数据处理方式"决定是否合并。处理规则的位置是 预设对象管理 → 销售线索 → 重复线索管理；只想查某一条是否重复，用 CRM 首页 → 工具 里的查重工具，单条查。
- **清洗评估靠打分器（题目没考，流程里有）**：位置在 管理 → 业务规则管理 → 打分器规则设置，按属性多维打分评估线索质量。课件给的例子：公司规模大于 50 人 +2 分、有过过往合作经历 +2 分、经营状况良好 +3 分、企业信息填写完整 +1 分。
- **题2 导入操作**：前端销售线索列表右上角点「导入」→ 选择导入对象与导入方式（导入时可以直接选目标线索池，入池后由池规则提醒管理员分配）→ 下载导入模板 → 在表格里填好数据并保存 → 回到导入页上传模板 → 开始导入，结果可在导入记录里查看。
- **题3 线索池入口**：管理后台 → 线索和线索池管理，顶部页签依次是线索池管理、线索转移设置、线索设置、线索跟进规则、线索基础设置，线索池相关配置都从这里进。
- **题3 建池要素**：新建线索池要填线索池名称、线索池类型（线索池／伙伴线索池）、管理员、管理员协作人、线索池成员，再配分配领取规则、负责人规则、新线索提醒、领取上限。课件把池规则归成五项：线索池类型、领取上限、超时提醒、分配规则、收回规则。
- **题3 无效线索池**：用同样的入口再新建一个无效线索池，管理员与成员按题目要求设置，保存后两个池就都建好了。这个池就是题9 转移的落点。
- **题4 分配规则**：进线索池编辑页找到「分配规则」，可以添加多条规则并分优先级，每条规则由筛选条件 + 分配给谁组成。分配方式有手动分配、分配指定人、循环分配、自动分配几种。
- **题4 按地区分人**：优先级1 条件为「手机归属 属于 北京市」，分配对象选营销一部；优先级2 为「手机归属 属于 上海市」，分配对象选营销二部，最后点确定。
- **题5 提醒规则位置**：提醒不在前台设置，入口是线索池编辑页的「超时提醒」，分两行：一是超时未分配提醒线索池管理员，二是超时未跟进提醒线索负责人和外部负责人。两行可以只开一行；新线索进池时也能设成不提醒线索池管理员，按客户实际的管理方式选。
- **题5 30 分钟**：在"未跟进"一行填 0 小时 30 分钟，系统就会在 30 分钟未跟进时提醒线索负责人；还可勾选"触发未跟进超时提醒时，同时提醒线索池管理员"。
- **题6 收回规则**：同样在编辑页，进「收回规则」→ 添加收回规则 → 类型选"自动收回"；题目没给筛选条件就不配条件，只设"超过 1 小时未跟进，收回到本线索池"，点确定。已经转换的线索不参与收回，超时也不会被拉回来。
- **题7 线索转化**：进入跟进中的线索，判断它有做商机的可能后点「转化」，选择转化为客户和联系人，确认后补齐需要填写的信息再提交，转化即完成。转化时可以一并选中商机，转换要求也能配成"是否必须转客户／联系人／商机"；线索转换支持触发审批流。
- **线索的处理状态有四种**：跟进中（可定义哪些行为算跟进）、转换（转换要求可定义）、无效（标记无效状态）、退回（退回到原线索池）。题7 走转换，题9 走无效；题面里"收回"（超时系统归池）和"退回"（负责人主动退池）是两件事，别混着说。
- **题8 领取并通知管理员**：先在线索池编辑页勾选"领取时通知线索池管理员"并保存；再回到前台线索池的"未分配的"列表，选中线索点「领取」并确认。
- **题9 标记无效**：在销售线索列表选中该条线索，点右上角「无效」，维护好线索无效原因后确定；随后点「转移」，选择转移到无效线索池并确认。线索池里的线索在销售线索对象里同样能看到，这两步都在销售线索列表做。
- **题10 跟进规则**：后台 → 线索和线索池管理 → 线索跟进规则页签，编辑"销售线索"的跟进行为，只勾选 编辑、领取、发布销售记录、分配，其余行为不算跟进。最后跟进时间就按这套规则刷新，勾得越少，超时提醒和收回越容易触发；反过来，已经超时的线索写一条销售记录，就能从超时状态变回来。
- **智能表单怎么建（挑战题2 的前置）**：管理后台 → 对象管理 → 预设对象管理 → 智能表单，新建时先选基于哪个对象建；左侧可点的字段只能来自该对象已有的字段，缺字段先去对象下新建字段；必填字段默认带出且不能取消；"预设置项"是仅供内部填写的项；选择类型的字段可设默认值；还能设填写截止日期。发布形式三种：二维码、链接、网页嵌入代码。
- **挑战题1 拆解**：电销场景四件事——只有电销领导有分配权限且其余成员不可见（线索池成员只放领导、分配领取规则选"成员不可见，管理员可分配"）；按产品类型与区域自动分配（分配规则＋循环分配）；超过 24 小时未跟进提醒负责人；2 天未跟进自动收回本线索池。
- **挑战题2 拆解**：展会场景四件事——用智能表单收集姓名、手机号、公司、职务、所在城市；用工作流按城市把线索转到对应分公司线索池；池内成员不可见、由总经理（管理员）人工分配给销售并推送待办；超过 1 天未联系提醒，30 天未转化或 3 天未跟进则收回重分。
- **思考题结论**：线索对应的是"人"，客户对应的是"企业"。同一个人每年参展、同一公司的两个人、两个不同公司的人，都要各录一条线索；即使按公司名称被判为重复线索，业务上仍是两条线索记录。

## 结构与流程

```
题1 在销售线索对象中新建一条线索，操作更换负责人
 考点：新建入口 ＋ 更换负责人
 做法：CRM → 销售线索 → 右上角「新建」（只填必填）→ 提交
 详情页右上角「更换负责人」选人确认；或列表勾选 → 工具栏「更换负责人」

题2 批量导入一批线索，线索名称不可重复
 考点：唯一规则 ＋ 导入
 做法：后台 对象管理 → 预设对象管理 → 销售线索 → 唯一规则
 → 校验方式设为"从外部导入时按唯一规则校验" → 保存
 前台 销售线索列表 → 右上角「导入」→ 选对象与导入方式 → 下载模板
 → 填数据保存 → 上传模板 → 开始导入

题3 后台建「营销中心线索池」和「无效线索池」，设管理员，营销中心部门入成员
 考点：线索池基础信息
 做法：管理后台 → 线索和线索池管理 → 线索池管理 → 新建
 填 名称／类型（线索池）／管理员／协作人／线索池成员（营销中心部门）→ 确定
 同样入口再建「无效线索池」，配好管理员与成员

题4 加 2 个分配规则：北京 → 营销一部，上海 → 营销二部
 考点：分配规则（优先级 ＋ 筛选条件）
 做法：线索池编辑 → 分配规则 → 添加分配规则
 优先级1「手机归属 属于 北京市」→ 营销一部
 优先级2「手机归属 属于 上海市」→ 营销二部 → 确定

题5 线索超过 30 分钟未跟进，提醒线索负责人
 考点：超时提醒
 做法：线索池编辑 → 超时提醒 → 未跟进一行填 0 小时 30 分钟
 → 提醒线索负责人和外部负责人（可勾选同时提醒线索池管理员）→ 确定

题6 线索超过 1 小时未跟进，自动收回到本线索池
 考点：收回规则
 做法：线索池编辑 → 收回规则 → 添加收回规则 → 选"自动收回"
 → 题目未要求则不配筛选条件 → 超过 1 小时未跟进 → 收回到本线索池 → 确定

题7 将跟进中的有效线索转换为客户和联系人
 考点：线索转化
 做法：打开跟进中的线索 → 点「转化」→ 转化为客户和联系人 → 确定
 → 补齐客户／联系人信息 → 提交

题8 领取线索池中未分配的线索，并设置领取后通知线索管理员
 考点：领取 ＋ 领取通知
 做法：后台 线索池编辑 → 勾选"领取时通知线索池管理员" → 确定
 前台 线索池 → 未分配的 → 选中线索 → 「领取」→ 确认

题9 无意向线索标记无效，并转移到无效线索池
 考点：无效 ＋ 转移
 做法：销售线索列表 → 选中线索 → 右上角「无效」→ 填无效原因 → 确定
 → 「转移」→ 选无效线索池 → 确定

题10 只有 编辑／领取／发布销售记录／分配 才算跟进线索
 考点：线索跟进规则（跟进行为）
 做法：后台 线索和线索池管理 → 线索跟进规则 → 编辑 销售线索
 → 只勾 编辑、领取、发布销售记录、分配 → 确定

挑战题1 多渠道获客：只有电销领导可分配、其余成员不可见；按产品类型＋区域自动循环分配；
 24 小时未跟进提醒；2 天未跟进收回
 考点：线索池 ＋ 分配规则 ＋ 超时提醒 ＋ 收回规则（无工作流）
 做法：① 建线索池，管理员＝电销领导，成员只放领导；分配领取规则＝"成员不可见，管理员可分配"
 ② 分配规则按优先级配条件：产品类型＝实验室产品 → 对应人员；
 产品类型＝在线产品 → 对应人员；其他产品 → 对应人员（再叠加华东／华南／华北区域循环分配）
 ③ 超时提醒：超过 24 小时未跟进 → 提醒线索负责人
 ④ 收回规则：超过 2 天未跟进 → 自动收回到本线索池

挑战题2 多城市展会：现场留资 → 按城市分给分公司总经理 → 再分给销售 → 1 天联系 → 30 天／3 天收回
 考点：智能表单 ＋ 工作流 ＋ 线索池 ＋ 超时提醒 ＋ 收回规则
 做法：① 后台 对象管理 → 智能表单，对象选销售线索，字段收 姓名／手机号／公司／职务／所在城市
 ② 工作流管理 → 新建线索自动分配工作流，触发对象＝销售线索，
 按城市设分支（北京／上海／深圳…）＋ 立即执行的活动 → 转移到对应分公司线索池
 ③ 各分公司线索池：成员不可见、管理员（总经理）可分配；新线索提醒为管理员推送待办，便于及时分配
 ④ 超时提醒：超过 24 小时（1 天）未跟进 → 提醒线索负责人及相关成员
 ⑤ 收回规则：自动收回，30 天未转化 或 3 天未跟进 → 收回到本线索池，重新分配

思考题 一个人每年都来参加展会，是一条线索还是两条线索
 考点：线索与客户的区别
 结论：线索是"人"、客户是"企业"；同一个客户下的多个人 → 多条线索
 同公司两人（李总＋同事）→ 两条线索；两个不同公司的人 → 两条线索；
 两个不同部门的两个人（销售部领导＋IT 负责人）→ 两条线索，最终关联同一客户，未来可产生多个商机
 按公司名称判重只会标为重复线索，记录本身仍是两条
```

## 术语表

| 术语 | 含义 |
| --- | --- |
| 销售线索 | CRM 中承载潜在客户"人"信息的对象，新建、导入、转化都在该对象下操作 |
| 更换负责人 | 把线索的归属人改成另一个人，详情页右上角和列表页工具栏都有入口 |
| 唯一规则 | 后台预设对象上的校验规则，可设为"从外部导入时按唯一规则校验"，用于防止重复数据导入 |
| 预设对象管理 | 后台对象管理下管理标准对象（销售线索、客户等）及其规则的入口 |
| 导入模板 | 从导入页下载的表格模板，按列填好线索数据后再上传 |
| 线索和线索池管理 | 后台管理线索池、线索设置、跟进规则的总入口，含五个页签 |
| 线索池 | 存放暂未分配给具体负责人的线索的容器，可按业务划分（营销中心、无效、分公司等） |
| 线索池管理员 | 负责在池内分配线索的人，挑战题中通常是部门领导或分公司总经理 |
| 线索池成员 | 有权限看到／领取该池线索的人员或部门 |
| 分配领取规则 | 决定成员能否自己领取：成员可见可领取、管理员可分配；或成员不可见，管理员可分配 |
| 领取上限 | 限制每个员工最多能领取多少条线索 |
| 新线索提醒 | 新线索进池时给管理员推送待办，便于及时分配 |
| 分配规则 | 在线索池内按筛选条件自动把线索分给指定人员的规则，支持多优先级 |
| 手机归属 | 分配规则中使用的条件字段，按手机号归属地判断地区（题4 用北京／上海判断） |
| 超时提醒 | 线索池内的提醒规则，超时未分配提醒管理员、超时未跟进提醒负责人 |
| 收回规则 | 满足条件（如超时未跟进）时把线索自动收回本线索池的规则 |
| 线索转化 | 把有效线索转为客户和联系人，转化后进入客户体系 |
| 领取 | 在线索池中把未分配的线索认领到自己名下 |
| 无效 / 无效线索池 | 把无意向线索标记为无效并转移到专门的池中沉淀 |
| 线索跟进规则 | 定义哪些行为才算"跟进过"线索，直接影响超时提醒与收回的计时 |
| 智能表单 | 后台对象管理下配置的表单，用于展会等场景在线收集线索信息，可按二维码、链接、网页嵌入代码三种形式发布 |
| 工作流 | 后台配置的自动化流程，可按条件分支自动执行转移、更新等动作 |
| 重复线索 | 命中判重规则（如公司名称相同）的线索，仍以两条记录存在，只是被标记 |
| 查重设置 | 预设对象-销售线索下的判重规则，新建线索、扫名片时遵循，与唯一性规则是两套 |
| 重复线索管理 | 预设对象-销售线索下设置重复数据如何标记、归集、合并的入口 |
| 重复标签 | 命中查重规则后自动打到线索上的【重复】标记，列表页、详情页都显示 |
| 查重工具 | CRM 首页-工具里的单条查重入口，不必新建也能查这条线索是否重复 |
| 扫名片 | 手机端把名片信息直接录成线索的入口，同样遵循查重设置 |
| 打分器 | 管理-业务规则管理-打分器规则设置，按线索属性多维打分评估质量 |
| 线索处理状态 | 跟进中 / 转换 / 无效 / 退回 四种状态，各对应不同的业务动作 |
| 退回 | 把线索退回原线索池的动作，和"收回"不是一回事 |
| 线索保有量 | 员工手上线索数量的上限，超过领取上限再领取会提示已达上限 |
| 线索池类型 | 建池时选的类型，决定成员是"员工可见可领取"还是"成员不可见、管理员可分配" |
| 预设置项 | 智能表单中仅供内部填写、不对外展示的字段项 |
| 黑名单线索池 | 被标记黑名单的线索自动进入、不再流转的池（课件案例2） |
| SDR | 销售开发代表，负责清洗市场线索、外呼拓客并产出有效线索；SDR 不等于电销，电销的任务是电话成交 |
| MQL | 市场认可线索，营销投入后表现出兴趣、相对更容易转成客户的线索 |
| SQL | 销售认可线索，销售跟进 MQL 后判定为高质量，等于被当成潜在客户 |
| ROI | 投资回报率 |
| CPQ | 配置、定价、报价的功能组合，用于需要复杂产品配置与报价的场景 |

## 需要注意的点

1. **题4 题目写"城市"，演示选的是「手机归属」**：幻灯片上题目是"城市属于北京"，实际操作里分配规则的条件字段选的是"手机归属"，按号码归属地判断地区。配置时按题目语义找能落地的字段，别在字段列表里死找"城市"。
2. **题10 的跟进规则不能直接保存**：线索跟进规则默认的跟进行为里包含 跟进中、发邮件、转移、无效 等多项，与题目要求不一致，必须按题目只保留 编辑、领取、发布销售记录、分配 再保存。这份清单还决定"最后跟进时间"什么时候刷新——勾漏了，超时提醒和收回会一直压着这条线索；已经超时的线索写一条销售记录就能变回未超时。
3. **题2 的两套判重规则别配反**：查重设置只管新建和扫名片，唯一性规则才管导入、智能表单、API 对接。题2 是导入，配唯一性规则；如果客户同时要求手填重名也拦，那查重设置得再配一遍，只配一边必漏一边。
4. **题8 要后台＋前台两处动作**：领取本身在前台线索池里点，但"领取后通知线索管理员"这个开关在后台线索池编辑页，只做前台领取等于没答完题。
5. **挑战题1 的"成员不可见"靠分配领取规则，不靠权限**：把线索池成员只设成电销领导，并把分配领取规则选为"成员不可见，管理员可分配"，其余成员自然看不到；用权限去限制反而绕远。
6. **两道挑战题的分工别混**：有固定规则（按产品类型／区域、按城市）就用线索池的分配规则或工作流自动分；题目明确说"没有特定的分配规则、由总经理人工分"时，就只建池＋管理员手动分配。另外思考题里"判为重复线索"和"两条线索"是两回事，判重只是打标签，记录数不变。
7. **"看不见线索"按三层查，别一上来就改权限**：① 他是不是线索池成员、池类型是不是"员工可见可领取"；② 线索池规则里的字段可见设置；③ 角色权限里销售线索的查看权限。另外管理员分配时只能搜到线索池成员，不是成员的选不出来；成员自己领取时提示"达到线索保有量上限"，是领取上限到了。
8. **已转换的线索是锁定态**：不能收回、不能更换负责人、也不能再分配给别的负责人；要作废得先有线索的解锁权限。但已经转换完的线索可以删除。
9. **作废后重建提示"已存在"**：线索作废后记录还留在回收站里，再新建同名就会提示已存在；要让管理员到回收站里恢复或者彻底删掉那条，再重新录入。
10. **跟进中的线索一旦被分配或更换负责人，状态会变回"待处理"**：这是系统规则，不是故障。反过来，写了销售记录并不会把状态推着走，状态看的是分配、换负责人这类动作，别拿"我写了记录"当作状态已更新。
11. **线索池不是待办箱**：线索被继续跟进、甚至已经转化成客户，仍然会留在池里显示。线索池只是存放线索的地方，不会因为跟进或转化就自动消失。
12. **能改线索池规则的不止 CRM 管理员**：CRM 管理员、该池的线索池管理员，以及企业自定义的、拥有线索和线索池管理模块权限的管理员，都能改。
