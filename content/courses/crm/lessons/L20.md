# 速览（30 秒看完）

- 本课是前几天学过的 CRM 核心模块的集中串讲和复习，不是新知识点课。
- LTC = Lead（线索）→ Customer（客户）→ Transaction（交易），是从线索到交易完成的完整销售周期。
- 线索生命周期：收集（智能表单）→ 打分（打分器）→ 分配（工作流 + 线索池）→ 跟进转化（客户）。
- 线索自动分配涉及"工作流的数据操作"——转移到线索池时，转移会保留原负责人，退回会清空负责人。
- 线索和客户两个对象有"公开转为公海"功能，其他对象没有；这两个对象也是唯一能在工作流里做"数据操作（转移/退回）"的对象。
- 客户模型搭建：先确定核心关注字段（客户方向），再通过多业务类型/布局规则区分不同类型客户的信息差异。
- 多业务类型与布局规则的选择：业务本质上多种类型用"多业务类型"，只是字段差异用"布局规则"；一旦选定不可修改。
- 高级外勤 vs 普通外勤：高级外勤可固化执行步骤（拍照门头、拍陈列、拍库存），普通外勤只能手动记录。
- 销售记录已"对象化"——意味着它能像普通对象一样配置字段、被后台流程匹配。日志、日程也已对象化。
- 商机有新旧版本：商机 2.0（新商机）支持 aPaaS 个性化调整，2019 年底后新开通企业只有商机 2.0。
- 商机推进用"阶段推进器"固化优秀销售的跟进步骤，让新销售按阶段系统指导做事。
- 商机转报价单的"一键带数据"靠两个功能配合：**映射规则**（字段映射关系）+ **按钮**（点击触发映射）。
- 回款计划前 N 天提醒销售催款是工作流的典型场景——定时触发 + 消息活动。
- 练习环节做了三道题：工商注册验证规则、外勤高级配置、回款计划提醒工作流。

## 核心要点

- **线索来源与收集**：线索渠道包括官网、400 电话、线下展会、搜索引擎。收集方式用"智能表单"——发布形式有二维码、链接、嵌入网页。从**前端**线索列表页"分享智能表单"生成的链接/二维码，收集的线索自动归当前负责人；从**后台**生成的表单线索归线索池。
- **线索打分器**：帮助判断线索质量高低。关键注意点：① 一个对象只能配一个打分器规则（否则系统冲突）；② 不只用于线索，客户等其他对象也可以用打分器判断其他属性。
- **线索分配**：公司自己的流程是——线索进公海→按区域分配到各区分公司总经理→再由总经理分给下属销售。这个过程分两层：第一层用**工作流**按地区自动转移到各区分公司线索池；第二层在各区分公司线索池内，用线索池自身的"领取"功能分给业务员。
- **工作流"数据操作"——转移 vs 退回的区别**：转移保留原负责人；退回清空负责人。
- **线索/客户独有功能**：后台工作流中，只有线索和客户对象在执行活动里有"数据操作（转移/退回）"选项，其他对象没有。因为只有这两个对象有线索池/公海的概念。
- **线索池分配规则**：线索池管理员可设置默认分配规则（仅管理员和指定同事）；按人员能力/层级分配不同量的需求，目前**默认功能做不到**，需通过低代码实现。
- **线索分析**：市场部最关注——各渠道线索数量、转化率、打分质量。BI 报表可生成看板，客户也可以搭建一套。
- **客户模型——确定"客户方向"**：帮客户梳理最关心的客户信息维度（如我们公司关注行业、客户级别/RFM 值），落到字段里。
- **多业务类型 vs 布局规则**：不同类型客户要维护不同信息——如果业务上确实是多种类型（如经销商 vs 终端客户），用"多业务类型"；如果只是一些简单字段差异，用"布局规则"。**一旦选定不可修改**。
- **高级外勤功能**：可固化执行步骤（如拜访必须拍门头照、拍陈列照、拍库存照），销售按步骤走，没完成不能提交。普通外勤只能手动写记录。讲师提到行业部做了一个"外勤自动生成日报"配置包——销售只需发外勤，日报自动汇总外勤、商机、销售记录。
- **销售记录自动沉淀**：只要发外勤、写日志、发审批时关联了该客户，在客户**详情页右侧**就会自动沉淀一条销售记录——包含时间、内容、发起人。
- **"对象化"概念**：原本只是其他对象下的小功能/小模块（如销售记录、日志、日程），研发把它们变成独立对象后叫"对象化"——对象化后可以在后台对象管理里配置它们的字段，也能和权限、流程等匹配。
- **商机（商机 2.0）**：商机是潜在销售机会，项目型企业（装备制造、医疗、专业服务、ICT）普遍需要。老商机不支持 aPaaS 个性化，商机 2.0 全面支持，2019 年底起新企业只有商机 2.0。老商机已改名"商机"，商机 2.0 简叫"商机"，但一些客户账号里还能看到旧商机。
- **阶段推进器**：把优秀销售的跟进步骤固化成阶段和动作（如阶段一必须下载报价模板发客户），新销售进入商机后系统引导按阶段推进，降低培训成本。
- **商机转报价单一键带数据**：两个功能配合——① 映射规则（管理后台→业务规则管理→映射规则）配置商机字段→报价单字段的映射关系（字段类型必须一致才能映射）；② 商机详情页有系统预建的"转化为报价单"按钮，点击自动触发映射。线索转客户也用了同样机制。
- **回款计划催款提醒——工作流典型场景**：回款计划里"计划回款日期"前 7/15 天提醒销售联系客户打款。用**定时触发**工作流——条件可加（如回款状态是"待回款"），活动用"企信提醒"通知数据负责人。
- **工商注册验证规则练习**：配置"客户创建时，工商注册字段（布尔型）= false 则阻断保存"。布尔型在字段里显示为"是/否"，但在公式里写 true/false。要点：先做工商注册的自动化调用，再写阻断公式。
- **高级外勤配置练习**：先在"外勤动作"里新建需要的动作（如"拍门头照""拍陈列照""拍库存照"），再在"外勤类型"里把这些动作组装进去。销售发外勤时选类型，系统引导逐步完成动作。易错点：外勤类型和布局规则混淆，注意区分。
- **外勤练习总结**：讲师确认了正确配置路径——外勤动作先建好拍照类动作，外勤类型里组装动作；布局规则用来区分不同业务类型客户显示哪些字段。

## 结构与流程

LTC 全链路：

```
线索阶段（Lead）
 收集（智能表单 → 二维码/链接/嵌入网页）
 → 打分（打分器，一个对象一个规则）
 → 分配（工作流自动按区域转移到线索池 + 线索池内领取）
 → 跟进 → 转化为客户

客户阶段（Customer）
 确定客户方向（核心关注字段）
 → 区分类型（多业务类型 / 布局规则）
 → 跟进（外勤 + 高级外勤 + 销售记录自动沉淀）
 → 商机转化（阶段推进器 + 报价单映射规则）

交易阶段（Transaction）
 报价单 → 销售合同 → 销售定单 → 回款计划 → 回款 → 开票
```

## 术语表

| 术语 | 含义 |
| --- | --- |
| LTC | Lead→Customer→Transaction，从线索到交易完成的完整销售周期 |
| 智能表单 | CRM 收集线索的工具，发布形式有二维码/链接/嵌入网页 |
| 打分器 | 根据预设条件自动判断线索/客户质量并打分的规则，一个对象只能一个 |
| 线索池 | 未分配具体负责人的线索存放区域，可设置管理员和默认分配规则 |
| 公海 | 客户/线索对象的公开区域，未分配负责人时存放的区域 |
| 工作流数据操作 | 工作流执行活动的一种，可把数据转移到指定线索池/退回线索池 |
| 高级外勤 | 可固化执行步骤（拍照等）的外勤类型，销售必须逐步完成才能提交 |
| 对象化 | 原本是其他对象下的功能模块，研发后变成独立对象，可在后台配置字段 |
| 商机 2.0 | 新版商机，全面支持 aPaaS 个性化，2019 年底后新企业仅用此版本 |
| 阶段推进器 | 把优秀销售的跟进步骤固化成阶段和动作的工具 |
| 映射规则 | 管理后台配置，指定字段从源对象自动带到目标对象的对应字段 |
| 回款计划催款 | 回款计划字段"计划回款日期"前 N 天提醒销售的工作流定时触发场景 |

## 需要注意的点

1. **智能表单的线索归属**：从前端线索列表页点"分享智能表单"生成的链接/二维码收集的线索自动归你；从后台生成的表单线索归线索池。别搞错。
2. **一个对象只能配一个打分器规则**：多了系统冲突不知道该用哪个。
3. **布尔型字段的公式写法**：工商注册字段在前端显示"是/否"，但在公式里写 true/false。验证规则里写"工商注册 = false 则阻断保存"。
4. **多业务类型 vs 布局规则一旦选定不可修改**：做客户模型时慎重选择。业务本质多种类型→多业务类型；仅字段差异→布局规则。
5. **高级外勤配置路径**：先在"外勤动作"里建动作，再在"外勤类型"里组装。不要去"外勤规则"里找。
6. **映射规则的前提条件**：源字段和目标字段类型必须一致才能映射。商机转报价单带不出数据时先检查字段类型是否匹配。
