# 速览（30 秒看完）

- 工作流＝自动触发器：条件满足了系统自己执行动作，不用人点。课件开篇的例子就是市场部收集的线索按所属地区自动分到各地区的电销线索池。
- 一条工作流只填四件事：在"管理后台 → 流程管理 → 工作流管理 → 右上角新建"里选对象、选何时触发、加条件、设触发操作。
- 五种触发方式：新建、作废、恢复、字段更新、定时触发。定时触发还能按"某个日期前/后 N 天/周/月"跑，并分执行一次和重复执行。
- 字段更新触发必须再补一条"某字段变更时"才能保存，这条条件只为防误触发、不影响触发结果；统计字段和引用字段要触发得先去字段白名单里加。
- "数据操作（退回/转移公共池）"只有线索和客户对象有，商机等其他对象没有——因为只有它们分线索池、公海。
- 课件共 8 道配置题，课上带做 7 道：题一对比执行活动、回款前 15 天催款、工单完成填时间、合同归档后锁定、新客户进公海、商机到期未赢单提醒、线索 24 小时未跟进收回；剩下一道"交付申请提交后自动发起业务流"补在核心要点里。
- 线索超时收回有两条路：工作流（定时触发+超时判断+退回公共线索池+提醒）或线索池自带的收回规则，后者更简单、优先用。
- 查工作流有没有跑：企业日志 → 流程日志 → 执行日志/触发日志；历史数据不会因为新建了工作流就补跑。

## 核心要点

- **工作流是什么**：按事先设好的规则自动执行一个操作，不需要人工分配。课件开篇举的就是线索管理课里的场景——市场部收集的潜在客户信息，根据收集到的地区不同，自动划分给各地区的电销线索池。
- **后台入口与四步配置**：管理后台 → 流程管理 → 工作流管理 → 右上角"新建"。页面上就四块：**请选择对象**（确定基于哪个对象发起）、**何时触发此工作流**（触发机制）、**添加条件**（要同时满足这个条件和上面的触发选项，系统才执行）、**触发操作**（有的对象既配了新建触发审批流、又配了新建触发工作流，这里决定触发审批流的同时要不要也触发工作流）。
- **五种触发方式**：新建（新建数据时触发）、作废（作废某条数据时触发）、恢复（恢复已作废的数据时触发）、字段更新（对象下字段被修改后触发）、定时触发（对象下日期时间到达设定时间时触发）。注意：触发条件和执行条件的选项都来自发起对象里的字段，对象里没有的字段选不到。
- **定时触发的三种时间口径**：一是按固定周期循环触发；二是"当某个日期前/后 N 天/周/月"触发；三是选执行一次还是重复执行——执行一次是到了客户"下次跟进时间"当天 9 点只触发这一次，重复执行是从那天起每天 9 点都触发一次。回款前 15 天催款要用重复执行，因为它每天都要检查一遍数据。
- **执行活动清单（13 项）**：CRM 提醒（向相关人员发送 CRM 消息，界面/口播里也叫企信提醒）、字段变更（自动改某对象某字段的内容）、短信通知、邮件通知（发给客户/指定角色）、数据操作（自动退回或转移客户/线索到公共池）、发起业务流程、数据锁定/解锁、分配负责人（分配给指定人员）、新建任务、新建日程、新建销售记录（在发起对象下建一条）、执行APL代码（执行特定函数运算）、新建外部通知（向微信用户/下游伙伴发消息）。
- **活动可配多项，菱形处配分支条件**：长方形处配执行的活动，一条工作流可以同时执行多项活动；菱形处写执行条件，即满足什么条件才执行后面的活动，支持配多个条件。
- **字段更新触发的硬性要求与白名单**：选字段更新触发时，不管下面配了哪种触发条件，都必须再加一条"某字段变更时"才能保存——这条条件只为防止随便改个字段就触发，本身不参与触发判断。统计字段、引用字段要能触发，得先去"工作流管理 → 右上角【全局配置】→ 字段白名单配置"把它加进白名单，例如客户下新增一个统计"角色为 KP 的联系人有多少个"的统计字段，数量变化时提醒客户负责人关注。
- **题一：线索/客户对象 vs 其他对象执行活动的区别**：给"销售线索""客户"对象各建一条新建触发的工作流，执行活动里都多出"数据操作（转移/退回公共池）"，商机、合同、定单等其他对象没有这项。原因就是只有线索和客户有线索池/公海的概念，数据能被退回或转移走。
- **题二：回款计划到期前 15 天提醒催款**：定时触发（重复执行）→ 执行日期＝计划回款日期前 15 天、执行时间 9:00 → 执行活动用企信提醒，提醒对象是回款计划的数据负责人，让他联系客户提醒打款。每天跑一遍，进入 15 天窗口的数据都会被提醒到。
- **题三：工单完成后自动填完成时间**：工程师做完售后工单、状态改成"已关闭"时要自动记录完成时间。配置：字段更新触发（工单状态变更时）+ 条件"工单状态＝已关闭" → 执行活动用字段变更，把工单完成时间填成 `当前日期()` 函数（取当前服务器时间）。完成时间字段的类型要和日期函数对得上。
- **题四：合同归档后自动锁定**：合同下有一个字段叫"**是否归档**"，归档之后数据不能被编辑。配置：字段更新触发（是否归档变更时）+ 条件"是否归档＝是" → 执行活动用数据锁定。
- **补充题（课件第 5 题）：交付申请提交后自动发起业务流**：已成交客户要做 CRM 实施交付，员工在 CRM 里发起【交付申请】，提交后要自动触发交付申请的业务流，省掉人工再发起一次的动作。配置：新建触发（交付申请对象）+ 执行活动"发起业务流程"。业务流本身怎么画，下一课 L25 再讲。
- **题五：新客户自动进公海**：新进来的客户先自动进入公海池，由管理员统一分配。配置：新建触发（总是触发）→ 执行活动用数据操作，转移到客户公海。客户公海在对象里就是一个固定的池对象，直接选"客户公海"即可。
- **题六：商机到期未赢单提醒**：销售建商机时要录预计成交时间，到了预计成交时间当天还没赢单就提醒负责人。配置：定时触发（执行日期＝预计成交时间当天）+ 条件"商机阶段≠赢单、≠输单、≠无效" → 执行活动用企信提醒，提醒对象是商机数据负责人，话术里让他二选一：要么改预计成交时间，要么把商机推进到输单/无效。
- **题七：线索按大区分配 + 24 小时未跟进收回**：公司有华东、华南、华北三个大区，市场部活动收集的线索先按所属大区分给对应大区销售总监（新建触发 + 数据操作，转移到该大区线索池），总监再把线索分给业务员；业务员 24 小时内没处理（线索状态还是"待处理"），线索自动收回到"公共线索池"，并提醒对应的大区销售总监。用工作流做：定时触发（执行日期＝分配给业务员当天）+ 条件"状态＝待处理 且 距分配时间已过 24 小时" → 执行活动：① 数据操作，退回公共线索池；② 企信提醒，提醒该大区销售总监。
- **题七的第二条路：线索池自带收回规则**：后台线索池配置里直接设"分配给业务员 X 小时未跟进 → 自动收回"，不用写工作流，效果一样、更好维护。只做超时收回时优先用这个；还要按大区分流、还要额外提醒销售总监，才上工作流。
- **课件给的 6 个对号入座例子**：每月最后一周提醒销售关怀客户＝定时触发 + CRM 提醒；来源是市场活动的线索自动进市场部线索池＝新建触发 + 数据操作；新建知识库案例提交后自动锁定不让改＝新建触发 + 数据锁定；拜访记录里填了下一次拜访日期要生成日程＝字段更新触发 + 新建日程；新建项目计划表要给参与人员建任务＝新建触发 + 新建任务；订单发货后给收件人推发货信息＝字段更新触发 + 短信/邮件/外部通知。
- **怎么确认工作流跑没跑**：企业日志 → 流程日志 → 执行日志/触发日志，能看到流程由谁、用什么方式执行、耗时多久。数据"没反应"时先来这里看，别急着回去改配置。
- **历史数据不会补跑**：工作流只对配置生效之后的数据生效。去年创建的数据碰上今年新建的工作流不会触发，要它触发只能手动编辑一次、或更新导入匹配数据来触发（前提是这条工作流支持"编辑时触发"）。不补跑的原因是有些企业历史数据量太大，直接生效会让系统瞬间负载过高。
- **本课定位**：这是 L23 工作流功能讲解的配套练习课，课件这 8 道题就是把五种触发方式和执行活动两两组合练一遍。判断套路固定：先看业务是"某件事发生了"还是"某个时间到了"（定触发），再看要满足什么条件，最后看要执行什么活动。

## 术语表

| 术语 | 含义 |
| --- | --- |
| 定时触发重复执行 | 按某个日期字段每天/每周/每月循环触发工作流 |
| 字段更新触发 | 某个字段变更时触发工作流，需配合"变更时"条件 |
| 数据操作（转移） | 线索/客户独有的执行活动，把数据转移到指定线索池/公海 |
| 当前日期() | 系统内置函数，在字段变更里填入获取当前服务器时间 |
| 线索池自动收回规则 | 线索池自带的功能，配置分配后 X 小时未跟进自动收回，比工作流简单 |
| 工作流（自动触发器） | 按设定规则自动执行操作，不需要人工分配到具体人，如线索按地区自动进对应线索池 |
| 新建触发 | 新建该对象数据时触发这条工作流 |
| 作废触发 | 作废某条数据时触发这条工作流 |
| 恢复触发 | 恢复某条已作废数据时触发这条工作流 |
| 定时触发 | 对象下日期时间到达设定时间时触发，可按周期循环，也可按某个日期前/后 N 天/周/月 |
| 执行一次 / 重复执行 | 定时触发两种口径：只触发一次；或从该日起每天（每周/每月）反复触发 |
| 添加条件 | 必须与"何时触发"同时满足，系统才执行这条工作流 |
| 触发操作 | 对象同时配了新建触发审批流和工作流时，决定触发审批流的同时要不要也触发工作流 |
| CRM 提醒（企信提醒） | 向相关人员发送 CRM 消息提醒 |
| 字段变更 | 自动变更某个对象下某个字段的内容 |
| 数据操作 | 自动把客户/线索退回或转移到公共池，只有这两类对象有 |
| 发起业务流程 | 自动发起一条业务流程，省掉人工手动发起 |
| 数据锁定/解锁 | 对数据加锁或解锁，锁定后不能编辑 |
| 分配负责人 | 把数据分配给指定人员 |
| 新建任务 / 新建日程 | 在工作界面自动创建一条任务、一条日程 |
| 新建销售记录 | 在发起对象下创建一条销售记录 |
| 执行APL代码 | 执行特定的函数运算 |
| 新建外部通知 | 向微信用户/下游伙伴发送通知消息 |
| 分支条件（菱形） | 判断满足什么条件之后再执行后面的活动，可配多个 |
| 字段白名单配置 | 工作流管理-全局配置里的入口，统计字段/引用字段要能触发须先加入白名单 |
| 执行日志 / 触发日志 | 企业日志-流程日志下的两类日志，看工作流是否触发、由谁执行、耗时多久 |
| 历史数据 | 工作流创建之前已存在的数据，不会被新建的工作流触发 |

## 需要注意的点

1. **字段更新触发保存不了，就是缺"变更时"条件**：选了字段更新触发，系统要求不管下面配了哪种条件，都必须再加一条"某字段变更时"才让保存。这条条件本身不参与触发判断，只是防止随便改个字段就触发工作流。
2. **合同那个字段叫"是否归档"**：课件题目和界面里都是"是否归档"，之前写成"是否规短"是错字，配置时照界面里的字段名去选，别自己造。
3. **统计字段、引用字段触发要先加白名单**：默认触发不了，会提示先去加白名单。位置是"工作流管理 → 右上角【全局配置】→ 字段白名单配置"，再把客户对象下那个统计字段选进去，例：统计客户名下角色为 KP 的联系人数量，数量变化时提醒负责人。
4. **历史数据不会补跑**：去年创建的数据碰上今年新建的工作流不触发。要它触发只能手动编辑一次，或更新导入匹配数据来触发，前提是这条工作流支持"编辑时触发"。产品不做全量补跑，是因为历史数据量大，直接生效会让系统瞬间负载过高。
5. **排查先看日志，别先改配置**：企业日志 → 流程日志 → 执行日志/触发日志。先确认是压根没触发（对象选错、条件不满足、历史数据），还是触发了但后面的活动没执行。
6. **"触发操作"这个开关很容易漏**：同一个对象既配了新建触发审批流、又配了新建触发工作流时，靠它决定触发审批流的同时要不要也触发工作流。客户说"两条都配了只有一个跑"，先看这里。
7. **定时触发的执行日期字段别选错**：回款催款用计划回款日期，商机提醒用预计成交时间，客户跟进提醒用下次跟进时间。字段选错等于整条流程白配。
8. **执行一次和重复执行别选反**：一次性提醒（到期当天提醒一次）用执行一次；需要每天滚动检查的（回款前 15 天窗口、24 小时未跟进）必须用重复执行。
9. **线索超时收回优先用线索池自带规则**：后台线索池里配"分配给业务员 X 小时未跟进 → 自动收回"，比写工作流少维护一层，效果一样。只有还要按大区分流、还要额外提醒销售总监时才上工作流；题七的提醒对象是分线索过去的那位大区销售总监，不是线索池管理员。
10. **商机条件的三终态缺一不可**：阶段≠赢单、≠输单、≠无效，三个都排除条件才成立。只排除赢单，已输单的商机会被反复拉出来提醒。
11. **工作流只负责自动执行，别拿它替审批流**：需要有人判断、有人点通过的场景用审批流；需要自动跑完一整套动作的用工作流或业务流，三个概念别混。
12. **工作流不会因为"改了字段"就随便跑**：加上"变更时"条件之后，只有指定的那个字段变了才触发；如果客户反馈"改别的字段也触发了"，先看触发条件是不是选成了不相关的字段。
