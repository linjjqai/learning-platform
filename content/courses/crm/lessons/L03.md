# 速览（30 秒看完）

- 系统初始化＝拿到开箱账号后，按本企业规则把后台基础配置改一遍：组织架构与账号、权限、企业设置等。
- 后台仍由四部分组成：组织架构（谁用）、模块（用什么）、权限（用多少）、流程（怎么用），本课只讲"系统管理"这一半。
- 系统管理共六块：管理首页、企业设置、组织架构管理、角色权限管理、企业日志、集成平台管理，另有系统配置引导。
- 管理首页要看两个数：总员工数 ≠ CRM 用户数——导入员工只是建账号，还要单独分配 CRM 角色才能用前端。
- 组织架构"先部门、后员工"：部门名称不可重复、最多 15 级、"全公司"不算一级部门、负责人只能设 1 人。
- 员工停用与禁止登录不是一回事：停用不占账号配额、不可删除、重新启用要重设权限；禁止登录仍然占配额。
- 角色权限分两层：管理功能权限决定能进哪个后台（系统管理员 / CRM 管理员），业务功能权限决定能操作哪些对象。
- 企业日志能回答"谁在什么时候改了什么"，课末给了 6 个典型排障场景，可以直接照着查。

## 核心要点

- **系统初始化的含义**：在正式使用系统之前，管理员要先给系统做一套初始设置，包括组织架构与账号导入、权限设置等。我们拿到的都是开箱账号、保持一致的默认配置，但各家企业规则不同，所以要先做个性化调整，这个过程就叫系统初始化。
- **后台永远由四部分组成**：组织架构（公司有哪些部门、哪些人员使用）、模块（不同人员要用哪些模块、模块里有哪些字段）、权限（谁有某个对象的增删改查、是否只能查看）、流程（业务在系统里如何流转）。学员现在都以"本公司 CRM 管理员"的身份，把四块基础搭建起来。
- **本课范围与后台入口**：今天只讲"系统管理"里的基础设置，涵盖管理首页、企业设置、组织架构管理、角色权限设置、企业日志和集成平台管理。入口是登录账号后点左下角"管理后台"（2026 版界面里是左侧栏下方的小齿轮图标，需要管理员权限才看得见）；后续课程才会展开"CRM平台管理"（对象、流程等）。
- **系统管理六大模块的分工**：① 管理首页——账号与资源使用情况、到期时间；② 企业设置——企业信息、员工功能、工作时间、手机号隐私、域名、安全、品牌色、到期提醒等；③ 组织架构管理——部门与员工账号；④ 角色权限设置——员工系统权限与 CRM 角色；⑤ 企业日志——导入导出、CRM 操作、异常登录记录；⑥ 集成平台管理——与各类系统、数据源做集成。
- **企业信息设置与生效位置**：可设企业名称（全称与简称）、完整 logo 与简化 logo、系统语言（中文/英文/繁体）。生效位置有两处——登录页（logo + 企业名）和前台账号区；还可选择显示全称还是简称、要不要显示 logo，改完刷新前台即可看到。
- **员工功能设置六项**：修改汇报对象权限、修改职位信息权限、修改手机号和邮箱权限、邀请新同事权限、人员新建和导入提醒设置、信息发送范围设置。前几项都是"是否允许员工在前端自己改"，默认全部为禁止。
- **汇报对象与职位默认禁止修改**：汇报对象、主管部门、角色本应由组织架构管理员在新建员工时设好；一旦放开，员工可在"个人设置"里自改汇报对象，组织架构容易乱。职位同理——同一岗位被写成"销售运营""运营专员"等不同叫法，后续统计与管理都会乱，所以开箱默认禁止。
- **信息发送范围设置**：可指定禁止的员工与禁止的部门，使其在发布分享日志、审批任务、日程、公告时不能选择"全公司"范围，只能发给本部门或指定范围。
- **工作时间可按部门建多套**：新建工作时间要填名称、时区、工作日、起止时间、适用部门范围，例如销售一组 9:00—18:30、周一至周五；保存时若同一员工被多套规则覆盖，会提示"冲突的员工"，需要先处理旧规则。假期（如春节假期）在工作时间里新建，也会在"假期"菜单同步创建。
- **手机号隐私设置**：管理员在此设置员工手机号在同事中的可见范围，范围之外的同事看不到该员工手机号。可设新员工的默认值（默认为公开、所有同事可见），也可逐个勾选员工批量调整；员工个人还能在前端自设公开、私密、仅部门可见或部分可见（指定对哪些同事不可见）。
- **域名管理与自定义登录页**：域名可自定义前缀，后缀是纷享的域名、无法调整；企业若不希望显示纷享品牌，可在前缀上体现自己公司，并配合自定义登录页上传自己的 logo 与轮播图。
- **分支小组**：把跨部门的特定成员拉成一个小组，统一赋予管理某些组织架构的权限。新建时填小组名称、要管理的组织架构、小组成员与描述，再分别对"分支对象、分支流程、分支业务角色、分支线索池规则"选择全部授权或部分授权。
- **账号安全设置八项**：双因素认证、扫码登录、密码安全强度要求、密码过期时间、管理后台是否验证密码、多手机设备登录设置、授权登录访问设置、登出规则。纷享目前提供"账号密码＋验证码"的双因素，不提供图形验证码这类多因素认证。
- **代理登录与多设备限制**：开启"授权登录访问"后，管理员可对已激活登录过的员工账号执行"代理登录"，替员工排查问题（未登录过的假账号不会出现该按钮）；"多手机设备登录"可限制只允许一台手机在线，后登的设备会把前一台顶掉；登出规则可在 30 分钟到 24 小时之间设置无操作自动退出。
- **通讯录安全设置**：四个开关——隐藏通讯录菜单（前台直接看不到通讯录入口）、隐藏全公司、隐藏部门人员统计（部门树后不再显示人数）、允许导出手机通讯录（手机端可把部门同事电话导出到手机）。
- **设备绑定与单点登录**：开启设备绑定后，首次登录的手机或 PC 会与账号绑定，之后不能换设备，换设备需管理员解绑后重新绑定，也可为个别员工设白名单；单点登录用于与飞书等外部互联，在企信里打开飞书链接可免二次登录（换成微信打开则仍需登录）。此外员工更换设备登录时，需要该员工手机号收验证码授权，这个动作会记在"员工设备管理"里。
- **水印、品牌色与到期提醒**：水印可加在对象列表页、详情页、图片、附件预览、企业内与互联会话等位置（如姓名加工号）；品牌色默认"橘色＋黑色"，可自定义 WEB 主题色、移动端主题色，右侧有效果预览，支持立即使用和恢复默认；到期提醒可设提醒时间（如 09:00）、提前天数（如到期前 90 天）和接收人。
- **组织架构的搭建顺序与规则**：先建部门、再把员工放到部门下；员工支持模板批量导入（新建员工与修改员工是两套模板，须分别下载），也可手动新建。建部门有五个硬规则——**部门名称不允许重复**；创建后可按拖拽调整层级；编辑部门时"全公司"不计入层级，最多 **15 级**；**部门负责人只能设置一个人**，且负责人默认可看到所负责部门下员工的所有 CRM 数据；部门下还有"助理"与"工作观察者"两个角色（助理可看本部门员工全部 CRM 数据，工作观察者只看抄送范围在观察范围内的数据）。
- **员工账号的字段与查重要求**：系统名（昵称）在系统内展示、**不允许重复**；姓名**允许重复**；手机号、登录账号**不允许重复**。批量导入时，所有不允许重复的字段都会做查重。通过导入开通账号时，必须严格按模板示例格式录入，**不可自行修改表头**；员工首次登录需修改初始密码，且要符合公司设置的密码强度；账号开通后默认只能用工作模块，**要用 CRM 必须单独加 CRM 角色**。
- **禁止登录 vs 停用员工的区别（高频考点）**：**禁止登录**只是不让登录，账号**仍占用企业已购配额**，适合员工离职但考勤/审批还要导出时临时处理；**停用员工**则释放配额，但**已停用的员工无法删除**（要保留其历史发布的信息），重新启用时**需要重新设置权限**，且已停用员工**仍参与新建员工时的查重**。部门停用后可以删除，前提是该部门下没有发布过任何信息。
- **主属部门与附属部门**：**主属部门**是员工职能上直接归属的部门，**只能有一个**；**附属部门**用于员工工作范围同时涉及其他部门时，**可以设置多个**。例：张三既是销售中心负责人又是总裁办成员，则主属部门＝销售中心、附属部门＝总裁办。
- **员工激活与密码找回**：账号开通后员工一直没登录就是"未激活"，可在"部门与员工"勾选员工点"激活提醒"，系统会发短信提醒；员工忘记密码，除本人重置外，管理员也可在部门与员工界面直接重置。
- **多维度管理（区域线 / 行业线 / 产品线）**：启用后系统自动开启三套维度，在"组织架构管理-多维度管理"里维护层级（如华东/华北/华南/华中四个一级区域，华东下设上海地区）。可给员工指定负责的维度节点，其默认能看所负责维度及下级维度的全部业务数据；启用的业务对象会自动增加维度字段，但**不会自动在前台显示**，还需要管理员指定对象布局。多维度同样支持列表页筛选、条件共享规则与 BI 统计。
- **通讯录隔离**：分"基本设置 / 隔离的部门 / 隔离的用户组"三个页签。对某部门可设对部门外隐藏（上级部门负责人除外）或对部门内隐藏，再指定哪些同事可见，并限制其工作信息（动态、公告、任务、审批）只接收本部门的；用户组同样可设隔离。
- **角色权限两层结构与预置角色规则**：管理功能权限里系统预设了"**系统管理员**"（系统内最大权限，可操作后台任何设置，**建议只给最高管理者**；**不能移除自己的系统管理员角色**；**可设置多个、无上限**）和"**CRM 管理员**"（CRM 模块最大权限，可查看和编辑 CRM 全部数据，**可设置多个**），两者可叠加、不可修改；预置角色不够用时，可**复制已有角色的权限**来自建管理角色（例如专门管审批流的管理员）。只有 CRM 管理员，就看不到也管不了上面的系统管理。
- **企业日志七类**：审计日志（谁在什么时间对哪个模块做了什么操作）、登录日志（是否登录成功、用什么方式）、CRM 日志（具体到对象，如客户被编辑、锁定、解锁、回收）、导入导出记录、函数日志、函数监控（查看函数调用与报错次数）、流程日志（流程由谁、用什么方式执行、耗时多久）。
- **企业日志的六个典型排障场景**（课件给的对照表）：① 客户下某条数据不见了、想查被谁删除 → 企业日志-CRM日志-类别：对象-客户；② 联系人数据被导出、查是谁导的 → 导入导出日志-类别：对象-联系人；③ 同事 CRM 权限有问题、查是谁给的角色 → 审计日志-类别：管理-功能权限；④ 审批流程被改、查修改记录 → CRM日志-类别：管理-审批流程管理；⑤ 查某员工登录情况 → 登录日志；⑥ 查员工账号开通时间 → 审计日志。
- **集成平台与系统配置引导**：集成平台预设多款连接器——**金蝶云星空、SAP、用友 U8、Database、通用连接器、OA 连接器**等，企业按需开通；只要对端系统提供可访问的接口，都能通过连接器对接。系统配置引导把前面讲的基础配置列成清单，不知道先做什么时可以逐项点开，直接跳到对应配置页面。

## 结构与流程

系统管理完整菜单（截图为真实层级）：

```
管理后台（登录后左下角进入）
├─ 系统管理 ← 本课全部内容（基础配置，仅系统管理员可见）
│ ├─ 管理首页 总员工数 / CRM用户数 · 订阅账号 · 资源配额 · 互联配额 · 快捷入口 · 通知
│ ├─ 企业设置
│ │ ├─ 企业信息设置 企业名称（全称/简称）· 完整logo / 简化logo · 系统语言
│ │ ├─ 员工功能设置 修改汇报对象 · 修改职位信息 · 修改手机号和邮箱 · 邀请新同事
│ │ │ 人员新建和导入提醒 · 信息发送范围（禁止选「全公司」）
│ │ ├─ 工作时间 时区 · 工作日 · 起止时间 · 适用部门（可按部门建多套）
│ │ ├─ 假期 如春节假期（起止日期），供工作时间引用
│ │ ├─ 手机号隐私设置 新员工默认可见范围 + 员工逐个/批量调整
│ │ ├─ 域名管理 自定义域名前缀（后缀固定）
│ │ ├─ 企业安全设置
│ │ │ ├─ 分支小组 小组名称 · 管理组织架构 · 小组成员 → 分支对象/流程/业务角色/线索池规则
│ │ │ ├─ 账号安全设置 双因素认证 · 扫码登录 · 密码强度 · 密码过期 · 后台验证密码
│ │ │ │ 多手机设备登录 · 授权登录访问 · 登出规则
│ │ │ ├─ 通讯录安全设置 隐藏通讯录菜单 · 隐藏全公司 · 隐藏部门人员统计 · 允许导出通讯录
│ │ │ ├─ 设备绑定 首次登录设备与账号绑定；白名单
│ │ │ ├─ 单点登录 与飞书等互联免登录
│ │ │ ├─ 水印设置 列表页/详情页/图片/附件预览/会话
│ │ │ ├─ 代码安全设置 正式环境禁止改代码，只能测试环境改后上线
│ │ │ └─ 认证供应商 OpenID Connect 等方式接入外部认证
│ │ ├─ 自定义登录页 登录页 logo 与轮播图
│ │ ├─ 品牌色 主题色（WEB / 移动端）+ 效果预览 + 立即使用
│ │ ├─ 到期提醒设置 是否开启 · 提醒时间 · 提前天数 · 接收人
│ │ └─ 全局设置
│ ├─ 组织架构管理
│ │ ├─ 部门员工 部门树（新增子部门/编辑部门/负责人/助理）+ 员工（导入/新建）
│ │ │ 规则：名称不可重复 · 最多 15 级 · 全公司不算一级 · 负责人只能 1 人
│ │ ├─ 多维度管理 区域线 / 行业线 / 产品线，可授权员工负责维度节点
│ │ ├─ 通讯录隔离 基本设置 / 隔离的部门 / 隔离的用户组
│ │ └─ 员工设备管理 登录设备、首次激活时间；换设备需验证码授权
│ ├─ 角色权限管理
│ │ ├─ 管理功能权限 系统管理员 · CRM管理员（预设不可改、可多个）→ 可复制自建
│ │ ├─ 业务功能权限 按对象（客户、商机、市场活动…）分配
│ │ └─ 用户组 跨部门同权限打包，也可单独做通讯录隔离
│ ├─ 企业日志 审计 · 登录 · CRM · 导入导出 · 函数 · 函数监控 · 流程
│ ├─ 集成平台管理 金蝶云星空 / SAP / 用友U8 / Database / 通用 / OA 连接器
│ └─ 系统配置引导 按步骤列出待配项，点击直达配置页
└─ CRM平台管理 ← 本课不展开
 └─ 对象管理 · 流程管理 · 数据权限管理 · 业务规则管理 · 业务组件管理 · 界面定制管理 · 定制开发平台 · 数据维护工具 · 环境
```

有强依赖的配置顺序（讲师明确的部分）：

```
① 企业信息设置 名称 / logo / 语言 → 登录页与前台账号区立即生效
② 组织架构：部门 先建/批量导入部门，设置部门负责人与助理
③ 组织架构：员工 在对应部门下导入或新建员工（新建与修改是两套模板）
④ 角色权限 管理功能权限（决定谁能进哪个后台）
  → 业务功能权限（对象）→ 员工才有 CRM 前端权限
⑤ 其余企业设置 员工功能 / 工作时间与假期 / 手机号隐私 / 域名 / 企业安全 / 登录页 / 品牌色（按需，无强依赖）
⑥ 企业日志 配置与日常操作都可回溯核对
```

## 需要注意的点

1. **总员工数 ≠ CRM 用户数**：把员工导入系统只是建了账号，不等于他能用 CRM。必须到"角色权限管理"给员工分配角色权限，他才会出现在 CRM 前端；课上示例是 20 个员工、17 个 CRM 用户，差额就是这么来的。
2. **停用员工 ≠ 禁止登录**：很多人把两者混着用。**禁止登录**只是不让登录，配额照占；**停用**才释放配额。而且停用后**不能删除**（要保留历史信息），重新启用还要**重设权限**，停用的人**仍参与查重**，否则同名账号会被放进来。
3. **部门有五个硬规则，配错很难回退**：名称不可重复；最多 **15 级**；"全公司"不算一级部门；**负责人只能 1 人**；负责人默认可看该部门下员工全部 CRM 数据——所以任命负责人等于给了数据权限。
4. **三项"修改权限"开箱默认禁止，不是配置漏了**：汇报对象、职位信息、手机号和邮箱默认都不允许员工自改。要让组织架构、职位口径统一，就别随手打开；只有像员工换手机号、希望通讯录里能直接拨号这类场景，才考虑放开手机号和邮箱。
5. **员工导入必须用原模板**：新建员工与修改员工是两套模板；导入时**不能改表头**，且系统名、手机号、登录账号会查重，姓名允许重复——这些字段搞错会整批导入失败。
6. **"邀请新同事"功能即将下线**：部分账号里已经看不到这个菜单，属于正常现象，不用去找、也不用给客户讲。
7. **工作时间保存会提示"冲突的员工"**：同一个员工被两套工作时间同时覆盖时会出现提示，说明之前已经给他套过别的规则。先把旧规则停用或调整适用范围，再保存新规则，否则生效范围会互相打架。
8. **后台权限是两层，别混淆**：系统管理员管"系统管理"（本课内容），CRM 管理员管"CRM 平台管理"（对象、流程等）。只给某人 CRM 管理员，他看不到上面的系统管理，这不是权限没生效；两个角色可以叠加。另外系统管理员**不能移除自己**，避免把自己锁在门外。
9. **多维度字段不会自动出现在前台**：启用多维度后对象确实多了维度字段，但必须去对象布局里把它放出来，前端才看得到，否则"配了却看不见"。
10. **口播与界面叫法要对齐**：讲师口播说"通讯数据隔离"，界面实为"通讯录隔离"，下面分"基本设置 / 隔离的部门 / 隔离的用户组"三个页签；口播说"分管小组"，界面是"分支小组"。给客户讲或写文档时以界面名称为准。
11. **查问题先想日志在哪一类**：数据"消失"多半是 CRM 日志，导出泄露看导入导出日志，权限被改看审计日志，流程被改看 CRM 日志的流程管理类别，登录异常看登录日志——按这五类先定位，再谈排查。
