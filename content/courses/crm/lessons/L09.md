# 速览（30 秒看完）

- 权限只有两条线：**管理功能权限**和**业务功能权限**，入口都在「管理后台 → 角色权限管理」。
- 管理功能权限管「能不能进后台、进哪个模块」；有它才进得了后台，不同管理员看到的后台内容不一样。
- 系统管理员权限最大，也是**唯一能给别人分配其他管理角色**的角色；常见管理角色还有组织架构管理员、CRM 管理员、对象管理员、互联管理员、开发人员、AI 管理员、应用中心管理员。
- 工作观察者：把 A 设为 B 部门的观察者，B 部门成为被观察部门，抄送给它的工作信息会自动抄送给 A。
- 不是所有管理都在后台：考勤、外勤、网盘、企信、工作圈的管理都在各自应用里。
- 业务功能权限围绕 CRM 所有对象按角色配操作，可叠多个角色，主角色决定界面布局；落到对象上就是一排按钮——查看列表/详情、新建、编辑、作废、导入导出等，不勾就不显示。
- 数据范围由「查看全部 / 编辑全部」控制：默认只能看自己创建的，部门领导能看本部门，勾了全部才能看全公司。
- 字段权限有读取、编辑、导出、显示四种，可以实现"能看不能改"。

## 核心要点

- **本课要解决的两个问题**：一是搞清楚系统里各类权限分别是什么效果，二是学会怎么给员工分配权限。权限配置集中在「管理后台 → 系统管理 → 角色权限管理」，分为管理功能权限和业务功能权限两条线。
- **管理功能权限的定位**：具备"管理"性质的权限，权限范围比较大，侧重于系统层面的管控。只要拥有管理功能权限，就能进入后台；而每个员工的管理权限范围不一样，所以进后台后看到的内容也不同。
- **系统管理员**：拥有整个系统最大的管理权限，关键特性是**只有系统管理员才能给其他员工分配任何管理角色**（如组织架构管理员、CRM 管理员），其他管理员都做不到。实际使用中一般交给专门管理系统的同事或高层领导。
- **组织架构管理员**：主要负责管理组织架构，可以添加员工、编辑员工信息、新建部门、做部门管理，还能做通讯组隔离。因为它直接管人和部门，通常分配给 HR 部门，或把权限留给高层领导。
- **CRM 管理员**：管理整个 CRM 模块，拥有 CRM 平台、CRM 应用当中所有数据的权限，权限非常大，所以要分配给比较少的员工。
- **各模块管理员与应用中心管理员**：互联管理员看到互联模块，开发人员看到定制开发平台模块，AI 管理员看到 AI 模块，服务通管理员对应服务通应用（需购买服务通才可见），线上客服管理员对应线上客服，都是"管哪个模块就给哪个管理员"。应用中心管理员则能看到整个应用列表，可对 CRM 应用视图、产品台做编辑配置（后续课程会专门介绍）。
- **工作观察者**：比较特殊的管理角色。把 A 设为 B 部门的工作观察者后，B 部门就成为"观察部门"，凡是抄送给 B 部门的工作信息，都会自动抄送给 A，A 都能看得到。
- **入口本身也受权限控制**：「管理功能权限」这个菜单只有系统管理员能看到，其他管理员看不到这个模块。实操中系统管理员在此按角色添加员工，如把小王、小罗加到组织架构管理员，两人就能看到系统管理下的企业设置、国际化、集成平台等。
- **对象管理员（口播听作"项目管理员"）**：管理 CRM 平台下的对象管理模块，可以创建对象、管理对象、增加字段、配置校验模板、配置工作流/审批流/业务流以及权限管理，只有添加了这个角色才能看到这部分配置。
- **工作台（工作圈）管理员与日志模板**：添加后会出现"工作圈管理"模块；添加或移除角色后往往要刷新（甚至重新登录）才真正看到该模块。在工作圈管理里可做可见范围控制、公司圈管理，并可设置圈管理员（日志管理员、公告管理员、话题管理员）；日志模板还能限定哪些部门使用、预设固定点评人（一般设为部门领导）、抄送范围、提交起止时间与是否支持补交。
- **审批的两种形态**：现在审批已经对象化，在工作圈提交请假等审批后会在 CRM 模块生成对应数据，可在 CRM 里搜索对象、查询导出；开通较早的老企业审批尚未对象化，仍需在工作圈审批里增加字段、配置审批流程，数据在"审批查询统计"里查看导出。
- **工作圈数据的彻底删除**：用"信息删除工具"处理。把鼠标放到目标数据上弹出新窗口打开，拿到数据 ID 后复制，粘贴到工具里点"彻底删除"，这条数据才会真正消失。
- **不是所有管理都在后台**：企信、考勤、外勤、网盘等应用的管理都在应用自己内部完成。企信开通后所有员工都能看到，企信管理员会多出"企信管理"，可做企信定制，例如部门群会把通讯录里该部门的人员自动建成群、便于信息流转；考勤管理员能配考勤规则、导入考勤数据；外勤有自己的外勤规则；网盘管理员才能管理公司文件，普通员工只能上传自己的个人文件。被移除管理员后再进入，会直接提示"没有权限查看内容"。
- **业务功能权限的定位**：围绕 CRM 的所有对象（客户、联系人、商机、销售订单等）逐项给操作权限——能不能看、能不能新建、能不能改、能不能导出分别勾。它和管理功能权限是并列的两条线：一条决定进不进得了后台、进哪个模块，一条决定对数据能动到什么程度。
- **预设角色与"所有员工"**：业务功能权限里预置了所有员工、CRM 管理员、CRM 观察者、目标管理员（对企业所有目标规则和目标值有完整查看与操作权），以及报表管理员/报表设计者/报表查看者（详见报表模块课程）。其中"所有员工"是所有 CRM 人员都有的角色，若员工只被给了市场管理者角色却能看到某个对象，很可能就是它在起作用，排查权限时必须先看它。
- **两个「CRM 管理员」分属两条线**：管理功能权限里的 CRM 管理员，管的是 CRM 模块、拥有全部数据权限、能进 CRM 平台管理；业务功能权限的预设角色里也有一个 CRM 管理员，管的是对 CRM 所有对象可做任何操作、默认拿到 CRM 模块最大业务权限。同一个名字，配之前先说清要的是后台管理那一个还是对象操作那一个。
- **角色叠加与主角色**：每个角色都同时带管理功能权限和业务功能权限；市场管理者能看客户、市场人员能看市场活动，一个人挂两个角色就能同时看客户和市场活动。分配角色有两条路径：组织架构里编辑人员添加，或在角色下用"员工分配 → 添加员工"；多角色时由"主角色"决定查看对象时的详情页布局、新建与编辑布局。
- **业务类型按角色分配**：同一个对象里的数据可以用业务类型分类（工单分客户投诉、客户咨询，各自要填的字段不一样），谁能用哪个类型由角色决定——售后服务人员分「客户投诉」、售前人员分「客户咨询」，他新建时看到的表单就跟着变。三条硬规则：一个业务类型只能对应一个布局，一个布局可以同时分配给多个业务类型，一个角色可以使用多个业务类型和多个布局。
- **对象权限就是一排按钮**：查看列表、查看详情、新建、复制、编辑、作废、恢复、导入、导出、更换负责人、添加/删除团队成员、发起业务流程、查看业务流程、终止业务流程、打印、合并等。不给某项权限，对应按钮就不显示（例如没有查看详情权限，点进去会提示无权限）。数据范围则由"查看全部／编辑全部"控制：默认只能看到自己创建的数据，部门领导还能看到本部门员工的数据——小王创建 3 条、小罗创建 10 条，普通员工看不到小罗的数据，勾上查看全部才能看到整个系统的客户数据。
- **从对象的权限跟着主对象**：主从关系里（订单—订单产品），从对象的数据权限受主对象权限控制，也就是从对象的权限遵循主对象；这条明细能不能看，实际由主对象那条数据的权限决定，不用也不能给从对象单独配一套。
- **字段权限**：对单个字段控制读取、编辑、导出、显示。典型场景是把某些字段对员工隐藏（不给读取就看不到），或"能看不能改"——放开读取、取消编辑，很多企业都在用。
- **对象和字段的配置权只在 CRM 管理员手里**：在「管理后台 → 对象管理 → 预设对象/自定义对象 → 添加字段」建字段、禁用字段，以及改字段在页面上的位置和顺序（在对象布局里拖），都是 CRM 管理员才有的后台权限，普通员工没有这个入口。删字段要先点「禁用」再点「删除」，删掉后平台内该字段下的值会一并清除且不可恢复。
- **编辑审批部门（特殊配置）**：回款作废、查看部门销售订单、编辑销售订单这三类操作，除需要订单管理员/订单财务/回款财务等角色外，还要求配置了"编辑审批部门"，只能操作归属该部门的数据；若在 CRM 配置里打开对应开关，则改走通用业务功能权限，只要有编辑权限即可。
- **自定义角色**：在业务功能权限里可新建角色，填角色名称、描述，选择功能许可，也可复制已有角色的权限。新建自定义对象（如市场活动）时，预设角色里没有它的权限，必须自己建角色并勾选，员工才能正常使用。

## 结构与流程

权限体系构成（管理后台 → 角色权限管理）：

```
角色权限管理
├── 管理功能权限（系统层面，进后台、管模块）
│ ├── 系统管理员 最大权限，唯一可分配其他管理角色
│ ├── 组织架构管理员 管人、部门、通讯组隔离
│ ├── CRM 管理员 CRM 平台全部数据与对象
│ ├── 对象管理员 对象管理：建对象、加字段、校验模板、工作流/审批流/业务流
│ ├── 互联管理员 / 开发人员 / AI 管理员 / 集成管理员 / 服务号管理员
│ ├── 应用中心管理员 应用列表、CRM 应用视图配置
│ ├── 服务通管理员 / 线上客服管理员（需购买对应应用）
│ └── 工作观察者 观察部门 → 抄送信息自动转给观察者
│
└── 业务功能权限（按角色配，控制数据操作）
 ├── 角色 = 管理功能权限 + 业务功能权限（可多角色叠加，主角色定布局）
 ├── 对象权限（即操作权限，按钮级）
 │ ├── 查看类：查看列表、查看详情、查看全部
 │ ├── 新建与修改：新建、复制、编辑、编辑全部、作废、恢复
 │ ├── 数据流转：导入、导出、更换负责人、添加/删除团队成员
 │ ├── 流程类：发起业务流程、查看业务流程、终止业务流程
 │ └── 其他：打印、合并、审批流操作、锁库等
 ├── 字段权限（字段级）：读取 / 编辑 / 导出 / 显示
 └── 数据范围：本人 → 本部门（部门领导）→ 全部（勾"查看全部/编辑全部"）

应用内管理（不在后台，各应用自己管）
├── 考勤：考勤规则、考勤数据导入
├── 外勤：外勤规则
├── 网盘：公司文件（仅网盘管理员）
├── 企信：企信管理、部门群、群内推送
└── 工作圈：工作圈管理、圈管理员、日志模板、审批、信息删除工具
```

授权流程：

```
1. 管理后台 → 系统管理 → 角色权限管理
2. 选线：管理功能权限（管后台模块）／业务功能权限（管数据操作）
3. 建角色：选预设角色，或「新建角色」并复制已有角色权限
4. 配权限：勾对象权限按钮 → 设查看/编辑范围 → 配字段权限（读取/编辑/导出/显示）
5. 配人：角色页「员工分配 → 添加员工」，或组织架构→编辑人员→添加角色
6. 定主角色：决定详情页与新建/编辑使用哪套布局
7. 验证：换一个账号（或用被授权员工账号）登录，看模块与按钮是否符合预期
```

## 需要注意的点

1. **两条线别混着讲**：管理功能权限决定"能不能进后台、能进哪个模块"，业务功能权限决定"能对业务对象做哪些操作"。一个新员工的完整权限 = 两类权限的叠加。
2. **"所有员工"是最常见的权限异常来源**：排查"他为什么能看到这个对象"时，先看这个人人人都有的角色，再看具体业务角色，否则很容易误判。
3. **角色权限 ≠ 数据权限**：角色权限管的是按钮和字段能不能用，能看到"哪些人、哪些部门、全部"的数据则由查看/编辑范围决定；后台左侧还有独立的「数据权限管理」入口（截图可见），本课未展开，不要混为一谈。
4. **加/减角色后要刷新或重新登录**：讲师添加工作圈管理员、移除考勤管理员后，都是刷新后才看到模块出现或提示无权限，别以为配置没生效。
5. **新建自定义对象后必须补权限**：预设角色里没有新对象的权限项，任何人都看不到、点不动，需要新建或编辑角色把对应权限勾上。
6. **给了权限也可能用不了**：一是按钮还要在布局/按钮设置里放出来（反过来说，把作废、导出从布局移除，员工同样看不到）；二是订单与回款属特殊对象，作废回款、查看或编辑销售订单走的是"角色 + 编辑审批部门"组合，不能只靠业务功能权限的编辑勾选。
7. **别把两个「CRM 管理员」当成一个**：管理功能权限下那个写的是"管理 CRM 模块、拥有所有数据的所有权限"，业务功能权限预设角色里那个写的是"可以对 CRM 所有对象进行任何操作"。给客户配权限、排查问题时先确认说的是哪一个，别在同一个词上各说各话。
8. **明细数据看不到，先查主对象权限**：主从关系下从对象的权限遵循主对象，订单产品能看多少由订单那条数据的权限决定。排查"订单产品列表是空的"，先看这个人对订单的查看范围，再去怀疑从对象本身。
9. **对象和字段只有 CRM 管理员能配，删字段不可恢复**：加字段、禁用字段、改布局顺序这些后台动作普通员工完全看不到入口；字段必须先禁用再删除，删掉后该字段在平台内的值一起消失，没有回收站。这也是 CRM 管理员权限不能大面积发放的原因。
