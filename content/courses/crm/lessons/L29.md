# 速览（30 秒看完）

- 本课是课时26的配套练习，用课件第34页的5道题过一遍；5道题都落在"业务功能权限＋数据权限"两层，管理功能权限只管能不能进后台，回答不了"能操作什么、能看多少"。
- 题1：线索、客户、商机、销售订单四个对象勾新建/编辑/查看列表/查看详情/导入，导出一律不勾。
- 题2：只勾需要的查看项，更换负责人、编辑相关团队成员、作废、导入、导出，以及对象上的状态操作（如"结束"）都不勾，就是禁止。
- 题3：产品的基础数据权限做不到"只放一部分"，要用数据共享的"基于条件"，条件是"上下架＝已上架"，共享给全公司。
- 题4：非管理员看全公司客户有两条路——数据共享给这个人（可给编辑权），或在角色里勾"查看全部"并确认风险提示。
- 题5：客户/商机/销售订单只给查看列表＋查看详情，再把"手机号"字段的"读取"取消，取消读取等于看不见也改不了。
- 三个最容易混的点：取消"显示"≠取消"读取"；共享来源默认含子部门、共享目标默认不含；主属性字段取消不了"读取"。
- 上线前用没有管理员身份的角色账号实测；查某位同事对某条数据到底是什么权限，用管理后台-数据维护工具-数据权限查询工具。

## 核心要点

- **课程定位**：承接课时26的功能讲解，用课件第34页的5道配置题过一遍：销售人员角色、自定义对象测试角色、已上架产品可见、非管理员看全公司客户、客户成功经理角色。
- **先分清两层权限**：管理功能权限（管理后台-角色权限管理-管理功能权限）决定员工能进哪个后台、能做哪些管理操作；业务功能权限（管理后台-角色权限管理-业务功能权限）决定他能对哪些对象做查看、编辑、导入、导出这些操作。5道题配的都是后者，加上字段权限和数据权限。
- **题1：新建销售人员角色**：线索、客户、商机、销售订单四个对象都要新建、编辑、导入，不允许导出。角色权限设置页左边是系统预置的CRM角色，右边是这个角色对这些对象的功能权限和字段级权限，逐个对象勾到"查看列表/查看详情/新建/编辑/导入"，导出不勾。
- **题1的导出要按角色逐个取消**：想全公司都不能导出客户，是把每个角色针对客户对象的导出权限都取消，只改一个角色不够。
- **员工没角色就看不到CRM模块**：要用人得先去"员工角色分配"把他加到"销售人员"这类角色下，不加角色前端根本没有CRM入口。一个人可以同时有多个角色，角色权限是叠加的；自定义角色可以复制其他角色的权限作为起点。
- **删除权限不在角色里**：销售角色能配的是新建、编辑、查看、导入、导出这类操作，删除只能由CRM管理员在管理后台的回收站里做，所以"能不能删除线索"这种题要选"不能"。
- **题2：自定义对象的测试角色**：课件题干是"只允许此角色看到自定义对象，不允许该角色更换负责人、编辑相关团队成员、作废、导入、导出、解锁"。先去对象管理确认自定义对象有哪些分组项、哪些操作项，再进业务功能权限里对这个对象逐项配。
- **题2的做法**：只勾需要的那几个查看权限，多余的分组项不授权；把不需要的操作项都不勾——更换负责人、编辑相关团队成员、作废、导入、导出，以及该对象上的状态类操作（如"结束"）。有多个自定义对象时，每个对象都要单独配一遍。
- **题3：只让全员看已上架产品**：产品的基础数据权限是"公开只读/公开读写"这种粒度，一放就是全部产品，做不到只放已上架的。正确做法是用数据共享，把符合条件的那部分产品共享出去。
- **数据共享的四种取数范围**：基于数据负责人（按负责人、负责人主属部门、用户组或CRM角色定范围）、基于数据归属组织、基于数据归属部门、基于条件（按对象里符合某些条件的数据共享）。题3用"基于条件"。
- **题3具体配置**：管理后台-数据权限管理-数据共享-新建，对象选产品，范围选"基于条件"，条件写"上下架＝已上架"，共享到全公司（全部门），保存。共享出去时可以给查看权限，也可以给编辑权限。
- **共享来源和目标对子部门的默认处理不一样**："数据来源于"选的部门默认包含下级子部门（选销售中心，下面的子部门也算在内）；"数据共享到"选的部门默认不含子部门，要让子部门也能看，得把子部门单独加上。
- **主属部门和归属部门不是一回事**：新建数据时归属部门跟随主属部门；员工调岗后主属部门自动变成新部门，归属部门仍停在创建时的那个部门。这是为了业绩核算准确——按归属部门共享订单，提成口径不会跟着人跑。
- **题4：非管理员看全公司客户（方式一）**：用数据共享把全部客户共享给这位员工，并给查看＋编辑权限。
- **题4：方式二是在角色里勾"查看全部"**：新建或编辑角色，进客户对象的权限设置勾"查看全部"，系统弹出风险提示——"查看全部将赋予角色对当前对象所有数据的查看权限，在决定授权之前，请仔细评估必要性和潜在的风险"，确认后该角色看客户就不受数据权限限制了。
- **不勾"查看全部"时默认只能看自己那份**：基础数据权限遵循负责人逻辑，私有数据只有数据负责人本人、汇报对象、部门负责人、相关团队成员和CRM管理员能看见。这就是非管理员默认看不到别人客户的原因，属于正常现象。
- **题5：客户成功经理角色**：新建角色后，客户对象只勾"查看列表""查看详情"，不勾新建、编辑、作废这类操作。
- **题5隐藏手机号必须动字段权限**：客户对象的字段权限里有四个开关——读取（既能看见也能编辑）、编辑、导出、显示（该字段是否出现在列表页的"筛选项"和"字段设置项"里）。要让人看不见手机号，是取消"读取"，不是取消"显示"；取消"显示"只是让他筛选和设置字段时找不到这个字段，详情页照样看得见。
- **主属性字段取消不了"读取"**：客户名称这类主属性字段不支持取消读取权限，想隐藏字段前先确认它不是主属性字段。
- **题5商机和销售订单同步配**：商机、销售订单同样只给查看列表和查看详情，不给编辑。
- **另外五类数据权限各自解决什么**：部门内数据权限（同部门销售联合跟进，要互看彼此名下客户）、相关团队数据权限（按普通成员/联合跟进人/售后人员三种预置角色，分别设其能看哪些关联对象）、临时权限（只对"待处理的审批流、待处理的业务流程"短期开放）、基础数据权限（全公司默认范围）、"其他"里的脱敏（对线索、客户、商机2.0、拜访、产品没有查看权限的人，在工作界面看到的关键信息显示为星号）。
- **选错权限类型是高频失分点**：课件三道常见问题——销售一部负责人能看到销售二部全部订单，问题出在数据共享设置，不是相关团队；回款财务在待办里点开数据提示没有权限，最佳做法是配数据共享；业务流程处理人每次都要加联合跟进太麻烦，用临时权限。
- **收尾：验证和反查**：配完用非管理员账号、切到对应角色实测一遍。想知道某位同事对某条数据到底是什么权限，用管理后台-数据维护工具-数据权限查询工具，输入对应信息直接查。

## 术语表

| 术语 | 含义 |
| --- | --- |
| 查看全部 | 角色级权限，勾选后该角色可看到当前对象的所有数据（不受数据权限限制），系统会弹出风险提示 |
| 数据共享条件 | 数据共享的筛选条件，可按对象任意字段精确筛选需共享的数据范围 |
| 设计角色 | 系统预设的可用于自定义对象权限配置的角色，权限需管理员手动配置 |
| 分组项 | 自定义对象下的子分组/子项，权限可按分组项精细控制 |
| 角色复制 | 新建角色时勾选"复制"选项，一键复制已有角色的全部权限作为起始点 |
| 管理功能权限 | 决定员工能进哪个后台、能做哪些管理操作（系统设置、组织架构、角色分配），位置在管理后台-角色权限管理 |
| 业务功能权限 | 决定员工能对哪些对象做哪些操作（查看列表/详情、新建、编辑、导入、导出），位置在管理后台-角色权限管理 |
| 预置管理角色 | 系统默认给的管理角色，权限固定、不能改 |
| 自定义管理角色 | 企业自己建的管理角色，权限自己配，如课件里的"测试管理角色" |
| 员工角色分配 | 把员工加到某个CRM角色下的入口，不加角色员工看不到CRM模块 |
| 字段权限 | 针对一个对象下每个字段分别设置读取、编辑、导出、显示四个开关 |
| 读取 | 字段权限之一：既能看见也能编辑；取消读取＝看不见也改不了 |
| 显示 | 字段权限之一：控制字段是否出现在列表页的"筛选项"和"字段设置项"中，不影响详情页可见 |
| 主属性字段 | 对象的主名称字段（如客户名称），不支持取消"读取"权限 |
| 基础数据权限 | 针对全公司CRM模块设置的默认数据范围，遵循负责人逻辑 |
| 负责人逻辑 | 私有数据默认只有数据负责人本人、汇报对象、部门负责人、相关团队成员、CRM管理员能看 |
| 部门内数据权限 | 让同一部门（含上下级）的销售互相看到彼此名下的数据 |
| 数据共享 | 把某个范围的数据共享给指定部门或人员，并给查看或编辑权限 |
| 数据来源于 | 数据共享里选数据所属范围的那一侧，选的部门默认包含下级子部门 |
| 数据共享到 | 数据共享里选共享给谁的那一侧，选的部门默认不含子部门 |
| 基于条件共享 | 数据共享的一种取数方式，按对象中符合某个条件的数据共享，如"上下架＝已上架" |
| 基于数据归属组织 | 按数据的归属组织共享，需要开通多组织才能使用 |
| 主属部门 | 数据负责人当前所在部门，员工调岗后自动跟着变 |
| 归属部门 | 数据创建时记下的部门，员工调岗后不变，用于业绩核算 |
| 相关团队 | 数据上挂的一批协作人，预置普通成员、联合跟进人、售后人员三种角色 |
| 相关团队数据权限 | 按相关团队角色分别设置其能看到哪些关联对象的数据 |
| 临时权限 | 只对"待处理的审批流、待处理的业务流程"开放的短期查看权限 |
| 脱敏显示 | "其他"里的开关：对线索、客户、商机2.0、拜访、产品没有查看权限的人，看到的关键信息显示为星号 |
| 数据权限查询工具 | 管理后台-数据维护工具下，输入信息就能查某位同事对某条数据的具体权限 |

## 需要注意的点

1. **"查看全部"要先评估再勾**：勾选时系统明确弹出风险提示，一旦勾上这个角色看该对象就不受数据权限限制，等于把全公司数据都放开了。按岗位临时授权可以，别图省事往通用角色上勾。
2. **取消"读取"和取消"显示"是两件事**：想让某人看不见手机号，必须取消"读取"；取消"显示"只是这个字段不再出现在列表页的筛选项和字段设置项里，详情页还是照常可见。题5做错基本都错在这里。
3. **主属性字段的"读取"取消不了**：客户名称这一类主属性字段不支持取消读取权限。挑字段做隐藏时先看它是不是主属性字段，否则在权限页上根本取消不掉。
4. **共享来源含子部门、共享目标不含子部门**：给销售中心共享数据时，来源侧默认把销售中心下的子部门也算进来；共享到某一侧要选部门时，默认只给到这个部门本身，子部门要另外加，否则会出现"上级能看、下级看不见"。
5. **基于数据归属组织的数据共享要开通多组织**：没开多组织的账号里这个选项用不了，别在客户现场反复试。
6. **"公开读写"不等于数据共享**：基础数据权限设成公开读写，是全公司都能看、都能改，收不回来；数据共享能挑范围（如只看已上架产品）、能指定共享给谁、能只给查看不给编辑，管控精度差一个量级。
7. **删除权限只能在后台回收站做**：销售人员角色里没有"删除数据"这个操作项，删除由CRM管理员在管理后台回收站执行，题干问"销售能否删除线索"要按不能来答。
8. **自定义对象的操作项跟标准对象不完全一样**：题2题干写"解锁"，演示时点的是"结束"这类状态操作，不同对象的操作项叫法不同。配置前先把该对象权限页里的操作项列表看全，不要只照着题干去对名字。
9. **一道题往往要两层权限一起配**：题5同时动了对象级操作权限（只给查看）和字段级权限（手机号取消读取）。只取消编辑、不动字段，手机号照样露出来，属于只做了一半。
10. **非管理员看不到别人的数据是默认设计**：基础数据权限按负责人逻辑走，只有负责人本人、汇报对象、部门负责人、相关团队成员和CRM管理员能看。学员发现"我只能看自己的客户"时，不是权限坏了。
11. **选权限类型别拍脑袋**：跨部门看数据用数据共享（如销售一部负责人看到二部全部订单，就是数据共享配多了）；审批待办里点开提示没权限，优先配数据共享；业务流程处理人只是临时处理一条数据，用临时权限，不要为了一个人开一大片共享。
12. **上线前一定要用角色账号实测**：拿没有管理员身份、只挂了目标角色的账号登进去看列表、详情、字段，逐项对一遍。查不清某人对某条数据的具体权限时，用管理后台-数据维护工具-数据权限查询工具直接查。
