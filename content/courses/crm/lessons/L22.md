# 速览（30 秒看完）

- 本节是审批流作业讲解的第一段：讲师在测试环境里，把作业要求的对象和审批流一步步配出来，边配边讲为什么这样做。
- 作业要先建**四个自定义对象**：实施申请、交付申请、投标申请、项目——对象没建好，后面的审批流无从谈起。
- 配置顺序固定：建对象与字段 → 配审批流（发起对象 + 触发时机 + 节点 + 处理人 + 后动作）→ 用普通账号提交一次走通。
- 审批流的零件都在 L21 功能课里：节点类型、处理人维度、后动作，本节只是把它们组合成题目要求。
- 判断自己有没有配对，最直接的办法是拿一个非管理员账号跑一遍，看审批路线是不是你画的那条。

## 核心要点

- **先建对象再配流程**：作业用到的对象是实施申请、交付申请、投标申请、项目（见截图"自定义对象管理"列表）。对象在**管理后台 → 对象管理 → 自定义对象**里新建，建完后加字段、配布局，才轮到流程。
- **对象名的两个字段要分清**：名称是展示名，后续可改；**API Name 建于对象创建时、建完不能改**。作业里给自己留余地，API Name 想清楚再写（如 `project__c`）。
- **对象可选项按需勾**：新建对象时的可选功能包括相关团队、全局搜索、动态、修改记录、多字段排序。作业里如果要求"能看修改历史"就要勾修改记录，要求"能按团队共享"就要勾相关团队。
- **主属性字段**：新建对象时必须给一个主属性字段（默认 `name`），它是这个对象"叫什么"的字段，用于查重、列表展示与查找关联的显示值。
- **审批流的三要素**：发起对象（这张单子是什么）、触发时机（新建/编辑/作废/变更负责人/阶段变更/其他按钮）、节点（谁来批、按什么分支走）。三者缺一，流程就跑不起来。
- **触发时机选错是常见错误**：作业要求"提交后审批"就选新建；要求"改金额再批一次"就选编辑，并加上字段变更条件。
- **节点类型的选择**：单线审批用普通审批；"金额小于 1 万走 A、大于等于 1 万走 B"用多分支；需要几个人同时处理用任务协作；"两条线都走完再汇合"用并行网关。
- **处理人的九种维度**：发起人、发起人主属部门负责人、指定角色、指定人员、指定部门负责人、表单上的字段（如"项目总监"）、流程相关变量、数据相关变量、人员对象变量。作业里"给项目总监审"就用字段取值或角色。
- **逐级审批怎么写**：选"本级部门"表示从发起人所在部门开始逐级往上；固定级数选 2 表示本级加上一级；固定级别选"1 级部门负责人"表示不管谁提交都批到第一级。注意：逐级审批节点里**不支持加签**。
- **后动作的位置决定时机**：写在节点上方的后动作，在节点完成时执行；左下方"执行操作"里的动作，要整条流程结束后才执行。作业要求"审批通过后改状态"，就放在节点后动作里。
- **验证方式**：用非管理员账号提交一次，看审批人收到的待办、审批通过后的字段变化；再故意走一次驳回，确认驳回后的分支也对。
- **权限别漏配**：新建的自定义对象要进"角色权限管理-业务功能权限"给对应角色授权，否则员工在前端根本看不到这个对象。

## 术语表

| 术语 | 含义 |
| --- | --- |
| 自定义对象 | 企业按业务需要新建的对象（如实施申请、投标申请），区别于客户、商机等预设对象 |
| API Name | 对象的程序标识，创建时确定、之后不可修改 |
| 主属性字段 | 对象"叫什么"的字段，用于查重、列表展示与查找关联的显示值 |
| 修改记录 | 对象可选项，开启后能查看字段级的历史变更 |
| 相关团队 | 对象可选项，允许把一批人加到这条数据的团队里共享权限 |
| 触发时机 | 审批流在什么动作发生时启动：新建、编辑、作废、变更负责人、阶段变更、其他按钮 |
| 普通审批 | 最基础的审批节点，指定处理人审批通过或驳回 |
| 多分支 | 按条件把流程拆成多条路径，各路径审批人不同 |
| 任务协作 | 需要多人共同处理的任务节点 |
| 并行网关 | 多条分支同时进行、全部完成后汇合 |
| 逐级审批 | 按部门层级一路往上批，可选本级、固定级数或固定级别 |
| 后动作 | 审批节点完成后触发的动作，如改字段、发提醒、发起业务流程 |
| 加签 | 审批过程中临时增加审批人；逐级审批节点不支持 |

## 需要注意的点

1. **API Name 建后不可改**：对象一旦创建，API Name 就固定了，后续集成、报表、接口都靠它，起名别用"test1""新建对象"这类。
2. **对象建完不等于能用**：还要加字段、配布局、在角色权限里授权，否则前端看不到，学员会以为"对象没建成功"。
3. **逐级审批不支持加签**：这是硬限制，遇到"逐级审批中途要加个领导看一眼"的需求，只能改流程设计。
4. **阶段变更类审批流没有"审批通过后动作"**：只能配节点完成后动作，和普通审批的配置位置不同。
5. **测试要用普通账号**：管理员有全量权限，用管理员测永远"看起来是对的"，一定要拿业务角色账号跑。
