# 速览（30 秒看完）

- 本课是课时14「客户管理」的配套练习：把课上讲过的配置点做成三道题，讲师在后台边操作边对答案。
- 第一题考「部门 + 角色 + 权限」：客户对象只勾查看列表、查看详情，手机号靠字段权限取消勾选变成不可见。
- 第二题考「自定义字段 + 公海回收」：先加「客户级别」单选字段（VIP客户 / 一般客户），再建一个公海配 7 天、30 天两条收回规则。
- 第三题考「业务类型 + 布局 + 多公海」：分配业务类型让直营销售、代理销售各管各的数据，分配布局让两类客户显示不同字段。
- 判分看的是后台勾选组合，不是前端看着像不像；题目里做不了的部分（销售助理的 BI 报表）讲师明确先不配。
- 回收天数是从客户的「最后跟进时间」算的，而这个时间由客户跟进规则里的跟进行为刷新，跟进行为没勾的动作不算跟进。
- 公海收回规则有三个参数必须会答：优先级从上往下逐条判断、包含已过去天数决定改规则时是否重算、成交后占有保有量。
- 保有量上限是「员工手上最多能有多少客户」，课件案例是每人 50 个、区域公海成员最多领 100 个，不在规则里的部门或员工不受限。

## 核心要点

- **本课定位**：课时14 已经学过客户管理并做过基础配置，这一节把配置点拆成三道题，只看题目、拆思路、在系统里对答案，题目做完要能独立把后台四要素串起来用。
- **第一题题目**：A公司成立新部门「客户成功部」，入职一批新的客户成功经理（目前公司 CRM 里只有「销售人员」一个角色）。需要把这批人加入系统，要求他们能看见客户列表、能看客户详情信息，但不能编辑客户数据，且客户下的「手机号」字段不可见。
- **第一题拆解顺序**：先把人放进去，再决定他们能干什么。所以顺序是「建部门 → 建角色 → 给角色配客户对象的操作权限 → 再配字段权限」，部门是组织归属，角色才是权限载体。
- **新建部门**：进管理后台 → 组织架构管理（部门与员工）→ 添加部门，填部门名称「客户成功部」、部门编码（如 0021）、部门负责人。负责人是必填项、只能从在职员工里选；系统里已有同名部门时直接沿用，不必重复创建。
- **新建角色**：管理后台 → 角色权限管理 → 业务功能权限 → 新建角色。填角色名称「客户成功经理」、角色描述、角色分组，还可以勾选复制某个已有角色的权限，避免从零一条条勾。
- **业务对象权限只勾看**：角色建好后回到该角色，先设置它对「客户」这个对象的权限：勾选「查看列表」「查看详情」，不勾「新建」「编辑」「删除」。注意编辑一勾上，前端详情页就会出现编辑按钮，判分看的是这几个勾选项的组合。
- **字段权限挡手机号**：切到「设置字段权限」，找到客户对象下的手机号字段，取消勾选，保存。字段权限是针对具体字段的可见性控制，和把字段从布局里删掉不是一回事——后者只是前端不显示，数据层面仍然看得到。
- **第二题题目**：客户管理要分级。客户级别为「VIP客户」的，要求员工 7 天之内跟进，否则提醒客户负责人、客户需要回收；「一般客户」一个月之内保持跟进即可，同样一个月没有任何跟进也会提醒负责人并被回收。
- **先补字段再配公海**：题目提到的客户级别在系统里没有现成字段，所以第一步是在客户对象上新建一个单选字段，第二步才是用公海承接「到期没跟进就回收」这件事。
- **新建客户级别字段**：管理后台 → 对象管理 → 预设对象管理 → 客户 → 字段列表 → 新建字段。字段类型选「单选」，字段名称「客户级别」，API Name 系统自动生成；选项一填「VIP客户」（对应值保留系统给的 option1），选项二填「一般客户」。后面的英文标识是底层开发用的，配置时可以先不管。
- **公海与「非公海客户」**：客户分给员工之后，如果长期没人跟进，资源就沉在个人手上，公海是集中管理和再分配的池子。不属于任何公海的客户称作「非公海客户」，所以收回规则分公海、非公海两套——本课两道题配的都是公海侧，刚新建还没进公海的客户走的是另一套。
- **新建公海**：客户公海管理 → 新建，填公海名称（如「客户管理部客户池」）、公海类型选「常规」，再指定管理员和公海成员。成员决定谁能看到、领取这个公海里的客户；题目里只有客户成功经理会用，就按该角色加人，不必把全公司都放进来。
- **分配领取规则**：可选「成员可见可领取，管理员可分配」和「成员不可见，管理员可分配」两种。题目没提这条，演示里选的是成员可见可领取，管理员可分配。
- **第一条收回规则（VIP）**：在公海里添加收回规则，条件选客户字段「客户级别」等于「VIP客户」，7 天内未跟进即回收，收回到「本公海」（不另选其他公海时默认回本公海），并设置提前 2 天提醒客户负责人及其所属团队。
- **第二条收回规则（一般客户）**：同一个公海再加一条，条件为客户级别等于「一般客户」，30 天（一个月）未跟进则回收，同样回收到本公海，提前 5 天提醒负责人。两条规则叠加，就实现了分级管理。
- **第三题题目**：公司业务模式分直营和代理，直营客户由直营销售负责、代理客户由代理销售负责，两个角色的数据相互独立不可见；两类客户要记录的信息不同；直营客户 10 天未跟进回收至直营公海，30 天未跟进回收至公共公海，代理客户同理；另需销售助理能看两类客户报表但不能新建编辑客户数据。
- **建业务类型**：客户对象 → 业务类型页签 → 新建，分别建「直营客户」和「代理客户」。业务类型是同一对象下的细分，让两类客户在系统里成为可区分、可分别授权的数据。
- **建两个销售角色**：角色权限管理 → 业务功能权限 → 新建，分别建「直营销售」「代理销售」。题目对权限没做特殊要求，给客户对象配常规的查看列表、查看详情、新建、编辑四项即可。
- **分配业务类型**：客户对象 → 业务类型 → 分配业务类型，弹窗左侧是角色、上方是业务类型，勾选关系就是权限关系。直营销售只勾「直营客户」，代理销售只勾「代理客户」，两个角色的数据才相互独立。
- **布局按主角色分配**：客户对象下有三种布局——列表页布局（进对象看到的表格）、详情页布局（点开一条数据看到的页面）、新建/编辑布局（点新建、选完业务类型后填写的表单）。一个账号可以有多个角色，但布局只看「主角色」，所以布局是按主角色分配的，不是按业务类型分配。
- **分配布局**：复制或新建出直营客户布局、代理客户布局后，点分配布局，按角色找到直营销售、代理销售，分别配上对应业务类型的布局并保存。
- **三个公海、两级回收**：直营公海管直营客户，代理公海管代理客户，公共公海做兜底。直营公海配两条规则，一条是业务类型为直营客户且 10 天未跟进，收回到直营公海并提前提醒；另一条是 30 天未跟进，收回到「其他公海」即公共公海。代理公海按同样思路配，只是对象换成代理客户。
- **收回规则的三个参数**：优先级——先判断客户是否满足优先级 1，满足就收回，不满足再校验优先级 2，以此类推；包含已过去天数——对当前的收回规则做修改时会更新收回剩余天数，这个开关决定是否重新计算；成交后占有保有量——勾选则客户成交后仍占有保有数量。
- **回收判的是「最后跟进时间」**：客户跟进规则里勾选的跟进行为（发销售记录、更新客户信息、创建商机订单等，可多选）会刷新客户的最后跟进时间，回收天数从这一天开始算；所以改跟进规则会直接影响客户什么时候被收回，配置前先把跟进行为定下来。
- **保有量上限**：客户保有量上限是员工可以保有的最大客户数，不在规则中的部门或员工没有保有量限制，还可以对部门单独设置收回规则和提醒信息。课件案例给的口径是员工负责的客户最多 50 个、区域公海每个成员最多领取 100 个。

## 结构与流程

三道配置题的题目 → 考点 → 配置路径：

```
第一题 部门 + 角色 + 权限（客户成功经理只能看、不能改、看不到手机号）
 考点 组织架构是权限前提；对象权限与字段权限是两层控制
 路径 管理后台 → 组织架构管理 → 添加部门（客户成功部 / 编码 / 负责人）
 → 角色权限管理 → 业务功能权限 → 新建角色（客户成功经理）
 → 该角色 → 客户对象：勾 查看列表、查看详情，不勾 新建 / 编辑 / 删除
 → 设置字段权限 → 手机号 取消勾选 → 保存

第二题 自定义字段 + 公海回收（VIP 7 天 / 一般客户一个月）
 考点 单选字段承载分级；公海收回规则按字段条件和天数自动回收
 路径 对象管理 → 预设对象管理 → 客户 → 字段列表 → 新建字段
 （类型：单选；名称：客户级别；选项：VIP客户、一般客户）
 → 客户公海管理 → 新建公海（名称 / 常规 / 管理员 / 公海成员=客户成功经理）
 → 分配领取规则：成员可见可领取，管理员可分配
 → 收回规则 → 添加规则
 规则1 客户级别 = VIP客户 未跟进 7 天 → 收回到本公海，提前 2 天提醒
 规则2 客户级别 = 一般客户 未跟进 30 天 → 收回到本公海，提前 5 天提醒

第三题 业务类型 + 布局 + 三个公海（直营 / 代理 / 公共）
 考点 业务类型管「数据归属与角色授权」，布局管「字段怎么显示」，
 布局按主角色分配；回收规则可跨公海级联
 路径 客户对象 → 业务类型 → 新建：直营客户、代理客户
 → 角色权限管理 → 新建角色：直营销售、代理销售（客户对象四项常规权限）
 → 客户对象 → 业务类型 → 分配业务类型：角色 × 业务类型 交叉勾选
 → 客户对象 → 布局 → 详情页 / 新建编辑 / 列表页 三种布局
 → 分配布局：直营销售 → 直营客户布局；代理销售 → 代理客户布局
 → 客户公海管理 → 新建 直营公海、代理公海、公共公海
 → 直营公海收回规则：业务类型=直营客户，10 天未跟进 → 直营公海
 业务类型=直营客户，30 天未跟进 → 公共公海
 → 代理公海按同样两条规则配置（对象换成代理客户）
```

第一题的判断标准（勾选组合）：

- 客户对象：查看列表 ✔ ｜ 查看详情 ✔ ｜ 新建 ✘ ｜ 编辑 ✘ ｜ 删除 ✘
- 字段权限：手机号 ✘（不可见），其余字段按默认

课件「功能节点回顾」给出的四个功能节点，配完题回头对一遍：

```
① 客户的创建         CRM 对象新建 ／ 智能表单录入
② 分类创建客户       布局 + 业务类型
③ 外勤               外勤动作 → 外勤类型 → 外勤规则
                     经销商拜访要完成签到、店铺拍照、填写沟通记录、签退
④ 客户公海管理       查重设置（避免重复新建客户）· 保有量
                     · 客户回收规则（公海、非公海两套）
```

天数口径有两套，别混：课件案例（饮品公司）是 VIP 客户 10 天、重要客户 30 天、普通客户 60 天未跟进回收；本课三道题按 VIP 7 天、一般客户 30 天、直营/代理 10 天与 30 天出题。配置方法完全一样，天数按题目填。

| 术语 | 含义 |
| --- | --- |
| 客户成功部 | 第一题要新建的部门，客户成功经理的组织归属 |
| 部门编码 | 添加部门时填写的部门唯一标识，如 0021 |
| 部门负责人 | 部门的管理人，添加部门时必填，只能选在职员工 |
| 角色 | 一组权限的集合，账号通过角色获得对对象和字段的操作能力 |
| 业务功能权限 | 角色权限管理下配置角色权限的页签，新建角色也从这里进 |
| 业务对象权限 | 角色对某个对象（如客户）的查看列表、查看详情、新建、编辑、删除等操作权限 |
| 字段权限 | 控制角色对对象内具体字段（如手机号）能否查看、能否编辑 |
| 公海 | 集中存放无人跟进客户的池子，按规则自动回收并支持成员领取 |
| 非公海客户 | 不属于任何公海的客户，刚新建的客户就处于这个状态，走非公海收回规则 |
| 客户级别 | 第二题新建的单选字段，选项为 VIP客户与一般客户 |
| 分配领取规则 | 决定公海成员是否可见公海客户、能否自行领取 |
| 收回规则 | 满足字段条件与未跟进天数后，把客户自动收回公海的规则 |
| 优先级 | 多条收回规则的判断顺序，满足优先级 1 就收回，不再往下校验 |
| 包含已过去天数 | 修改收回规则时，是否把已经过去的天数重新计入、重算剩余天数 |
| 成交后占有保有量 | 勾选后客户成交仍占用保有数量，不释放给本人再领 |
| 本公海 | 收回规则里「收回到」的默认目标，即客户当前所在公海 |
| 保有量上限 | 员工可以保有的最大客户数；不在规则中的部门或员工没有限制 |
| 客户跟进规则 | 定义哪些动作算「跟进」，直接决定客户最后跟进时间何时刷新 |
| 跟进行为 | 会刷新最后跟进时间的动作，如发销售记录、更新客户信息、创建商机订单，可多选 |
| 成交动作 | 被认定为成交的动作，如商机赢单、销售订单确认、新建合同，单选 |
| 最后跟进时间 | 客户上的时间字段，回收天数的计算起点 |
| 客户成交规则 | 决定客户何时变为「已成交／多次成交」的规则，分预设与自定义 |
| 客户规则设置 | 客户业务规则开关集合，如是否允许修改客户名称 |
| 数据维护工具 | 管理后台的批量维护入口，「全部客户」可批量更换客户负责人 |
| 外勤规则 | 限定外勤类型适用范围与定位范围的规则，经销商拜访靠它留痕 |
| 业务类型 | 同一对象下按业务形态做的细分，如直营客户、代理客户 |
| 分配业务类型 | 把业务类型授权给角色，决定角色能操作哪类客户 |
| 布局 | 字段在页面上的排布，分列表页、详情页、新建/编辑三种 |
| 主角色 | 一个账号可拥有多个角色，布局只取主角色对应的那一套 |
| 公共公海 | 兜底公海，承接直营/代理公海中长期未跟进被二次回收的客户 |

## 需要注意的点

1. **角色单独建出来不等于能用**：新建角色只是建了个空壳，必须再回到角色里勾客户对象的操作权限、必要时再配字段权限，权限才真正生效。第一题最容易漏的就是「设置字段权限」这一步。
2. **「手机号不可见」不要用删字段的方式做**：把字段从布局里删掉只是前端不显示，数据层面仍然看得到；正确做法是在字段权限里取消该字段的勾选。题目考的是权限，不是界面。
3. **收回规则的「收回到」默认是本公海**：第二题只建了一个公海，两条规则都不用另选目标；第三题才需要把 30 天那条改成收回到「其他公海」（公共公海），两条规则是级联关系，不是各建一个公海。
4. **业务类型与布局是两件事，都要配**：业务类型决定这条客户归谁管、哪个角色能碰；布局决定这个角色看到哪些字段。只分配业务类型不配布局，前端字段展示不会按业务类型分开；只配布局不分配业务类型，角色又操作不到对应客户。
5. **布局跟主角色走，不跟业务类型走**：同一账号挂多个角色时，系统只取主角色对应的布局。演示里账号同时有直营销售、代理销售等角色，所以要按主角色去理解最终展示效果。
6. **题目里有做不了的部分要说明**：第三题销售助理的月度报表要依赖 BI 报表模块，课程还没讲到，讲师明确先不配置，只把角色、业务类型、布局、公海这些能在本节课完成的部分做掉。新手不要把「没配」当成「配错了」。
7. **天数按题目填，别照抄课件案例**：案例里是 VIP 10 天、重要 30 天、普通 60 天；本课题目是 VIP 7 天、一般客户 30 天，第三题是 10 天与 30 天。回收规则怎么配都一样，数字填错等于题做错。
8. **改已有收回规则要留意「包含已过去天数」**：规则一改，系统会更新客户的收回剩余天数，这个开关决定是否把已经过去的天数重新算进去。勾错会让一批客户提前或推迟被收回，上线前先确认口径。
9. **跟进行为没勾，动作做了也不算跟进**：客户跟进规则里没勾「发销售记录」，销售发了记录也不会刷新最后跟进时间，客户照样到点被回收；反之成交动作（商机赢单、销售订单确认、新建合同，单选）会更新最后成交时间、最后跟进时间、是否成交和剩余保有时间。
10. **已成交客户也会被回收**：课件场景里，未成交的领取客户 30 天未跟进、第 25 天提醒，已成交客户 90 天没有新成交同样自动回收、提前 30 天提醒；只配了「未跟进」一条规则，这批成交客户就漏掉了。成交状态由成交规则判定，预设规则下（新建销售订单并审批通过即成交）前端没有手改入口。
11. **客户名称改不了先查两处**：客户规则设置里不勾「允许修改客户名称」时，员工在前端改不了，只有 CRM 管理员能在【CRM设置-数据维护-全部客户】改；要放开员工改名，就在客户规则设置里把这一个开关勾上，不用去动字段权限。
12. **换负责人和作废有连带限制**：更换客户负责人时可以一并更换商机、联系人、订单、合同的负责人，缺任一对象的更换权限就会保存失败；客户处在审批流程中也会失败。另外审核中的数据不能作废，必须撤回审批或等审核完成。离职员工的客户批量转出，走管理后台 → 数据维护工具 → 全部客户 → 筛选停用员工，再用迁移工具处理。
