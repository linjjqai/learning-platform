# 速览（30 秒看完）

- 对象管理被拆成五部分、五节课讲：对象&字段、布局&业务类型、字段依赖&布局规则&验证规则、角色权限设置、按钮&场景管理，本课只讲第一部分。
- 对象是业务模块（客户、商机、联系人、销售订单），字段是对象里一条条具体的信息项；配对象就是先建"表"，再加"表头"。
- 预设对象开箱即用、主属性字段类型不可改；预设对象覆盖不了的个性化业务才建自定义对象（售后服务、售前支持申请、实施项目）。
- 入口只有一个：管理后台 → CRM 平台管理 → 对象管理，只有 CRM 管理员能进。
- 建对象四步：对象名称与图标 → 可选功能 → 主属性字段（体现唯一性）→ 布局配置；对象名可以重，API Name 必须唯一。
- 字段上限是硬数字：单行文本 100 字符、多行文本 2000、富文本 131072、单选/多选各 3000 个选项、图片 20、附件 50、大附件 1、查找关联 10、引用/计算/统计各 20、主从关系 1。
- 字段的位置和顺序在对象布局里调，后台改完必须刷新前端才看得到。
- 生命状态五个取值：未生效、审核中、正常、变更中、作废；审核中的数据会自动锁定，统计只认"正常"。

## 核心要点

- **课程定位与五部分结构**：课件把对象管理拆成五块——对象&字段、布局&业务类型、字段依赖&布局规则&验证规则、角色权限设置、按钮&场景管理，本课只讲第一块「对象与字段」。贯穿全课的场景是：同一家公司做国内和国外两个市场，国外客户不录注册资金、法人代表；勾了"是否上市公司"才出现公司规模、注册日期、注册资金三个字段，不勾就既不用填也不该看到；一级行业选高服/制造/快消，二级行业只能按对应关系选（高服→互联网、计算机软件；制造→家居建材、医疗医药；快消→快消品、农牧业）。"该不该出现、能不能选"这类问题，后面要靠字段、字段依赖、布局规则一步步解决。
- **对象与字段的类比**：用问卷星或 Excel 类比——表名/问卷名是"对象"，表头/问题是"字段"，填写的内容是"字段值"，一行记录就是系统里的一条数据。落到系统里，客户对象的一行是一条客户数据，客户名称、负责人、行业这些都是它的字段。搞懂这层对应，后面配对象、配字段就不抽象。
- **系统里的对象与后台入口**：登录纷享销客后，CRM 应用里的各个模块就是对象：客户、联系人、商机、销售订单。它们在管理后台 → CRM 平台管理 → 对象管理里配置，分两类——预设对象是为了企业开箱即用而存在；自定义对象用于预设对象无法满足的个性化业务，例如设备类行业自建"售后服务"、ICT 行业自建"售前支持申请""实施项目"。
- **从列表页到创建对象**：点进对象先看到数据列表页，一行一条数据；点开某行进详情/编辑页，看到的是各字段的排布，这些字段共同构成这条数据。创建时从管理后台进对象管理，先填对象名称（本课示例"学校"，命名逻辑与客户、订单、商机一致），再选对象在 CRM 里展示的图标，图标之后可随时更换。
- **可选功能五个开关**：新建对象时有一组可选功能，勾了前端才出现。相关团队——把同事加进这条数据一起跟进、共同查看；修改记录——展示该数据的所有操作，谁新建、谁更换负责人、系统自动改负责人、谁添加了相关团队，可查 18 个月；动态——发布销售记录（如"2 月拜访王总，方案已认可，下周签合同"），沉淀在动态区。全局搜索、多字段排序也是同一组开关。
- **主属性字段与唯一性**：主属性字段承载对象的核心内容、体现唯一性，是不同数据之间的最大区别——客户的客户名称、销售订单的订单编号（如 20250616-000492）。类比身份证号：身高、体重、籍贯都可能相同，身份证号不同，数据也靠主属性字段区分。字段设置里可改名称与 API Name，类型可选文本（如客户名称）或自增编号（如订单编号），编号还能设前缀/后缀（可插入年、月、日或字段）、位数、起始值、重算规则，以及"是否允许重复"——不允许时，两条都叫"冲冲冲"的客户就提交不进去。
- **对象可以重名，API Name 必须唯一**：对象与对象可能重名，但对象的 API Name 全局唯一；字段也一样，每个对象都有主属性字段 name，各字段的 API Name 也不能撞。保存报错先查 API Name，而不是反复改名字。
- **对象建好后自带的预设字段**：创建完成后再打开字段列表，系统已自动生成 12 个预设字段（也叫标准字段、预制字段）：学校名称、负责人、归属部门、锁定状态、负责人主属部门、外部负责人、最后修改时间、创建时间、最后修改人、创建人、业务类型、生命周期状态。它们存的是数据的共性，因此不能删除、部分字段可编辑；字段在页面上的位置和顺序，是管理员在这个对象的布局里改，不是在字段列表里改。
- **字段类型与数量上限**：添加字段按需选类型，用途与上限是硬规定——单行文本填简短文字（姓名，最多 100 字符）；多行文本填备注、建议（最多 2000 字符）；富文本做图文混排、课件里叫"协同富文本"（最多 131072 字符）；单选、多选各最多 3000 个选项值；金额带千分位；日期时间选到具体时刻（如 2099-12-31 16:31）；手机只收号码；图片每对象最多 20 个，支持水印拍照与 OCR 文字识别；附件每对象最多 50 个，可设定最多上传个数；大附件每对象最多 1 个，专传 100M 以上的文件、暂不支持资源包；查找关联最多 10 个、引用字段 20 个、计算字段 20 个、统计字段 20 个、主从关系 1 个。超出的要购买资源包。
- **字段属性与 API Name 的用法**：字段列表显示字段名称、API Name、创建时间等；技术侧看到的不是中文名而是 API Name，字段统计不对、金额不对时把 API Name 复制给客服转技术，比描述字段名高效得多。添加字段还可填备注（只在后台说明用途，前端不展示）和帮助信息（写填写要求，支持提醒/悬浮提示与外置显示，外置显示仅新建编辑页），并可勾必填——不填就提交不了。
- **基础字段实操：选项与输入方式**：单选可逐个新建选项，也可批量新建（每行一个值，一次生成小学、初中、高中、中专、大专、本科），再给单个选项配色（把 VIP 客户标红）；数字可设小数位数；日期时间可选日期或"此刻"；手机只能输入数字；布尔是"是/否"开关；百分比可选择进度条样式，前端更直观。
- **刷新生效与必填校验**：后台所有配置都要等前端刷新后才生效。新建数据时必填项没填，提交会失败；填上单选项、日期时间、人数、手机号、百分比后提交成功，详情页能看到单选颜色、进度条、帮助信息提示这些效果。
- **列表页显示字段与每页条数**：列表页默认展示的字段不一定是最关心的，点齿轮进设置，把要看的字段勾上并上下移动排到前面，不需要的取消勾选；还能设每页显示 20/50/100 条。详情页上能看到的字段，也可以同时放到列表页展示。
- **计算字段**：用公式算值，例如把两次加购价格累计、按条件取某个选项。设置里先选返回类型（数值、百分数、日期、布尔值等）与小数位数，公式分基础模式（只能选本对象字段）和高级模式（可跨对象取关联对象的数据），支持插入字段/运算符/函数，还有 AI 公式助手与预发检查。检查报错往往是用错了类型（把日期时间当数值参与计算），改回数值即可通过；配好还能用测试数据验算，例如人数 1234 求和仍得 1234。计算字段只读，前端不能手填。
- **统计字段**：用于跨对象汇总，典型是统计订单下"订单产品"的条数、或汇总订单的回款金额。添加时选主对象（销售订单）与统计类型（计数、求和、平均值、最大值），做求和/平均要指定被统计的字段。保存后字段只读、系统实时累计：订单里 2 条产品就统计出 2，加到 4 条就变 4；再在客户下建一个统计字段，就能知道这个客户一共产生过多少订单、金额合计多少，用于判断大客户。
- **查找关联**：系统给对象之间只定了两种特定关系——查找关联与主从关系。查找关联把当前对象与其他对象（或自身）关联，如【订单】关联【客户】。配置时选查找关联对象，填相关列表标题（如"学校"）与相关列表 API Name，选是否把该相关列表加到对方对象的布局里，并可限定可选数据范围（全部 / 符合条件）。建好后双向可见：销售订单里点蓝色的客户名称能进客户详情，客户详情下的销售订单组件里，所有关联了此客户的订单都在这个列表。
- **引用字段**：用来跨对象取值，如【订单产品】引用【产品】的自定义信息，或在学校详情页引用关联客户的"客户级别"。它同样只读、不能手填，且必须在布局里放出来前端才可见。前提是来源字段本身有值——客户级别没填，引用出来就是空的。
- **主从关系**：把明细行挂在主对象下面，典型是销售订单—订单产品：订单里能直接看到产品明细并进入编辑。与查找关联的区别是——查找关联的每条数据都独立存在，而从对象的明细必须依附于一条主对象，一条主对象下可以有多条明细（类似报销单与费用明细，汇总后得到总费用）。四条规则：从对象里加主从字段、1 个从对象只有 1 个主对象、1 个主对象最多 5 个从对象；从对象明细最多 200 条，需购买资源扩容、不建议超过 500 条；同一套主从关系可复用到样机申请—样机申请明细；从对象权限完全跟随主对象。
- **字段的禁用、删除与启用**：不需要的字段先"禁用"，禁用后前端看不到该字段及其数据；确认不再使用再"删除"，删除后该字段下的值一并删除且不可恢复；重新"启用"则恢复到之前的状态。字段与对象的后台配置权限只给 CRM 管理员，普通员工不能进后台加字段。
- **生命状态与统计口径**：每个对象都预置了生命状态字段（界面上也叫生命周期状态），五个取值对应数据真实状态——未生效（设了新建审批、审批不同意）、审核中（新建审批进行中，该条数据会被自动锁定，解锁前不允许编辑）、正常（审批通过；没设审批则新建保存后即正常）、变更中（正常数据走了编辑审批流、正在审批中）、作废（数据被作废）。做业务统计必须按它过滤：只有生命状态正常的订单才算本月真正生效的业绩，未生效、审核中、变更中、作废的都不能计入；统计字段里也能加"生命状态等于正常"的条件。
- **客户数据模型练习（课件任务）**：任务是把客户信息搭进 CRM——客户名称、是否上市公司（是/否）、公司规模（特大型企业、大型企业、中小型企业、小型企业）、客户级别（普通客户、重要客户、VIP客户）、预计成交金额，加上企业信息里的注册日期、注册资金、法人代表、经营范围。要自己判断每一项用什么字段类型；"是否上市公司"要必填就勾必填，VIP 客户要标红就在单选选项里单独配色；再自己配一个计算字段和一个统计字段，保存后到前端看数据效果。

## 结构与流程

对象分类：

```
对象
├── 预设对象（开箱即用，系统预置逻辑，主属性字段类型不可改）
│ ├── 客户 / 客户地址 / 客户财务信息
│ ├── 联系人 / 商机 / 商机明细
│ ├── 销售订单 / 订单产品 / 报价单
│ └── 产品 / 价目表 / 回款 …
└── 自定义对象（个性化业务，自行创建）
  ├── 设备类行业：售后服务
  ├── ICT 行业：售前支持申请、实施项目
  └── 本课示例：学校（主属性字段＝学校名称）
```

字段类型清单（幻灯片 + 系统添加字段列表）：

```
基础字段
 单行文本 ≤100 字符 多行文本 ≤2000 字符
 富文本（课件称协同富文本）≤131072 字符
 单选 / 多选 各 ≤3000 个选项 数字（可设小数位数）
 金额（带千分位） 日期 / 时间 / 日期时间
 手机（仅数字） 邮箱 网址 百分比（可用进度条展示）
 布尔值（是/否） 图片（每对象 ≤20，支持水印拍照、OCR）
 附件（每对象 ≤50，可设最多上传个数）
 大附件（每对象 ≤1，传 100M 以上文件，暂不支持资源包）
 部门 / 部门(多选) / 人员 / 人员(多选) / 区域 / 地区 / 签到 / 地区定位 / 签名
高级字段
 查找关联（每对象 ≤10） 引用字段（每对象 ≤20）
 计算字段（每对象 ≤20） 统计字段（每对象 ≤20）
 主从关系（每对象 ≤1，1 个主对象 ≤5 个从对象，明细 ≤200 条）
```

生命状态五个取值（每个对象都预置）：

```
未生效 ← 设了新建审批，审批不同意
审核中 ← 新建审批进行中：数据自动锁定，解锁前不允许编辑
正常   ← 审批通过；未设审批时，新建保存后即正常
变更中 ← 正常数据走了编辑审批流、审批中
作废   ← 该条数据被作废
```

建对象→用字段的配置顺序：

- **第 1 步** 管理后台 → CRM 平台管理 → 对象管理 → 新建自定义对象
- **第 2 步** 对象基本信息：对象名称、对象图标、可选功能（相关团队 / 全局搜索 / 动态 / 修改记录 / 多字段排序）
- **第 3 步** 主属性字段设置：字段名称、API Name、类型（文本 / 自增编号）、前缀/后缀、位数、起始值、重算规则、是否允许重复
- **第 4 步** 布局配置 → 保存退出（API Name 不能重复）
- **第 5 步** 字段列表：确认 12 个预设字段 → 添加字段（选类型 → 填名称/API Name/备注/帮助信息/必填 → 选项与颜色）→ 保存，需要连续加时用「保存并添加」
- **第 6 步** 前端刷新 → 新建/编辑数据验证效果
- **第 7 步** 列表页齿轮 → 调整显示字段与顺序、每页条数
- **第 8 步** 按需追加高级字段：计算 → 统计 → 查找关联 → 引用 → 主从关系
- **第 9 步** 不用的字段先禁用，确认后再删除；统计时用生命状态过滤口径

## 术语表

| 术语 | 含义 |
| --- | --- |
| 对象 | 系统里的业务模块，如客户、商机、联系人、销售订单；相当于一张表/一份问卷 |
| 字段 | 对象里的具体信息项，相当于表头 |
| 字段值 | 字段里填写的内容，一行内容即一条数据 |
| 预设对象 | 系统预置、开箱即用的对象，逻辑已固定，主属性字段类型不支持修改 |
| 自定义对象 | 预设对象无法满足个性化业务时自行创建的对象 |
| 主属性字段 | 承载对象核心内容、体现唯一性的字段，如客户名称、订单编号 |
| 字段编号 | 主属性字段按规则自动生成的编号，可插入日期、设位数与起始值，无需手填 |
| 是否允许重复 | 主属性字段的唯一性开关，不允许重复时同名数据提交会报错 |
| API Name | 对象/字段在系统里的唯一技术标识，技术排查问题时使用 |
| 可选功能 | 新建对象时勾选后才在前端出现的功能开关（相关团队、动态、修改记录等） |
| 相关团队 | 把同事加入某条数据共同跟进、共同查看数据的组件 |
| 修改记录 | 记录该数据全部操作，可展示 18 个月内的修改历史 |
| 动态 | 发布销售记录/跟进记录并沉淀在详情页动态区的组件 |
| 对象图标 | 对象在 CRM 里展示的图标，创建时选择、之后可随时更换 |
| 布局配置 | 建对象流程的最后一步，决定字段在页面上的排布 |
| 预设字段 | 对象创建后系统自动生成的 12 个基础字段，也叫标准字段/预制字段，不可删除、部分可编辑 |
| 帮助信息 | 字段的填写提示，支持提醒/悬浮提示与外置显示（仅新建编辑页） |
| 协同富文本 | 课件对富文本的叫法，做图文混排，比富文本多协同能力，字段值最多 131072 字符 |
| 大附件 | 专门上传 100M 以上文件的附件类型，每个对象最多 1 个，暂不支持资源包 |
| 资源包 | 字段、图片、附件等配额不够时另行购买的扩容包 |
| 计算字段 | 用公式计算取值的只读字段，基础模式限本对象，高级模式可跨对象 |
| 统计字段 | 跨对象汇总的只读字段，统计类型有计数、求和、平均值、最大值 |
| 查找关联 | 当前对象与其他对象（或自身）建立关联关系的字段，如订单关联客户 |
| 引用字段 | 跨对象读取并展示来源对象字段值，只读，如学校引用客户级别 |
| 主从关系 | 明细数据依附主对象存在的特殊关联，如销售订单—订单产品，权限随主对象 |
| 生命状态 | 系统预置字段（界面也叫生命周期状态），取值未生效/审核中/正常/变更中/作废 |
| 审核中 | 新建审批未完成时的状态，数据被自动锁定，解锁前不能编辑 |
| 变更中 | 正常数据走了编辑审批流、审批中的状态，用于统计口径过滤 |

## 需要注意的点

1. **口播的"字段编号"其实是主属性字段的设置项**：转录里反复出现的"足路限制段/主属性字段"，指的就是承载唯一性的主属性字段；编号（自增、插入日期、位数、起始值）只是其中一个配置块，别把它当成一种独立字段类型。
2. **对象名可以重、API Name 不能重**：对象名称重复没关系，但 API Name 全局唯一，字段的 API Name 同理。新建对象保存报错时先查 API Name，而不是反复改名字。
3. **预设字段删不掉、预设对象的主属性类型改不了**：对象建好后自动生成的 12 个字段是标准字段（预制字段），存的是数据共性，只能部分编辑；预设对象的主属性字段类型也不支持修改，遇到"改不了"不是权限问题。
4. **生命状态最容易被说错**：五个取值是未生效、审核中、正常、变更中、作废，没有"编辑中"；"审核中"的数据会被自动锁定，解锁前不允许编辑；没设新建审批的对象，保存后直接是"正常"。统计只认"正常"，别把未生效、审核中、变更中、作废算进业绩。
5. **字段删除不可逆**：必须先点"禁用"再点"删除"，删除后该字段下的值一并删除且无法恢复。给客户演示时点到删除要格外小心，"启用"只能恢复被禁用的字段，救不回已删除的。
6. **后台改完必须刷新前端**：字段、布局、选项颜色、进度条样式改完，前端不刷新看不到效果；演示或给客户讲解时别忘了这一步，否则会误判为"配置没生效"。
7. **计算/统计/引用字段一律只读，且依赖源数据**：它们由系统算出，表单里填不进去；源字段没有值时结果就是空。统计字段的口径还要叠加生命状态（只要正常的），否则会把未生效、作废的数据也算进业绩。
8. **数量上限是硬上限，不是建议值**：图片 20、附件 50、大附件 1、查找关联 10、引用/计算/统计各 20、主从关系 1 个，超出要购买资源包；但大附件只有 1 个配额且明确暂不支持资源包，它只负责传 100M 以上的文件，普通附件留着传日常文件。主从关系另有 1 从对象只对应 1 主对象、1 主对象最多 5 个从对象、明细最多 200 条（不建议超 500）的限制，建模前先算清楚。
9. **对象之间只有两种特定关系**：查找关联和主从关系，没有第三种。查找关联的数据各自独立、可以互相关联；主从关系的明细必须依附一条主对象，权限跟着主对象走，删除主对象明细也会跟着走。选错类型后期很难改。
10. **字段位置在布局里改，不是字段列表里改**：字段列表管的是加、禁用、删除；字段显示在页面哪个位置、什么顺序，要在该对象的布局里拖拽调整。布局里能新建字段、能隐藏字段，但禁用和删除只能回字段列表操作。
11. **叫法要和界面对齐**：课件写"协同富文本"，系统字段列表里叫"富文本"，指的是同一个类型；课件写"生命状态"，口播和界面上也说"生命周期状态"。给客户讲或写文档时先说明是一回事，别让客户以为系统里缺了这个功能。
12. **做客户数据模型练习时的两个易漏点**：公司规模是四个选项，别漏"特大型企业"；"是否上市公司必填"和"VIP 客户标红"是两处配置——前者在字段上勾必填，后者在单选选项里单独配色，位置不同，先想清楚再动手。
