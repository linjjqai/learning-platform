# 速览（30 秒看完）

- 工作流＝按预设规则自动执行，完全不用人盯；审批流是"要有人审"，工作流是"没人管自动跑"。
- 五种触发：**新建**（提交后 / 审批通过后）、**作废**、**恢复**、**字段更新**、**定时**（执行一次 / 重复执行，支持日期前或后 N 天/周/月）。
- 配置三步：管理后台 → 流程管理 → 工作流管理 → 右上角"新建"；选发起对象 → 选何时触发 → 加条件 → 配执行活动。条件与触发时机必须**同时满足**。
- 字段更新触发的硬性要求：必须再加一条"某字段变更时"条件才能保存；统计字段、引用字段、系统预置字段还要先加**字段白名单**。
- 执行活动十几种，线索和客户对象独有"**数据操作（转移 / 退回公共池）**"；一个分支可以同时挂多项活动。
- 条件分支按顺序匹配，不设条件的分支是默认分支；"下一条件=是"才会继续匹配后面的分支（默认否）。
- 历史数据不会因为工作流新建就补跑：用更新导入（勾"是否触发工作流=是"）或编辑更新，前提是工作流支持编辑时触发。
- 查是否触发：**企业日志 → 流程日志 → 执行日志 / 触发日志**，按数据 ID 查最准。

## 核心要点

- **工作流定义与核心价值**：按企业经营过程和预设规则自动执行制度任务，**完全无需人工干预**。课件里的原型场景就是线索按地区自动划分到各地区电销线索池——不用 SDR 一条条查手机号判地区再分配。
- **后台配置入口与基本信息四项**：管理后台 → 流程管理 → 工作流管理 → 右上角"新建"。基本信息要填：流程名称、发起对象（基于哪个对象发起工作流）、何时触发、添加条件；另有一个"触发操作"决定和审批流的先后。**触发条件和执行活动里能选到的字段，全部来自"发起对象"这个对象**。
- **触发时机——新建触发**：新建一条数据时立即触发，可选"提交后直接触发"或"对象审批通过后再触发"。后者用于该对象本身配了审批流的情况——先过了审批再执行工作流。
- **触发时机——作废 / 恢复触发**：作废某条数据时触发；恢复某条已作废的数据时触发。这两种跟着对象的作废状态走，不需要额外判断。
- **触发时机——字段更新触发**：对象下某个字段被修改后触发。**硬性要求**：不管下面配了什么触发条件，都必须再加一条"某字段变更时"的条件才能保存。这条条件只是为了通过系统校验，**不影响实际触发逻辑**；设计意图是避免数据上任意字段一改就触发工作流，造成执行风暴。
- **触发时机——定时触发**：按对象下的日期时间字段到点触发，分两种：① 执行一次（到设定日期当天跑一次就停）；② 重复执行（从该日期起按每天 / 每周 / 每月 / 每年循环）。参数是执行日期（选哪个日期字段）、执行时间（当天几点）、开始 / 结束日期、重复方式。
- **定时触发的时点口径**：既可以是日期字段**当天**，也可以是"某个日期**前 / 后 N 天 / 周 / 月**"这种相对时点。课件配套题里的"计划回款日期到期前 15 天提醒销售催款"，选的是计划回款日期 + 前 15 天，不是等日期当天。
- **字段白名单**：系统预置字段（创建时间、最后修改时间）、统计字段、引用字段默认不在字段更新的可选列表里。要到 工作流管理 → 右上角"**全局配置**" → **字段白名单配置**，把这些字段加到对应对象下。课件例：客户对象加一个统计字段统计名下角色为 KP 的联系人数量，数量变化要提醒客户负责人，就得先把该统计字段加进白名单。
- **"添加条件"和触发时机是"同时满足"**：基本信息里加的这条条件，和上面的"何时触发"必须同时成立，系统才执行工作流。它和分支里的菱形条件不是一回事——一个是进门条件，一个是执行活动前的分流条件。
- **触发操作——与审批流联动**：对象既配了新建时触发审批流、又配了新建触发工作流时，这里决定触发审批流的同时是否也触发工作流：可以提交后同时跑审批流 + 工作流，也可以先过审批、通过后再跑工作流。
- **执行活动清单（课件原表）**：CRM 提醒（向相关人员发送 CRM 消息提醒）、字段变更（改本对象或关联对象的字段）、短信通知（向客户 / 指定角色发）、邮件通知（向客户 / 指定角色发）、数据操作、发起业务流程、数据锁定 / 解锁、分配负责人、新建任务、新建日程、新建销售记录（在发起对象下建一条销售记录）、执行 APL 代码（执行特定的函数运算）、新建外部通知（向微信用户 / 下游伙伴发消息）。
- **执行活动——数据操作**：只有**线索和客户**对象有，选项是"转移到"或"退回"**公共池（线索池）**。转移保留原负责人，退回清空负责人。
- **执行活动——提醒人怎么选**：不要硬选某个人，用数据负责人、部门负责人、角色这类变量，数据流转到谁手上就提醒谁。邮件通知要先配好系统邮箱。
- **活动与条件怎么摆**：长方形里配执行活动，一个分支可以**同时执行多项活动**；菱形里写执行条件，**支持多个条件**一起判断。
- **条件分支与"下一条件"**：多个分支按顺序匹配。每个分支可设"下一条件"——满足条件执行完活动后，是否继续匹配后面的分支；默认"否"，改成"是"就能让一条数据连续触发多个活动。
- **前端效果演示——线索自动分配**：新建一条省市为上海的线索，提交后系统自动把它转移到"上海线索池"，负责人自动变成线索池管理员，秒级完成、无人工介入。
- **执行逻辑总结**：事件触发（新建 / 作废 / 恢复 / 字段更新 / 定时）→ 条件判断（分支 + 下一条件）→ 立即执行活动 → 视"下一条件"决定是否继续。
- **常见问题一——历史数据没触发**：去年创建的数据、今年才建的工作流，对历史数据不生效。要生效就编辑一次，或用**更新导入**匹配数据来触发，前提是这条工作流支持编辑时触发。系统不让历史数据直接生效，是因为有些企业历史数据量太大，瞬间负载会把系统压垮。
- **常见问题二——查工作流有没有触发**：后台 **企业日志 → 流程日志 → 执行日志 / 触发日志**。可以按数据权限看，也可以按数据 ID 精确查——去前端数据详情页的 URL 里复制 ID，回来贴上去查。
- **学习重点**：一是搞清五种触发方式各自的应用场景，二是搞清每种执行活动的作用和适用场景，两者组合起来就能配出绝大多数自动化需求。

## 结构与流程

工作流配置逻辑：

```
管理后台 → 流程管理 → 工作流管理 → 新建

第一步：基本信息
 工作流名称
 发起对象（触发条件、执行活动的可选项都来自这个对象的字段）
 何时触发：
 ├── 新建触发（提交后 / 审批通过后）
 ├── 作废触发
 ├── 恢复触发
 ├── 字段更新触发（⚠ 必须加"某字段变更时"条件）
 └── 定时触发（执行一次 / 重复执行 / 日期前或后 N 天周月）
 添加条件（与"何时触发"同时满足才执行）
 触发操作（对象配了新建审批流时，是否同时触发工作流）

第二步：条件 + 活动配置
 条件分支（多条件按顺序匹配）
 ├── 分支一：条件A → 活动1 → 下一条件（是/否）
 ├── 分支二：条件B → 活动2 → 下一条件
 └── 默认分支（无条件，所有条件不满足时走它）
 执行活动（可同时执行多项）：
 CRM提醒 / 字段变更 / 短信 / 邮件 / 数据操作 / 发起业务流 /
 数据锁定解锁 / 分配负责人 / 新建任务日程销售记录 / APL代码 / 新建外部通知
```

定时触发参数详解：

```
执行一次：
 执行日期 = 某个日期字段（如"下次跟进时间"）
 执行时间 = 固定时间（如 9:00）
 开始/结束日期 = 单次触发

重复执行：
 执行日期 = 某个日期字段
 执行时间 = 固定时间
 重复方式 = 每天 / 每周 / 每月 / 每年 / 指定天数
 开始日期 = 字段日期的当天
 结束日期 = 不结束 / 指定日期

时点口径：
 当天 / 该日期前 N 天 / 前 N 周 / 前 N 月 / 后 N 天 / 后 N 周 / 后 N 月
```

### 六个高频场景速查（触发方式 × 执行活动）

| 场景 | 何时触发 | 执行的活动 |
| --- | --- | --- |
| 公司要求销售每月最后一周联系客户做关怀，希望系统每月提醒 | 定时触发 | 企信提醒 |
| 来源是市场活动的线索，需要自动进入市场部线索池 | 新建触发 | 数据操作 |
| 新建知识库案例，提交后自动锁定、员工不能修改 | 新建触发 | 数据锁定 |
| 拜访记录中填了下一次拜访日期，需按日期自动生成日程 | 字段更新触发 | 新建日程 |
| 员工新建项目计划表，希望自动为项目参与人员创建任务 | 新建触发 | 新建任务 |
| 订单发货后，自动为收件人推送发货信息 | 字段更新触发 | 短信 / 邮件 / 外部通知 |

| 工作流 | 按预设规则自动执行任务，无需人工干预的流程功能 |

| 作废触发 | 数据被作废时触发工作流 |
| 恢复触发 | 已作废的数据被恢复时触发工作流 |
| 字段更新触发 | 对象某个字段变更时触发，**必须加"某字段变更时"条件** |
| 定时触发 | 按某个日期字段在指定时间自动触发，支持执行一次/重复执行 |
| 发起对象 | 工作流基于哪个对象发起，触发条件和执行活动的可选项都来自它的字段 |
| 添加条件 | 基本信息里的进门条件，与"何时触发"同时满足才执行工作流 |
| 触发操作 | 决定对象同时配了新建审批流时，触发审批流的同时是否也触发工作流 |

| 字段白名单配置 | 入口在工作流管理右上角"全局配置"下，用来给对象放行字段 |
| 统计字段 | 汇总计算出来的字段（如客户名下 KP 联系人数），变更触发前要先加白名单 |
| 引用字段 | 引用其他对象数据的字段，变更触发前同样要先加白名单 |
| 条件分支 | 按多条件顺序分流，可选"下一条件"控制是否继续匹配 |
| 执行活动 | 工作流触发后执行的自动操作，有 CRM 提醒/字段变更/转移/锁定等十几种 |
| CRM 提醒 | 执行活动之一，向相关人员发送 CRM 消息提醒（课程口播也称企信提醒） |
| 数据操作（转移/退回） | 仅线索和客户对象独有——把数据转移到/退回到指定线索池 |
| 公共池 | 线索/客户被转移或退回的目标池，退回会清空负责人 |
| 新建销售记录 | 执行活动之一，在发起对象下创建一条销售记录 |
| APL 代码 | 执行活动之一，执行特定的函数运算，常规配置做不到时用 |
| 新建外部通知 | 执行活动之一，向微信用户或下游伙伴发送通知消息 |
| 执行日志/触发日志 | 企业日志→流程日志下的两类日志，看工作流有没有执行、有没有触发 |
| 更新导入 | 给历史数据触发工作流的方法：导入时勾选"是否触发工作流=是" |
| 下一条件 | 条件分支里的选项，决定满足条件执行活动后是否继续匹配其他分支 |

## 需要注意的点

1. **字段更新触发不加"变更时"条件保存不了**：系统硬性要求，不管下面配了多完整的条件。另外这条条件只是为过校验，**不影响实际触发逻辑**，别把它当成业务判断条件来设计。
2. **统计字段、引用字段、系统预置字段先加白名单**：入口是 工作流管理 → 右上角"全局配置" → 字段白名单配置，把字段加到对应对象下。不加白名单，字段更新触发里根本选不到这些字段，不是系统坏了。
3. **条件和活动的可选项都来自发起对象**：想用别的对象上的字段做条件，先看发起对象上有没有这个字段，没有就得先加字段或用关联/引用字段，否则列表里找不到。
4. **"当天"和"前/后 N 天周月"是两种口径**：回款到期前 15 天提醒，要选计划回款日期 + 前 15 天；选成当天就变成到期当天才提醒，催款就晚了。
5. **执行一次和重复执行别选反**：执行一次跑完就停；重复执行从该日期起按每天/每周/每月一直跑，结束日期选"不结束"就是长期循环，配错会天天发提醒。
6. **一条数据默认只走第一个命中的分支**：想让它继续匹配后面的分支，得把"下一条件"改成"是"（默认否），否则后面的分支永远轮不到。
7. **分支一定要留兜底**：不设条件的分支是默认分支，所有条件都不满足时走它；没有兜底，条件不满足的数据就什么活动都不执行。
8. **历史数据不会因为工作流新建就补跑**：要么工作流支持编辑时触发、再对历史数据做一次编辑更新，要么用更新导入并勾选"是否触发工作流=是"。系统不让批量新建历史数据，是怕瞬间负载太大。
9. **查日志别找错菜单**：是"企业日志 → 流程日志 → 执行日志 / 触发日志"，不是工作流管理里的某一项。要看单条数据，按数据 ID 查最准，ID 从前端详情页 URL 里复制。
10. **提醒人不要硬选某个人**：用数据负责人、部门负责人、角色这类变量，数据在谁手上就提醒谁，人员变动时也不用改工作流。
