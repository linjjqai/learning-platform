# 速览（30 秒看完）

- 客户是已产生直接经济关系的购买方；案例里客户有六类入口——线索转换、自开拓、转介绍、领取已有客户、导入客户、渠道经理开拓经销商，每个入口都要先查重再报备。
- LTC 的本质是推进客户与我们之间关系的改变；线索分 MQL（市场认可）和 SQL（销售认可），SDR 负责产出有效线索，SDR ≠ 电销。
- 客户全生命周期有明确边界：从客户开始了解企业（或企业开始开发客户）起，到业务关系完全终止、相关事项处理完毕为止。
- 案例三条硬时效：VIP 10 天、重要客户 30 天、普通客户 60 天未跟进即回收进公司资源池；员工手上客户最多 50 个；无需求退回"暂无需求池"。
- 两类客户靠"布局 + 业务类型"在同一个客户对象里分型：建两套布局、两个业务类型，业务类型按角色分配布局，前端新建先选类型。
- 配置顺序照课件九步走：对象配置 → 查重规则 → 保有/收回规则 → 客户规则设置 → 成交规则 → 非公海收回规则 → 公海配置 → 保有量上限 → 外勤规则。
- 回收分两套：非公海管刚建、还没进公海的客户，按优先级 1/2/3 逐条匹配，一个部门只能配一条；公海管被回收后的共享客户。
- 两个容易漏的开关：回收规则的"包含已过去天数"决定改规则后剩余天数是否重算，"成交后占有保有量"决定成交后还占不占名额。

## 核心要点

- **什么是客户**：线索是潜在客户，客户则是双方已经产生直接经济关系的对象，可以是个人、团体或企业——他购买你的产品或服务来满足某种需求。所以判断客户的关键不是"有没有联系过"，而是"有没有真实的经济关系"。
- **客户的六类来源**：课件案例里列全了入口——销售线索转换、自开拓、转介绍、领取已有客户（从公海领取）、导入客户，以及渠道经理开拓经销商（由销售助理导入系统）。不论走哪个入口，建客户前都要查重、报备；客户建好之后，最终目的都是转成商机、达成成交。
- **LTC 与五个必懂名词**：LTC 的本质是推进客户与我们之间关系的改变。SDR 是销售开发代表，负责清洗市场线索、主动外呼，产出有效线索；SDR ≠ 电销，SDR 的职责是输出有效线索，电销的任务是电话成交。MQL 即市场认可线索（营销投入基础上表现出兴趣、更容易转成客户的线索）；SQL 即销售认可线索，一条线索被标记为 SQL，就意味着销售团队已把它视为潜在客户。ROI 是投资回报率；CPQ 是配置、定价、报价的功能组合，用于产品配置和报价比较复杂的场景。
- **客户全生命周期的定义**：从客户开始对企业进行了解、或企业欲对客户进行开发开始，一直到客户与企业的业务关系完全终止、且与之相关的事都处理完毕为止，这段时间就是客户全生命周期。阶段上走：客户开发 → 客户洞察、客户培育 → 客户健康 → 流失预警挽留 → 客户流失 → 流失赢回，全程伴随客户关怀与服务。
- **客户管理体系的闭环**：客户进入系统后先建客户档案，再做客户画像（客户特征）、客户分级（重要客户／一般客户等），然后分配销售跟进、促成成交，成交后进入客户服务；服务不到位就走到客户预警、流失预警与挽回，挽回成功即二次成交，失败则流失。系统（CRM）是把这条链路线上化的载体。
- **案例：两类客户 + 三条硬时效**：某饮品公司开放两种卖法——销售通过"开拓客户"直接卖产品，渠道经理通过"开拓经销商"卖产品。获取客户信息后必须查重，避免重复新建；客户负责人要持续跟进，VIP 客户 10 天内、重要客户 30 天内、普通客户 60 天内至少跟进一次，否则客户被回收到公司资源池；跟进中若判断客户无需求，就把客户转到"暂无需求池"。案例同时限定员工负责的客户最多 50 个。
- **经销商拜访四动作**：渠道经理开拓的经销商分配给销售后，销售要持续拜访，并在系统里完成签到、店铺（门头）拍照、填写沟通记录、签退四个动作。这几个动作构成一次完整拜访的留痕，也是后面外勤配置的原型。
- **用布局 + 业务类型做分类创建**：两类客户要收集的信息不同，所以在对象管理里先建两套布局（客户布局、经销商布局），再建两个业务类型（如"自开拓客户""经销商"），业务类型里按角色分配对应布局；前端新建客户时先选业务类型，新建页字段就跟着变。布局可从已有布局复制、复制空白页或直接新建，未开"新建／编辑页面布局"时与详情页共用一套布局。
- **查重设置**：在客户对象下打开查重设置，可设定按哪些字段（如客户名称）查重、精确查询还是模糊匹配、为空是否参与、是否对已作废数据查重，并可联合查重销售线索。前端新建客户时会自动提示重复，查重确认后即可做"报备"，把这条客户锁给自己。
- **外勤三段配置与误差限制**：先在"外勤设置"里加外勤字段、外勤动作（如门头拍照、沟通记录），再建外勤类型把这些动作串成一条拜访流程（可设节点顺序、是否自动跳转），最后建外勤规则限定谁能用这个类型。外勤规则还可按客户地址判断定位范围，超出设定范围（如 200 米）就不允许签到或签退，保证拜访真实到店。
- **客户保有量与"不在规则里就不受限"**：分两步——先做"保有量定义"，即满足什么条件才算占用保有量（如按客户级别、成交状态、所属公海判断）；再建"保有量规则"，按人员或部门设定范围，配置"客户级别等于 VIP 的保有 5 个"之类的条件。客户保有量上限就是员工可以保有的最大客户数；**不在规则里的部门或员工没有保有量限制**。设上限的目的是让销售能更细致地照顾每个客户、避免客户过多导致跟进做不扎实。
- **公海：新建、成员与分配领取**：先在"公海管理"里新建公海（如公司资源池、暂无需求池），再添加公海成员（内部员工、伙伴），并选择分配领取规则——"成员可见可领取，管理员可分配"或"成员不可见，仅管理员可分配"。不属于任何公海的客户称作"非公海客户"。公海内还可设保有规则（每个成员最多保有／领取多少条，分企业级与个人级）、转移退回规则和共享规则（客户负责人或所属公海变化时，团队成员如何变化）。
- **公海回收规则**：可设自动回收或不自动回收，条件是"N 天没有新的成交""N 天未跟进"等，回收目标是本公海或其他公海，并可提前 N 天提醒客户负责人、相关团队成员和外部负责人。
- **非公海回收规则与优先级**：客户刚创建时所属公海为空，走的是"非公海客户收回规则"。案例里按优先级 1/2/3 配：VIP 客户 10 天未跟进 → 自动回收到"公司资源池"，提前 5 天提醒；重要客户 30 天、普通客户 60 天同理。多条规则按优先级从上往下逐条比对客户范围，先命中先执行（先判优先级 1，不满足再看 2，以此类推）；同一部门只能设置一条回收规则，已被占用的部门新建时选不到。此外还可以对部门设收回规则、对部门设提醒信息。
- **回收规则上的两个开关**：**包含已过去天数**——修改当前收回规则时，决定收回剩余天数要不要把已过去的天数算进去、是否重新计算；**成交后占有保有量**——勾选则客户成交后仍占用保有数量，不勾选则成交后释放名额。
- **为什么区分公海与非公海**：销售辛苦挖来的客户是他的私有资源，如果一建进系统就丢进公共池给别人看，会打击积极性，所以刚创建的客户先落在"非公海"，只有他本人负责。但客户长期不跟进就是资源浪费，于是用回收规则（如 60 天无操作）把客户收进公海，让更有精力的人接手。
- **无需求退回工作流**：用业务工作流实现——发起对象选"客户"，触发方式选"字段更新触发"，条件是"客户.是否有需求 变更后 = 否"（还需加一个变更前条件，否则无法启用），执行动作选"数据退回"：客户已有公海的退回原公海，没有公海的直接退回指定公海（如无需求公海）。
- **允许修改客户名称**：在客户规则设置里勾选后，客户负责人可在前端改客户名称；不勾选则只有 CRM 管理员能在【管理-数据维护工具-全部客户】里改。该页还有"新建编辑客户页面，当客户名称与系统中已有客户名称重复时进行提示"；多组织下客户只能继承主客户名称，此配置失效。
- **客户跟进规则**：跟进行为（如发销售记录、更新客户信息、创建商机／订单，**可多选**）会更新客户的"最后跟进时间"，最后跟进时间又直接影响客户是否被回收。认定成交的动作（商机赢单、销售订单确认、新建合同，**单选**）触发时，会更新客户的最后成交时间、最后跟进时间、是否成交、剩余保有时间等字段。演示中在详情页新建一条联系人，客户的最后跟进时间立刻刷新为这个时间点。
- **成交规则**：分预置成交规则与自定义成交规则，二者只能选其一。预置规则下，销售团队成员对客户做指定操作，客户状态会变为"已成交／多次成交"，最后成交时间自动更新——例：新建销售订单并且审批通过后，系统默认该订单已成交。自定义规则用于历史数据迁移这类特殊情况，支持通过新建／更新导入流程后动作变更。前端详情页不随手改成交状态；确需修改，管理员在【CRM设置-数据维护-全部客户】改。
- **客户审批与作废限制**：客户审批支持的触发动作有新建、作废、更换负责人、编辑、领取、退回六种。**审核中的数据不能被作废**，只有撤回审批流程或审核通过之后才可以作废——客户状态在审核当中，管理员也不能随时作废该客户。
- **更换负责人：连带对象、权限与离职场景**：更换负责人时可连带更换商机、联系人、销售订单、合同的负责人，但必须拥有这些对象的相应权限，否则整单操作失败；数据处在审批流中时被锁定。换完后还可以选择把原负责人移除相关团队或变更为普通成员。员工离职要把客户转给别人，走【管理后台-数据维护工具-全部客户-筛选停用员工】，或用迁移工具（可立即执行或定时，默认 22:00）。
- **场景补充：大区公海与"成交也会被回收"**：北京某公司分华中、华南两个销售大区各自管理，公司在大区放资源客户供员工自领，每个成员最多领取 100 个。领取的未成交客户 30 天未跟进，第 25 天给销售提醒，不跟进就自动回收，回收后清空客户负责人及相关团队成员，供其他人领取；已成交客户 90 天没有新成交也会自动回收，提前 30 天提醒客户负责人。员工自开拓的客户录进系统后自己直接跟进，30 天未跟进自动回收到华中销售大区，供他人领取。
- **客户群**：客户负责人和相关团队成员才会自动进入客户群，其他协作角色不会自动进群。

## 结构与流程

客户从进入到成交的完整链路（对应案例的九步落地）：

```
① 进入 ── 新建客户
 来源：线索转换 ／ 销售自主开拓 ／ 渠道经理开拓经销商（销售助理导入）
 前置：查重 → 报备（避免重复建客户）
 分型：业务类型（自开拓客户 / 经销商）＋ 布局 → 决定新建页与详情页字段

② 归属 ── 负责人 + 非公海
 新建时负责人就是创建人，所属公海为空 → 走"非公海客户收回规则"
 保有量：每人客户数上限（案例：员工最多 50 个；可细到 VIP 最多 5 个）

③ 跟进 ── 跟进行为 → 最后跟进时间
 联系人 / 回款 / 退款 / 客户 / 销售订单 的新建、关联、发布销售记录
 VIP 10 天 ／ 重要 30 天 ／ 普通 60 天 未跟进 → 回收
 经销商：签到 → 门头拍照 → 沟通记录 → 签退（外勤类型）

④ 回收 ── 进公海
 自动回收 → 本公海 或 指定公海（公司资源池）；可提前 N 天提醒
 多条回收规则按优先级 1 → 2 → 3 逐条匹配，先命中先执行

⑤ 领取 / 分配 ── 公海成员
 成员可见可领取 ／ 成员不可见，管理员分配
 领取上限、N 天内不可重复领取、转移与退回规则、共享规则

⑥ 无需求 ── 暂无需求池
 "是否有需求"由是变更为否 → 工作流触发 → 退回指定公海

⑦ 团队协作 ── 相关团队 / 客户群
 负责人与团队成员自动进入客户群；换负责人时可移除或降为普通成员

⑧ 转移（更换负责人） ── 连带对象
 客户 + 商机 + 联系人 + 销售订单 + 合同 可一并更换，需对应对象权限
 工具：数据维护工具-全部客户（批量更换）／数据迁移工具（立即或定时，默认 22:00）

⑨ 成交 ── 成交状态
 预置成交规则（按业务动作自动判定，不可手动改）
 自定义成交规则（导入更新回填成交状态与最后一次成交时间）
```

各环节的配置链路（后台从哪进、按什么顺序配）：

- **课件九步顺序**：对象配置 → 查重规则 → 保有／收回规则 → 客户规则设置 → 客户成交规则 → 非公海收回规则 → 公海配置 → 保有量上限 → 外勤规则
- **对象与分型**：对象管理 → 布局（调整布局 → 新建，复制已有／复制空白／直接新建）→ 业务类型（新建，命名 → 选适用范围 → 按角色分配布局）→ 布局规则可批量调整
- **查重**：对象管理 → 客户 → 查重设置（打开开关、设查重字段、精确／模糊、是否对已作废数据查重、联合查重销售线索）→ 前端"查重小工具"＋报备
- **外勤**：外勤设置 → 外勤字段 → 外勤动作 → 外勤类型 → 外勤规则（适用范围、允许误差 200 米、超范围不允许签到／签退）
- **保有量**：客户和公海管理 → 客户保有量 → 保有量定义 / 保有量规则（人员或部门范围 + 条件 + 数量上限）
- **公海**：客户和公海管理 → 公海管理（新建公海 → 加成员 → 分配领取规则 → 保有规则 → 转移退回规则 → 共享规则 → 回收规则）
- **回收**：公海管理内配"公海回收规则"；非公海侧配"非公海客户收回规则"（按优先级排序，一个部门只能一条）
- **跟进与成交**：客户跟进规则（跟进行为清单）→ 客户成交规则（预置／自定义二选一）
- **批量运维**：管理后台 → 数据维护工具-全部客户（批量换负责人）／迁移工具（迁移负责人）

## 术语表

| 术语 | 含义 |
| --- | --- |
| 客户 | 通过购买产品或服务满足需求、与企业产生直接经济关系的个人、团体或企业 |
| 线索 | 尚未产生直接经济关系的潜在客户，经转换后生成客户、商机、联系人 |
| LTC | 从线索到现金的完整经营链路，本质是推进客户与我们之间关系的改变 |
| SDR | 销售开发代表，负责清洗市场线索、主动外呼，产出有效线索；不等于电销 |
| MQL | 市场认可线索（营销合格线索），表现出对产品兴趣、更容易转成客户的线索 |
| SQL | 销售认可线索，被标记为 SQL 即意味着销售团队已将其视为潜在客户 |
| ROI | 投资回报率 |
| CPQ | 配置、定价、报价的功能组合，适用于产品配置与报价复杂的场景 |
| 客户生命周期 | 开发、洞察、培育、健康、流失预警挽留、流失、流失赢回的完整过程，全程伴随客户关怀 |
| 客户画像 | 客户进入系统后对其特征、规模、合作意向等信息做的结构化描述 |
| 客户分级 | 按重要程度划分客户（重要客户、一般客户、VIP 客户等），决定跟进时效与回收规则 |
| 布局 | 客户新建页／详情页的字段与组件排布方案，可按客户类型分别定制 |
| 业务类型 | 客户对象下的分类维度（如自开拓客户、经销商），决定按角色使用哪套布局 |
| 智能表单 | 除 CRM 对象新建之外的另一种客户录入方式 |
| 查重 | 新建客户时按设定字段比对已有数据，避免重复建档；确认后可报备 |
| 报备 | 查重后把客户归属锁定给开拓人，防止被他人重复创建 |
| 外勤动作 | 拜访中要执行的具体动作，如签到、门头拍照、填写沟通记录、签退 |
| 外勤类型 | 由若干外勤动作串成的拜访流程模板，可设节点顺序与必填 |
| 外勤规则 | 限定外勤类型的适用范围与定位误差（如超出 200 米不允许签退） |
| 客户保有量 | 定义哪些客户占用保有量，并给个人／部门设定客户数量上限；不在规则内的部门或员工不受限 |
| 剩余保有时间 | 客户详情页字段，由成交动作或规则更新，反映还剩多久被回收 |
| 非公海 | 客户刚创建、所属公海为空的状态，只归创建人本人负责，又称"非公海客户" |
| 公海 | 回收后供成员共享领取的客户池，如公司资源池、暂无需求池 |
| 公司资源池 | 案例中承接超期未跟进客户的公共公海 |
| 暂无需求池 | 承接被判定为无需求客户的公海，由退回工作流自动投放 |
| 回收规则 | 满足条件（N 天未跟进、N 天无新成交）自动把客户收回公海的规则 |
| 包含已过去天数 | 收回规则上的开关，决定修改规则后剩余天数是否把已过去的天数算进去重算 |
| 成交后占有保有量 | 收回／保有规则上的开关，勾选则客户成交后仍占用保有数量 |
| 优先级匹配 | 多条回收规则按 1→2→3 顺序逐条比对客户范围，命中即执行 |
| 领取规则 | 公海成员的领取方式与限制，如随时领取、N 天内不可重复领取 |
| 转移／退回规则 | 领取后能否把客户转到别的公海、能否退回本公海 |
| 共享规则 | 客户负责人或所属公海变化时，相关团队成员等如何随之变化 |
| 跟进行为 | 会刷新客户"最后跟进时间"的动作，如发销售记录、更新客户信息、创建商机订单，可多选 |
| 最后跟进时间 | 客户详情页上的字段，由跟进行为更新，是回收规则的判断依据 |
| 预置成交规则 | 系统内置的成交判定，触发后客户状态变为"已成交／多次成交"，成交时间自动更新 |
| 自定义成交规则 | 用于历史数据迁移等特殊场景，通过新建／更新导入流程后动作变更 |
| 多次成交 | 客户成交后仍继续产生成交时进入的状态 |
| 客户群 | 客户负责人与相关团队成员自动进入的协作群 |
| 数据维护工具 | 管理后台"全部客户"入口，可批量操作更换负责人、修改成交状态与客户名称 |
| 迁移工具 | 管理后台工具，按动作类型迁移负责人／归属部门，支持立即或定时执行 |

## 需要注意的点

1. **线索与客户的边界要先分清**：线索只是潜在客户，做的是分配、回收、转换；客户已经产生直接经济关系，做的是公海回收、保有量、跟进时效、成交状态。两者机制相似（都有分配回收），但对象不同，别把线索的规则套到客户上。
2. **新建客户默认是"非公海"**：刚创建的客户所属公海为空，走"非公海客户收回规则"；只有被回收或主动退回后才进公海。配规则时如果只配了公海侧，刚建的客户永远不会被回收。
3. **一个部门只能有一条回收规则**：新建时如果发现某些部门选不到，不是系统出错，而是这些部门已在别的回收规则里被占用。改规则要在原规则上编辑。
4. **回收规则是有顺序的**：多条规则按优先级从上往下匹配客户范围，先命中先执行，所以要把更严格的（VIP 10 天）放在前面，别把"全部客户"放在第 1 条。
5. **成交状态别在前端手改，但管理员能改**：预置成交规则下详情页没有改成交状态的入口，这是有意为之——手改会污染数据统计。确需修改走【CRM设置-数据维护-全部客户】；历史客户用"自定义成交规则 + 导入更新"，且导入时记得同时更新"最后一次成交时间"，否则会影响自动回收。
6. **审核中的数据不能作废、也不能编辑**：要撤回审批流程或审核通过后才能操作，管理员同样不能随时作废审核中的客户。客户审批的触发动作有新建、作废、更换负责人、编辑、领取、退回六种，配审批流时别漏了领取和退回。
7. **更换负责人连带对象要权限**：勾选连带更换商机、联系人、销售订单、合同负责人时，必须同时具备这些对象的权限，否则整单操作失败。员工离职转客户时，在"全部客户"里按"停用员工"筛选，否则按姓名找不到人。另外本课**没有讲"客户合并"**，不要和这里的"更换负责人／转移"混为一谈。
8. **保有量不是全公司默认生效**：不在保有量规则里的部门或员工没有上限，配完要回头确认覆盖范围，否则会出现"以为控了 50 个、其实有些团队完全没限"。
9. **成交不等于安全**：已成交客户 90 天没有新成交照样会被回收，提前 30 天提醒；领取的未成交客户是 30 天未跟进、第 25 天提醒。回收后客户负责人及相关团队成员会被清空，再供他人领取。
10. **改收回规则前先想清楚"包含已过去天数"**：它决定修改规则后收回剩余天数要不要把已过去的天数算进去、是否重新计算，客户对剩余天数有争议时先查这个开关。
11. **"成交后占有保有量"要想清楚再勾**：勾上则成交客户继续占销售的名额，影响他还能领多少客户；不勾则成交后释放名额。
12. **功能回顾里外勤被归在"考勤"名下**：课件把外勤动作／外勤类型／外勤规则列在"考勤"这一项下，实际配置入口是外勤设置，别在考勤模块里找。
