# 速览（30 秒看完）

- 线索是与客户初次接触拿到的原始信息，需求匹配度、信息准确度都还没核实，本质就是"潜在客户"。
- 线索管理在 LTC（线索到回款）里只管一段：获取 → 清洗评估 → 分配 → 商务跟进 → 转化，转化后交给客户、商机、订单。
- 企业要做线索管理是四道坎：获客成本逐年涨、海量线索靠人工洗识别难、市场与销售协作难、投放效果分析难。
- 线索进入四条路：手动新建、Excel 导入、手机端扫名片、智能表单（二维码 / 链接 / 网页嵌入代码），智能表单提交即生成线索。
- 查重分三套：查重设置管新建与扫名片，唯一性规则管导入 / 智能表单 / API，查重工具在录入前单条查；命中后打【重复】标签，再按规则归集或只生成行为记录。
- 打分器按字段条件打分，案例里的配法是规模 >50 人 +2、有过合作 +2、经营良好 +3、信息完整 +1；一个对象只能一套规则，最多 10 个指标字段、2 个结果字段。
- 线索池是装线索的容器：池里有管理员、协助人、成员三种角色，配领取上限、超时提醒、收回规则把线索推着走，区域分配交给工作流。
- 收回看的是"跟进行为"而不是打过电话；已转换的线索会锁定，不能收回、不能换负责人，作废还要有解锁权限。

## 核心要点

- **线索在 LTC 里的位置**：LTC（也叫 L2C）是从线索到回款的全过程，课件强调它的本质是推进客户与我们之间关系的改变。市场人员通过多种营销通路获取信息，经线索自动化培育形成市场认可线索（MQL），再由销售跟进确认为销售认可线索（SQL），最终转化为客户、商机、订单、签约与回款。负责前期清洗的岗位是 SDR（销售开发代表），产出的是 MQL；SDR 不等于电销，电销的任务是电话成交。本课只讲线索这一段：进入 → 分配流转 → 跟进转化。
- **什么是销售线索**：销售线索是与客户初次接触获得的原始信息，可以是展会拿到的名片、推广活动留下的电话号码，也可以是会议、广告、外部购买等渠道获得的客户简单信息。简单说，需求匹配度、信息准确度还没有完全核实的潜在客户就叫销售线索。举例：有人在公司官网咨询并留下姓名和联系方式，这条信息就成为一条线索，公司再把它分给某位销售同事进一步联系、确认需求与购买意向。
- **线索管理管什么**：一头是市场侧的线索获取，一头是线索进入系统后的分配流转、销售跟进与转化，管理者再针对整个线索管理全流程做数据分析——三段合起来才是完整的线索管理，而不是只管"把线索录进来"。
- **为什么企业要做线索管理（四道坎）**：① 获客难——流量红利渠道不断变更、获客成本逐年上升，需要判断哪条渠道的投入回报更高；② 识别难——海量线索多以电话外呼的方式人工过滤，成本高、效率低、信息获取片面，影响最终判断；③ 协作难——各团队分工职责是否明确、线索跟进流程是否清晰、MQL 与 SQL 的考核标准是否一致；④ 分析难——数据分散、缺分析工具，营销效果无法闭环，企业缺少判断最佳实践的依据。
- **五个管理方面与四重意义**：五个方面依次是营销获客（快速收集、降低整理成本）、识别与评估（身份、重复性、质量评估，释放人工压力、规避撞单）、跟进培育（分配跟进、低意向线索回收再培育，重点是分配流转效率）、转化（高意向线索转客户，重点是分给能力与精力都匹配的人）、数据分析（业务数据与员工效能，重点是统计及时准确）。对应的四重意义是：优化营销和销售流程，让跟进可追踪、可分析员工转化效率与成交率；提升线索利用效率与转化率，靠线索池分配规则、超时提醒、收回规则；降低获客成本、提高 ROI；增强客户联系与黏性。数据分析阶段的效果示例图，就是把这些指标落到线索来源分析、来源趋势、每月转化率、销售线索排行榜、线索无效原因、市场活动 ROI 等报表上。
- **全流程五个阶段**：线索进入（展会活动、搜索引擎、400/官网咨询、BD 合作等）→ 清洗评估（查重与质量评估，便于后续分配）→ 分配（按条件自动快速分配，减少人工参与）→ 商务跟进（跟进并回收长时间未跟进的线索）→ 转化（线索终结，标记线索状态，便于后期分析）。流程图上线索质量是自动识别的：高质量按条件分配、交销售跟进；低质量线索再次进入培育线索池，等培育成熟再来一轮；始终不成立的走无效终结。
- **线索进入的四种方式**：手动新建、Excel 导入、手机端扫名片（移动端能力，课上不展开）、智能表单。这一阶段的重点管理内容是确保线索快速收集，降低线索整理的时间和人力的成本。手动新建即在 CRM 中搜索"销售线索"后点右上角新建，维护姓名、来源、联系方式、具体需求等信息后提交；批量导入则先选导入类型（添加数据 / 更新现有数据），下载数据模板填好必填项后再拖拽上传，点右上角开始导入。
- **智能表单收集线索**：入口在 管理后台 - 对象管理 - 预设对象管理 - 智能表单。新建后先选基于哪个对象创建，本课选销售线索；在左侧点选字段放进表单，可选字段都来源于该对象已有的字段，缺字段要先回对象里新建；必填字段默认会体现在表单中、无法取消；标了"预设置项"的字段仅供内部填写；选择类型的字段可以设默认值；还能设表单填写的截止日期。发布有三种形式：二维码（放在展会门口、海报）、链接（随广告或活动资讯推送给客户）、网页嵌入代码（嵌到自家网页）。客户填写完成即自动在系统里生成对应的销售线索。
- **查重规则的设置**：入口在 管理 - 对象管理 - 预设对象管理 - 销售线索 - 查重设置。开启查重后可指定参与比对的字段（例如姓名与电话都一致才算重复），设置匹配控制以决定空值字段是否参与比对，可选择不对已作废数据查重；还能设定查重结果最多显示几条、显示哪些字段（如姓名、公司、电话），供销售在提醒弹窗里核对。
- **查重的三种入口**：精确查重命中时前端提示"线索已存在，无法保存"，点查看可直接看到那条重复线索；模糊查重（例如只按公司名比对）只提示"系统中存在相似的销售线索"，并给出「继续保存」，是否保存由销售自行判断。录入前还可以在 CRM 首页 - 工具 - 查重工具中主动查，选"销售线索"页签、填入查重内容，看系统里是否已有重复及其姓名、公司、电话。批量导入、智能表单、API 对接这类场景则遵循"唯一性规则"，在销售线索对象下配置生效场景与比对字段，命中后导入时记录重复并阻断。
- **重复线索管理**：位置在 对象管理 - 预设对象管理 - 销售线索 - 重复线索管理。识别发生在新建、编辑线索保存之后，系统按查重规则自动比对，重复数据在列表页和详情页都会带【重复】标签，再按处理规则做合并。新建处理规则时选择触发来源（导入、智能表单、编辑）与筛选条件、关联查重规则，再添加处理规则：可以规集到已有线索、在已有线索下生成行为记录，或执行自定义函数，用自动化减少人工判断。规集时可指定多条重复时归集到创建时间最早的那条。两者的区别是：规集会生成一条新线索挂到原线索下面，生成行为记录则不产生新线索，只对原线索做字段更新与跟进记录，字段可按类型选择覆盖或拼接。
- **清洗评估就是打分器**：线索的清洗评估指根据线索的不同属性做多维度打分，科学评估线索质量，释放员工手动操作的压力、提升整体流程效率。入口在 管理 - 业务规则管理 - 打分器规则设置，新建规则分三步：填基本信息（规则名称、评分对象、是否实时计算评分）、设指标规则（针对对象本身字段设条件与分值）、设评分结果（可直接给对象字段赋值，或按分数区间给高中低赋值）。案例1 的四条指标就是典型配法：公司规模大于 50 人 +2 分、有过过往合作经历 +2 分、经营状况良好 +3 分、企业信息填写完整 +1 分，分数落到线索上作为分配参考。
- **打分器的七条限制**：一个对象只能有一套打分规则；规则冲突时按设置先后顺序生效；最多可设 10 个指标字段；分数须大于等于 0 且最多两位小数；指标字段只支持单行/多行文本、数字、金额、单选、多选、布尔值、手机、邮箱；最多两个结果字段（类型限单选、多选、数字、金额、百分数、布尔值）；除销售线索外，客户、联系人、商机等预设对象与自定义对象也可配打分规则。
- **线索池与三种角色**：线索池可以理解为装线索的容器，池里的线索一切都受线索池规则管控。池可设管理员（可配置整个池、做分配）、管理员协助人（只能在前端做分配、收回等操作，不能编辑池配置），并维护线索池成员——只有作为该池成员，才能领取或跟进池里的线索。
- **分配领取规则与负责人规则**：分配领取规则二选一——成员可见可领取 + 管理员可分派（两条路都通），或成员不可见、仅管理员可分派（成员根本看不到池里的线索）；这个"池类型"选择直接决定了销售能不能自己领。负责人规则用来处理新进入线索的负责人归属：满足条件时清空当前负责人，以便按池的自动分配规则重新分配（例如市场一次导入上千条，负责人默认是导入人，必须清空后才能分给华北销售）；也可设条件不清空、由原负责人继续跟进，且不调用分配规则。
- **提醒、领取上限与分配规则**：新线索提醒可给管理员推送待办，便于及时分配，也可以设置为不提醒；线索领取上限可限制每个员工最多领取多少条，保证资源分配与员工精力匹配，前端提示的说法是"已达到线索保有量上限"；领取规则可限制 30 天内不能重复领取同一条线索（因未按时跟进被收回过，就不能反复抢）。分配规则支持按条件筛选后指定给某人，也支持循环分配（内部员工循环，或按部门等条件循环）。超时提醒可分别设置新线索进入后 X 小时未分派提醒线索池管理员、分配给销售后 X 小时未跟进提醒线索负责人；管理员分派时只能选到池成员，非成员不会出现在可分派名单里。
- **收回规则与跟进行为**：收回规则按范围 + 条件触发自动收回，例如"领取后 30 天未跟进，自动回收到本线索池"，用于保障跟进效率、避免资源沉睡；回收目标可以是本线索池，也可以是其他线索池。什么算跟进由"线索跟进规则"定义：点击跟进、发邮件、转换、无效、分配、发布销售记录、转移、领取等勾选的行为才算已跟进，规定时间内一个都没做就算未跟进、会被收回；到期前还可勾选允许申请延期，由管理员审批。此外还可授权成员领取后把线索转移或退回其他线索池，用清空规则处理负责人变更的连带关系，用显示设置决定未分配线索对池成员公开哪些字段（如只公开姓名、公司，管理员则可见全部）。
- **工作流做区域分配**：入口在 后台管理 - 流程管理 - 工作流管理。新建"线索分配"工作流，发起对象选销售线索、触发时机为新建（可选数据提交时触发或审批通过后触发），再按分支条件（区域等于华北 / 华南 / 华东）执行数据操作，把线索转移到对应线索池（也支持退回线索池、分配指定负责人）。线索进池后再由各池自己的规则管控分配与流转，每个池的规则可以不同、互不影响。案例1 就是这条路：展会、搜索引擎、400/官网咨询进来的线索先查重、再打分，然后按区域自动进华东 / 华南 / 华北线索池，由池管理员分配；销售领取后 30 天未跟进，回收到原池。
- **商务跟进与线索处理状态**：销售领取或收到线索后，依据详情页里的信息联系客户，联系完发布销售记录，线索状态随之变为"跟进中"。线索的处理状态有四种：跟进中（跟进行为可定义）、转换（转换要求可定义，是否必须同时转客户 / 联系人 / 商机）、无效（标记无效状态）、退回（退回原线索池）。跟进中发现意向较高、可转化，就点转化，可同时转成客户、联系人、商机，转换时还支持触发审批流；若意向很低或没有转换空间，则执行无效、退回或转移到其他线索池。线索池里的线索在销售线索对象列表里同样能看到。
- **案例2：多级回收池 + 黑名单**：培训行业软件公司由智能表单和 400 电话收集线索，按地区用工作流分到各地区"电销线索池"，池内销售可见可领取、管理员可分派。领取或分派后 2 天未转化，自动回收到"电销第一次回收线索池"；再过 2 天仍未转化，回收到"电销第二次回收线索池"，该池支持随时领取、2 天仍未转化再收回，且只允许本池成员退回或转移进来。跟进过程中被标记为黑名单的线索，由字段变更触发工作流，自动进入"黑名单线索池"，不再参与流转。
- **已转换的线索是锁定的**：线索一旦转换会自动锁定——不能再分配给其他负责人，也不能被收回；要作废必须给操作人线索的解锁权限；但已转换完的线索是可以删除的，删除后新建/转换又会撞上查重，需要去回收站彻底清掉。
- **最后跟进时间与超时判定**：最后跟进时间不会因为随便点一下而刷新，只有在 管理 - 线索和线索池管理 - 跟进规则 中满足条件时才变化。已经超时的线索，补写一条销售记录就能变回未超时，这个动作同时也会让最后跟进时间更新。
- **作废不等于删除**：作废的线索还在回收站里，所以作废后再新建或转换同一条线索会提示"已存在"，要让管理员去回收站恢复或彻底删除。另外，线索挂着审批流程、或状态已是"已转换"时，作废删除会直接提示"无此操作的数据权限"，属于系统的正常限制，不是权限配错了。
- **谁能改线索池规则**：CRM 管理员、线索池管理员，以及企业自定义的、被授予"线索和线索池管理"模块权限的管理员这三类人；普通池成员只能在自己的池里领取、跟进，改不了池规则。
- **两个场景的改造思路（场景思考）**：产品线场景——按产品线各建一个线索池、对应销售总监做池管理员、市场导入时直接选目标池、池内设 24 小时未处理自动收回由管理员重新分配，最后用报表统计不同活动的线索转化率与成交情况；线下交流会场景——用智能表单自动收集姓名、职务、手机号、区域、行业、规模，用工作流按区域自动分配，再拿历史成交客户反推打分维度（成交率高的行业、来源、客户规模），先自动做一轮质量初评。

## 结构与流程

线索全生命周期（获取 → 清洗评估 → 分配 → 跟进 → 转化/归档）：

```
① 获取 展会/沙龙/交流会 · 搜索引擎 · 官网表单 · 400 电话 · 客户转介绍
 │ 手动新建 / Excel 导入 / 名片扫描 / 智能表单（二维码 · 链接 · 网页嵌入代码）
 ↓
② 清洗评估 查重设置（新建、扫名片时拦）· 唯一性规则（导入/表单/API 时拦）· 查重工具（录入前主动查）
 重复线索处理：规集到已有线索 ／ 原线索下生成行为记录 ／ 执行自定义函数 →【重复】标签
 打分器：按字段条件多维度打分 → 线索评分（一个对象仅一套规则，最多 10 个指标字段、2 个结果字段）
 ↓
③ 分配 工作流（按区域等条件自动转移）→ 线索池
 池内：管理员分派 ／ 成员领取 ／ 循环分配 ／ 领取上限（保有量）+ 30 天内不可重复领取
 ↓
④ 跟进 领取或收到线索 → 联系客户 → 发布销售记录 → 状态「跟进中」
 超时未分派 / 未跟进 → 超时提醒 →（触发收回规则）→ 回收到原池或指定池 → 再分配
 跟进规则决定什么算跟进，也决定最后跟进时间何时刷新
 ↓
⑤ 转化/归档 转化：客户 + 联系人 + 商机（转客户 = 在系统里新建一条客户信息），可触发审批流
 转换后线索自动锁定：不可收回、不可换负责人，作废需解锁权限，但可以删除
 无效 / 退回 / 转移 → 标记线索状态，供后期数据分析
```

线索池的规则构成：

```
线索池
├─ 角色
│ ├─ 线索池管理员 配置整个池、执行分派
│ ├─ 线索池管理员协助人 仅前端分配/收回，不能改池配置
│ └─ 线索池成员 只有成员才能领取、跟进池内线索
├─ 分配领取规则（池类型）
│ ├─ 成员可见、可领取 + 管理员可分派
│ └─ 成员不可见、仅管理员可分派
├─ 负责人规则 满足条件时清空负责人（交回池规则分配）／ 不清空（沿用原负责人，不调用分配规则）
├─ 新线索提醒 新线索进池推送待办给管理员，也可设置为不提醒
├─ 领取上限 + 领取规则 每人最多领取条数（保有量）／ 30 天内不可重复领取同一条
├─ 分配规则 按条件筛选后指定专人 ／ 循环分配（员工循环、按部门等条件）→ 只能分给池成员
├─ 超时提醒 未分派提醒管理员 ／ 已分派未跟进提醒负责人（可同时提醒管理员）
├─ 收回规则 范围 + 条件 → 自动收回本池或其他池；回收依据「线索跟进规则」里勾选的跟进行为
│ 支持申请延期（管理员审批）；已转换的线索不参与收回
├─ 转移/退回规则 成员领取后能否把线索转移、退回其他线索池
├─ 清空规则 负责人清空时是否连带清空外部负责人等
└─ 显示设置 未分配线索对成员公开哪些字段（管理员可见全部）
```

## 需要注意的点

1. **线索不等于客户**：线索是需求匹配度、信息准确度都未完全核实的原始信息；"转客户"在系统里的含义是新建一条客户信息，不是把线索记录改个名字。
2. **三套查重机制各管一段，别只配一套**：查重设置管手工新建与名片扫描，唯一性规则管导入、智能表单与 API，查重工具是录入前的主动查询。只配了查重设置，批量导入照样可能灌进大量重复数据。
3. **精确查重和模糊查重的"硬度"不同**：精确命中直接提示无法保存；模糊命中仍会给「继续保存」按钮，由销售自行判断。给客户讲解时别说成"系统一律不让存"，那是两回事。
4. **线索转化或分配后仍会留在线索池里**：线索池是存放容器，不会因为线索被分配、跟进或转化成客户就消失，它依然受该池的规则管控——这正是新手最容易问的"为什么转化了还在池里显示"。同一批线索在销售线索对象列表里也能看到。
5. **收回的依据是"跟进行为"，不是"打个电话"**：只有产生线索跟进规则里勾选的跟进行为（如发布销售记录）才算已跟进。只联系客户、不写记录，到点仍会被收回；同时最后跟进时间也不会变，因为没满足跟进规则。
6. **线索池规则配错，销售就"看不见""领不到"**：看不见池通常是"不是池成员"或池类型设成了"成员不可见、仅管理员可分派"；能看见却只看到姓名、公司，是显示设置的字段可见范围太窄；领取时提示达到上限，是撞了领取上限；管理员已分派却还是看不到，则要看角色有没有销售线索的查看权限（管理 - 业务功能权限 - 角色权限设置，按员工角色配销售线索的查看权限）。
7. **分派时只看到几个员工，不是系统丢人**：管理员在线索池里分配，只能分给线索池成员，不是成员的人根本不会出现在候选名单里；要分给某人，先把他加进池成员。
8. **已转换的线索是锁定的**：转换后不能收回、不能换负责人、不能再分配给其他人；作废它需要操作人有线索解锁权限，否则会提示无权限。但已转换完的线索本身可以删除。
9. **作废不等于删除，会挡住后面的新建**：作废的线索还躺在回收站，重新新建或转换同一条线索时会提示"已存在"，让管理员去回收站恢复或彻底删除即可。另外线索挂着审批流程、或状态已是"已转换"时，作废删除会被系统直接拦下。
10. **"明明写了销售记录，状态还是待处理"**：因为线索在"跟进中"状态下被重新分配或换了负责人，状态会自动退回"待处理"，不是记录没保存。同理，超时的线索补一条销售记录就能变回未超时。
