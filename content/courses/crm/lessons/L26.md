# 速览（30 秒看完）

- 业务流＝为达到特定目标、由不同的人分别共同完成的一系列活动，是三大流程里唯一把"人操作的节点"和"自动执行的节点"混在一条线上跑的。
- 配置三步走：新建（空白或选模板改）→ 基本信息（发起对象 / 发起人范围 / 触发条件）→ 流程编排（从左侧拖元素、用箭头连线）；没配完可以先"保存草稿"。
- 编排顺序是**先拖够"阶段"，再在第一阶段放"开始"**，然后按需要放业务、审批、会签、工单、自动、分支、并行节点，箭头指向就是流转方向。
- 一个业务流只能有 1 个开始节点，结束节点可以有多个；开始节点编号只支持数字，按编号执行、不按画布位置。
- 业务节点（口播里叫活动节点）必须有人操作，"保存"和"保存并完成"两个按钮隐藏不掉；处理人有 5 个维度，比审批流多一个"前置任务处理人"，但前置节点有分支时选不到。
- 售前支持申请案例：只有渠道能发起，先由申请人部门负责人初审，通过后才上传合同，再按大区（西南 / 华东）分流到对应售前总监审批并分配售前同事。
- 服务工单案例：客服建单 → 实施团队负责人审批并指派工程师 → 工程师上门填服务记录、拍现场照片；必须用"完成条件"卡住没分配工程师的节点。
- 招投标、SaaS 实施两道配置题都是"先需求分析（字段表 + 流程图），再进练习账号配"，对象和流程按"姓名 + 对象名 / 流程名"命名。

## 核心要点

- **业务流与业务流程管理**：业务流是为达到特定的目标，由不同的人分别共同完成的一系列活动；业务流程管理则是把需要多人协作的任务，借助系统支持做到简单化、自动化。典型场景：退货流程（提交申请→店铺同意→寄回→商家收货→结束）、入职流程（面试→交资料→发 offer→入职）、家电报修流程（客服接单→主管确认→派区域工程师→上门→发满意度调查）。业务流是三大流程里最复杂的一个，因为它同时具备审批流的审批能力和工作流的自动执行能力。
- **节点按"要不要人"分两拨**：需要人动手的是**业务节点**（填字段、传附件，例：安装人员填安装信息）和**审批节点**（同意才能往下走，不同意退回指定节点）；不用人的是**自动节点**（自动变更字段、自动锁定数据）。**会签节点**单独算一类——每个审批人都同意才算同意。另有**工单节点**，能触发工单指派、服务评价、外勤计划、外部企业处理流程，售后场景常用。
- **业务流独有的三个元素**：**阶段**把流程切成"提交申请 / 总监审批 / 申请结束"这样的段落，前端按阶段的名称和编号展示；**业务节点**指向"对哪个对象的哪条数据做什么操作"；**工单节点**承接售后动作。审批、自动、分支、并行、等待这些是审批流和工作流已有的能力，搬进业务流里用。
- **配置三步与拖拽方法**：新建时可从空白起步，也可选已有模板修改 → 配置基本信息 → 配置流程。编排时把左侧元素拖到右侧编辑区，一般**先拖出对应数量的"阶段"，再在第一个阶段里放入"开始"**，之后按需要加其他元素；每个元素之间用箭头连，**箭头指向代表流程运行方向**。整套流程没编辑完之前，可以点右上角"保存草稿"，不用一次配完。
- **基本信息的三个过滤条件**：**流程发起对象**决定只有这个对象的数据能发起（如售前支持申请）；**发起人范围**决定只有范围内的人能发起，可按部门、角色、用户组、具体同事选；**触发条件**再加一道，例：客户级别＝重要客户时才允许发起售前支持申请。再勾上"同一数据进行中不能再次发起"，防止重复提交。
- **开始与结束节点规则**：必须且只能有 1 个开始节点；结束节点可以有多个，不同分支走不同终点。开始节点的编号只支持数字，系统按编号顺序推进——编号 1 先执行、编号 2 后执行，不是按画布上的视觉位置，建议顺着 1→2→3 编。
- **审批节点的五项配置**：**前置条件**（满足这个条件审批人才可以点同意 / 不同意）、**审批内容**（这次审批要重点审核什么，也能顺手填字段）、**审批人**（谁来批）、**同意 / 不同意后分别进入哪个节点**、**完成后**（审批批复后系统自动做什么——变更字段、锁定数据、发通知，作用等同审批流里的按钮后动作）。连线上的**绿色圆点代表同意后的流转路线，红色圆点代表不同意后的流转路线**；线没连出来，同意 / 不同意后的目标节点下拉框里就是空的。各区域售前总监的审批节点，配法和"部门负责人审批"节点基本一样。
- **业务节点的配置项**：① 业务名称（前端会显示）；② 操作对象（默认就是发起对象本身，也可改成编辑关联对象的那条数据）；③ 字段 / 按钮（只能从后台对象管理里预先建好的字段、按钮中选）；④ 处理人；⑤ **完成条件**——处理人必须满足条件才能点"完成"进入下一步，例："售前支持顾问"字段不为空时才允许完成，保证总监确实把人员分配下去了，不加这条人没分配也能一路点下去。系统预设的「保存」和「保存并完成」两个按钮不能隐藏——"保存"只是暂存数据、不推进流程，"保存并完成"才进下一个节点。
- **业务节点的处理人五个维度**：① **前置任务处理人**；② 数据相关人员（数据负责人、相关团队成员）；③ 人员 / 部门 / 角色（固定到某个人、某个部门、某个角色）；④ 关联对象人员字段（如客户对象上的负责人、联系人）；⑤ 流程发起人相关变量（发起人本人、发起人上级、发起人部门负责人）。**"前置任务处理人"只适用于前置节点没有分支的情况**——前置节点有分支时系统不知道这个人是从哪条路过来的，选项里选不到。
- **分支节点**：对一个字段做判断，按内容不同分别流转。售前支持申请里就是按申请人所属区域分流到西南 / 华东售前总监审批，有几个区域就配几个分支，每个出口都要连线，判定条件写在分支上。
- **并行任务节点**：一个业务流里需要多个任务同时执行时用，所有任务都完成后才进下一个节点。例：上传合同完成后，"财务审核合同"和"法务审核合同"同时进行，两个都过了才往下走。
- **自动节点**：不需要人操作，运行到该节点自动执行动作——自动变更某个字段、自动锁定数据、发起其他流程、执行自定义函数等，能力和工作流的执行活动一致，不用为了做个自动动作再出去单独配一条工作流。
- **等待节点**：等条件满足或等到某个时间点再往下走，条件等待（某字段＝某值才继续）和延时等待（等 X 小时 / 天）两种用法。
- **两种触发方式**：① 手动——前端对象详情页点"发起业务流程"，选对应流程；② 自动——先建一条工作流，触发时机选"新建售前支持申请"，第一个活动就选"发起业务流程"，这样订单一建出来系统就自动发起业务流。工作流的条件分支如果没设条件，默认走真分支继续往下执行。
- **案例一（售前支持申请）背景**：某互联网公司，销售遇到规模较大、需求较复杂的项目，可以申请售前同事联合跟进、出解决方案。组织上是两种销售模式——直营含华北、华南两个大区，渠道代理分西南、华东两个大区；**只有渠道体系能提交售前支持申请**；申请时填客户名称、行业、公司规模、商机名称、商机金额、需求描述。
- **案例一节点链路**：渠道销售提交申请 → 申请人所在部门负责人审批（初步判断要不要申请售前资源）→ **审批通过后销售才上传合同** → 按申请人大区由西南 / 华东售前总监审批（**西南审批不通过则重新上传合同；华东审批不通过则直接结束这条业务流**）→ 售前总监批复后分配对应的售前同事跟进 → 售前同事与客户调研后出具售前方案，并把方案文档上传到该申请下。
- **案例一的对象与字段**：流程挂在自定义对象"售前支持申请"上，字段包含客户名称（关联客户）、行业、公司规模、商机名称、商机金额、需求描述、售前支持顾问（人员字段，供售前总监审批时填写分配对象）。**字段要先在后台建好**，否则配流程时字段下拉里选不到，配到一半还得退回去补。
- **案例二（服务工单）字段表**：客户名称（查找关联，必填）、上门时间（日期，必填）、服务工程师（人员，必填）、上门地址（地区，必填）、服务类型（单选：咨询 / 维修 / 安装 / 实施培训，必填）、服务记录（多行文本，非必填）、现场拍照（图片，非必填）。
- **案例二节点链路**：某医疗设备厂商，客户设备出问题打电话要求上门。客服提交服务申请并记录、发起工单 → 实施团队负责人按工单的服务种类审批并指派对应工程师 → 工程师接单后上门服务，填写服务记录并现场拍照 → 对应"派单、工单外勤、工单评价"三段。业务节点上要设完成条件（服务工程师不为空才允许完成），并在操作字段里放出服务记录和现场拍照。
- **三大流程各管什么**：**审批流**用于数据的审核，核心是对数据的判定（新建客户要审）；**工作流**用于执行自动化操作，没有人的参与（新建线索后按条件自动分配负责人）；**业务流**用于围绕一个事件、多个部门不同岗位的人按顺序执行、最终形成闭环（申请售前支持既要审批又要分配售前动作）。发起方式上，审批流和工作流自动发起，业务流需手动发起，但可以通过工作流实现自动发起。
- **流程完成后能干什么（差异题）**：字段变更、发起业务流程、数据锁定 / 解锁、执行自定义函数、外部通知、发送邮件通知三种流程都支持；**CRM 提醒**只有审批流和工作流有；**新建任务 / 日程 / 销售记录**只有业务流和工作流有；**变量赋值只有审批流和业务流有，分配负责人只有工作流有**。完整对照表见下面"三大流程完成后可执行的动作"。
- **配置题一（招投标）需求原文**：① 销售跟进客户、了解招标文件后，在系统发起"投标申请"，附招标文件、写明投标理由、投标时间、开标日期；② 商务助理按招标文件评价公司丢标可能性，做**失分项检查**，给出总失分数及丢分项陈述——**总失分低于 15 分**，由商务部负责人直接指派商务主管制作标书；**总失分大于等于 15 分**，需先由公司分管业务的副总审批，通过后商务部负责人才可以指派，审批不通过则该投标申请结束；③ 商务主管制作完投标文件、上传电子版后，**只有提交人部门负责人和商务部负责人都审核通过**（会签）才可以邮寄给销售同事并记录快递单号、同时发通知给销售同事，不通过则商务主管按要求重做再提交审核；④ 最后销售根据中标结果在申请中记录。
- **配置题一的硬约束与交付要求**：失分项检查要"总分"和"各分项分数"分开建字段，条件分支直接拿总失分字段做 `<15` / `≥15` 的数值比较，不要指望一个字段既存总分又存分项；销售、商务助理、商务部负责人、商务主管、分管副总这些角色（或组织架构）必须先有基础数据，否则节点处理人根本选不到人；做法上要求**先在教材里完成填空部分，再在练习账号里配置**，先出需求分析（把所有字段、需要维护的组织架构、涉及的角色、所有分支列清楚，可用文字或 ProcessOn 画流程图），再出方案设计；对象字段按"字段分组 / 字段名称 / 字段类型 / 选项 / 是否必填 / 说明"六列一张表列全；对象与业务流程按"姓名 + 对象名字 / 业务流程名字"命名；配置完成后界面截图放进新人学习手册。
- **配置题二（SaaS 实施申请）**：某 SaaS 公司做费用报销财务软件，按客户账号数收费，客单价几千到几十万，共 20 位销售同事。合同成交后由销售创建"实施申请单"，关联客户并填预计交付时间、对接人姓名、联系电话，然后走实施业务流程：**软件实施节点填实施附件、实施天数；客户满意度调查填满意级别（非常满意 / 满意 / 不满意）及具体原因、建议**。要求配出实施申请模块和完整流程，并让业务流推进时能直接看到状态：**待审核 → 实施中 → 满意度调查 → 完成**。
- **课程收尾**：三大流程讲完。业务流元素虽多，但一半以上是审批流和工作流的功能展开，把审批流和工作流吃透，业务流就不算复杂；真正新的只有"阶段"和"业务节点"这两块。

## 结构与流程

三大流程的分工与发起方式：

```
审批流（用于数据审核，核心是对数据的判定）
 什么情况下用：新建客户需要审核这类场景
 是否要人：必须（审批人）
 如何发起：自动发起（新建 / 编辑 / 自定义按钮 / 阶段变更）
 核心节点：审批节点（普通 / 会签 / 层级 / 逐级）+ 条件分支 + 协作并行

工作流（执行自动化操作，没有人的参与）
 什么情况下用：新建线索后按某个条件自动分配负责人
 是否要人：不需要（全自动）
 如何发起：自动发起（新建 / 作废 / 恢复 / 字段更新 / 定时）
 核心元素：条件分支 + 执行活动

业务流（围绕一个事件，多个部门、不同岗位按顺序执行并形成闭环）
 什么情况下用：申请售前支持，既要审批又要分配售前动作
 是否要人：必须（执行人 + 审批人）
 如何发起：需手动发起，但可通过工作流实现自动发起
 核心元素：阶段 + 业务节点 + 审批 / 会签节点 + 工单节点 + 自动节点
          + 分支节点 + 并行任务节点 + 开始 / 结束
```

三大流程完成后可执行的动作（课件原表，√＝支持，—＝不支持）：

| 动作 | 审批流 | 业务流 | 工作流 |
| --- | --- | --- | --- |
| 发送邮件通知 | √ | √ | √ |
| CRM 提醒 | √ | — | √ |
| 字段变更 | √ | √ | √ |
| 分配负责人 | — | — | √ |
| 发起业务流程 | √ | √ | √ |
| 数据锁定 / 解锁 | √ | √ | √ |
| 新建任务 | — | √ | √ |
| 新建日程 | — | √ | √ |
| 新建销售记录 | — | √ | √ |
| 执行自定义函数 | √ | √ | √ |
| 外部通知 | √ | √ | √ |
| 变量赋值 | √ | √ | — |

业务流配置步骤：

```
第一步：基本信息
 流程发起对象（只有这个对象的数据才能发起）
 发起人范围（部门 / 角色 / 用户组 / 具体同事）
 触发条件（可选，相当于第二道过滤器，例：客户级别＝重要客户）
 同一数据进行中不能再次发起（建议勾选）

第二步：流程编排（左侧拖元素到右侧画布，箭头指向＝流转方向）
 先拖出对应数量的"阶段"，再在第一个阶段里放"开始"
 阶段 1（阶段名称 + 编号决定前端展示顺序）
 ├── 开始节点（唯一，编号只支持数字）
 ├── 业务节点（业务名称 / 操作对象 / 字段与按钮 / 处理人 / 完成条件）
 │    └── 系统预设"保存""保存并完成"两个按钮，不可隐藏
 ├── 审批节点（前置条件 / 审批内容 / 审批人 / 同意·不同意去向 / 完成后）
 │    └── 连线上绿点＝同意路线，红点＝不同意路线
 ├── 会签节点（每个审批人都同意才算同意）
 ├── 工单节点（工单指派 / 服务评价 / 外勤计划 / 外部企业处理流程）
 ├── 分支节点（按字段判断，按出口分流）
 ├── 并行任务节点（多个子任务同时执行，全部完成才汇合）
 ├── 自动节点（自动改字段 / 锁数据 / 发起流程 / 跑函数）
 └── 等待节点（条件等待 / 延时等待）
 结束节点（可多个，每个分支可独立终点）
 流程未编辑完可点右上角"保存草稿"
```

| 服务工程师 | 人员 | / | 是 |
| 上门地址 | 地区 | / | 是 |

| 服务记录 | 多行文本 | / | 否 |
| 现场拍照 | 图片 | / | 否 |

### 售前支持申请业务流（案例一）节点链路

```
渠道销售提交售前支持申请（客户名称 / 行业 / 公司规模 / 商机名称 / 商机金额 / 需求描述）
 ↓
申请人所在部门负责人审批（初步判断是否需要售前资源）
 ↓（审批通过后才允许上传合同）
销售上传合同（业务节点）
 ↓
分支节点：按申请人所属大区分流
 ├─ 西南大区 → 西南售前总监审批 ── 不通过 → 退回"上传合同"，重传后再审
 └─ 华东大区 → 华东售前总监审批 ── 不通过 → 结束该业务流
 ↓（审批时填写"售前支持顾问"人员字段，完成条件＝该字段不为空）
售前同事与客户调研 → 上传售前方案文档（业务节点）
 ↓
结束
```

### 招投标业务流（配置题一）节点链路

```
销售跟进客户 → 发起投标申请（招标文件 / 投标理由 / 投标时间 / 开标日期）
 ↓
商务助理：失分项检查（总失分数 / 各丢分项陈述）
 ├─ 总失分 < 15 分 ─────────────────→ 商务部负责人指派商务主管
 └─ 总失分 ≥ 15 分 → 分管业务副总审批
 ├─ 通过 → 商务部负责人指派商务主管
 └─ 不通过 → 投标申请结束
 ↓
商务主管：制作投标文件 → 上传电子版
 ↓
会签审批：提交人部门负责人 + 商务部负责人（两人都通过才算通过）
 ├─ 不通过 → 退回商务主管重新制作（回到"制作投标文件"）
 └─ 通过 → 自动节点：记录快递单号 + 通知销售同事
 ↓
销售：按中标结果在申请中记录 → 结束
```

## 术语表

| 术语 | 含义 |
| --- | --- |
| 业务流 | 为达到特定的目标、由不同的人分别共同完成的一系列活动，整合审批流 + 工作流能力 |
| 业务流程管理 | 把企业里需多人协作的任务通过系统支持做到简单化、自动化的管理方式 |
| 阶段 | 业务流的容器，包含若干业务 / 审批节点，名称和编号决定前端展示与执行顺序 |
| 活动节点 | 口播叫法；界面元素名是"业务节点" |
| 业务节点 | 流程运行到该节点需要员工执行具体操作，如填安装信息、上传合同、传售前方案 |
| 审批节点 | 需要审批，同意后继续下一节点，不同意退回指定节点 |
| 会签节点 | 需要每个审批人都同意才视为同意 |
| 工单节点 | 可触发工单指派 / 服务评价 / 外勤计划 / 外部企业处理流程，售后场景常用 |
| 分支节点 | 对一个字段做判断，按内容不同分别流转到不同节点 |
| 并行任务节点 | 多个任务同时执行，全部完成后才进入下一个节点 |
| 自动节点 | 无人操作，自动变更字段、锁定数据、发起流程或执行函数 |
| 等待节点 | 等条件满足或等时间到再继续往下走 |
| 完成条件 | 处理人必须满足该条件才能点"完成"进入下一步，如"售前支持顾问"不为空 |
| 前置条件 | 审批节点上，满足该条件审批人才可以操作同意 / 不同意 |
| 流程发起对象 | 限定只有该对象的数据才能发起这条业务流 |
| 发起人范围 | 只有范围内的人（部门 / 角色 / 用户组 / 具体同事）才能发起 |
| 触发条件 | 满足设定条件才允许发起，例：客户级别＝重要客户 |
| 保存草稿 | 流程未编辑完时先存下来，不必一次配完 |
| 前置任务处理人 | 业务节点处理人的特殊维度，仅适用于前置节点没有分支的情况 |
| 开始 / 结束节点规则 | 开始节点必须且只能 1 个；结束节点可以有多个 |
| 手动触发 | 前端对象详情页点"发起业务流程"按钮选对应流程 |
| 工作流自动触发 | 工作流执行活动里选"发起业务流程"自动触发，条件分支没设条件则走真分支 |
| 售前支持申请 | 案例一的自定义对象，销售为大项目申请售前同事联合跟进 |
| 服务工单 | 案例二的自定义对象，客服记录设备问题并发起上门服务 |
| 失分项检查 | 商务助理按招标文件逐项评失分，给出总失分数与各丢分项陈述 |
| 丢标可能性 | 商务助理评估公司中标的可能性，是投标申请里失分项检查的目的 |
| 实施申请单 | 配置题二的对象，合同成交后由销售创建并关联客户 |
| 变量赋值 | 流程完成后的动作，只有审批流和业务流支持，工作流不支持 |

## 需要注意的点

1. **先写需求分析再动手配**：把所有字段、需要维护的组织架构、涉及的角色、所有分支列清楚（文字或 ProcessOn 画图），再进系统。不然配到一半发现缺字段、缺角色，还得退回去改。
2. **拖元素的顺序别搞反**：先拖出对应数量的"阶段"，再在第一个阶段里放"开始"。顺序反了容易出现阶段套错、开始节点落错地方。整套流程没配完可以点右上角"保存草稿"，但草稿不等于发布，别把半成品当成品交。
3. **开始节点的编号只支持数字**，按编号顺序执行，不是按画布位置。建议按 1→2→3 顺下来，否则界面看着是左边先走、实际是编号小的先走。
4. **审批节点的"同意 / 不同意"去向必须先连线**：线没连到下个节点，下拉框里就是空的，选不了。连好之后线上会出现绿点（同意路线）和红点（不同意路线），别把两条线接反。
5. **"前置任务处理人"要看前置节点有没有分支**：前置节点是唯一路径才选得到，有分支就选不到——系统不知道该处理人从哪条分支来的。
6. **两个系统预设按钮隐藏不掉，完成条件也别漏**：业务节点上的"保存"（只暂存、不推进）和"保存并完成"（保存并推进）必须留着；同时给节点设完成条件，例如"售前支持顾问"不为空才允许完成，否则没分配人也能点过去。
7. **案例一两条分支的失败处理不一样**：西南大区审批不通过是**退回重新上传合同**，华东大区审批不通过是**直接结束这条业务流**。同一张图里两种去向，配错就会把该结束的流程一直退回去。
8. **服务工单的选项按课件原样**：服务类型是"咨询 / 维修 / 安装 / 实施培训"四项，不是"维修 / 安装 / 调试"；客户名称、上门时间、服务工程师、上门地址、服务类型五项必填，服务记录和现场拍照不必填。
9. **会签不是一个人同意就算过**：会签要求每个审批人都同意才视为同意。招投标题里"提交人部门负责人 + 商务部负责人"是两个人，用会签节点，不要用普通审批。
10. **三大流程别搞混，动作支持范围也不一样**：数据要审核 → 审批流；无人参与自动跑 → 工作流；多部门多岗位按顺序走完形成闭环 → 业务流。做完之后的动作里，**CRM 提醒业务流没有，新建任务 / 日程 / 销售记录审批流没有，变量赋值工作流没有，分配负责人只有工作流有**。
11. **条件分支没设条件＝默认走真分支**：工作流里是这个逻辑，业务流里由工作流自动发起时也一样，没条件的路线会被当成"真"直接放行。
12. **驳回回路别漏连**：会签"不通过"必须画回商务主管"制作标书"的业务节点，形成"重做 → 再次会签"的循环，直到通过才往下走。这条线不连，流程就断在半路、数据卡住推不动。
13. **先有基础数据再配节点**：角色、部门、人员没建好，节点处理人下拉框里就选不到人；字段没建好，"操作字段"里也选不到。
14. **同一个东西两个叫法**：这讲的元素在界面左侧叫"**业务节点**"，口播里习惯说"活动节点"，指的是同一个东西；和客户讲或写文档时以界面名称为准。
