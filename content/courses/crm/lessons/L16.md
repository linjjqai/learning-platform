# 速览（30 秒看完）

- 商机管理＝把"客户有购买意向"到交易达成的全过程管起来，本质就是对销售流程的管理。
- 系统里承载数据的是「商机2.0」和「商机2.0明细」对象，新建商机要选客户、产品和销售流程，保存后自动触发阶段推进器。
- 配置四步：分析业务诉求 → 配置字段（管理后台-预设对象-商机2.0）→ 配审批流程（发起对象商机2.0、触发动作阶段变更）→ 配阶段推进器（管理后台-流程管理）。
- 阶段就是商机2.0上系统预置的单选字段「商机阶段」，每个选项要定名称、赢率和阶段类型（进行中/赢单/输单/无效），进行中必须排在终结态前面。
- 阶段任务有五种：编辑对象、创建关联对象（报价单、销售订单）、批量编辑从对象、操作对象、空任务；单个阶段的任务上限是 5 个。
- 审批挂哪里要分清：输单/无效的审批挂在终结态自己身上，进行中阶段之间变更的审批挂在前一个阶段上。
- 高级开关都在"阶段详情"里：允许跳过、完成条件（没做完任务不许推进）、是否触发审批、进入条件、停留时长与超时提醒；输单/无效还能开"支持重新激活"。
- 适合项目型、目标客户是中大型企业、成交周期半个月以上、有明显阶段节点的业务；难点不在系统配置，而在怎么划阶段、定规定动作、定阶段完成标准。

## 核心要点

- **商机与商机管理的定义**：商机是基于对客户的跟进而发掘出的、能够产生商业利润的机会；商机管理就是对这一销售机会与客户不断沟通、分析客户购买产品/服务意愿，直到交易达成的过程，本质是对销售过程的管理。
- **适合用系统管商机的业务与三大目标**：项目型企业、目标客户为中大型企业、客户开发与成交周期长（例如半个月以上）、推进过程有明显关键节点/阶段的业务最适合。这类企业的典型痛点是销售分散过程难管、项目分段控制难且流程触发不智能、缺跟进提醒和风险预警、项目决策链不透彻。本课要解决三件事——说清什么是商机、判断哪种业务模式适合用系统管商机、亲手配一遍商机管理。
- **案例1：三个月的长周期销售流程**：某制造公司成交周期在 3 个月左右，按阶段推进：发现商机→了解商机（收集完善信息）→确认商机（分析业务痛点、判断产品价值、对比竞争对手）→方案论证（方案评审、内部试车）→商务谈判→最终成交或无效。每个阶段标的百分数，代表推进到该阶段时的成交可能性。
- **系统里的三块拼图**：商机2.0对象与商机2.0明细对象承载数据，字段在对象里配，流程内容（阶段、任务、审批）在阶段推进器里配。商机新建时选择对应客户、产品和销售流程，创建成功后自动触发阶段推进器，前端直接显示当前所处阶段和待完成的阶段任务。
- **阶段类型只有四种取值**：进行中、赢单、输单、无效。后三个是终结态，除它们之外的所有阶段都是进行中；赢单赢率 100%，输单、无效赢率各 0%。终结态的名字可以自己起——案例里就把"赢单"这个终结态命名成"已签约"，"已签约（100%）"就是赢单态。
- **阶段的配置方法**：管理后台→预设对象→商机2.0，找到系统预置的"商机阶段"单选字段，编辑选项值即可定义各阶段名称、赢率和阶段类型。阶段名称不能重复（系统提示"选项内容不能相同"），且所有进行中阶段必须排在终结态前面，拖动每个阶段左侧的六个小点排序。
- **不同角色的价值**：员工——流程标准化，新员工照着标准动作就能跟单，还能随时理单；管理层——及时了解每个人的跟进情况、方便理单、科学预测销售业绩、做员工优劣分析；公司——沉淀信息做报表分析、看阶段转化分析、做输单分析。
- **配置第一步：分析业务诉求**：要回答四个问题——确定商机分几个阶段及各阶段的成交概率、确定每个阶段的关键任务、确定每个阶段要产出什么结果以及是否需要审核、确定每个阶段有哪些角色参与。
- **配置第二步：配置字段**：位置是管理后台→预设对象→商机2.0。原则是"每个阶段推进所必须完成的任务字段，都要先配置到商机2.0或相关对象里"，否则后面在阶段任务里根本没得选；商机阶段本身是预置字段，只改选项、不新建。
- **案例2 的字段清单**：客户名称（查找关联，关联客户）、联系人（单行文本）、联系电话（数字）、商机阶段（预置单选）、预计签约金额（金额）、预计进场时间（日期）、输单或无效原因（多行文本）。
- **案例2 的阶段与硬性要求**：需求出现（10%）→信息收集（30%）→商务谈判（60%）→已签约（100%）/输单（0%）/无效（0%）。为保证业绩预测准确，录入商机有准入要求——必须填写客户名称、联系人、联系电话；信息收集阶段必须填预计签约金额、预计进场时间；商务谈判阶段必须创建报价单；变更到输单或无效必须填写输单/无效原因并触发审批。
- **配置第三步：配置审批流程**：到审批流程管理新建审批流，发起对象选"商机2.0"、触发动作选"阶段变更"，节点可按条件分支指定不同审批人，保存后还要回阶段推进器对应阶段勾选"需要触发审批"并选中这条审批流，才会真正触发。
- **配置第四步：配置阶段推进器的入口与结构**：位置是管理后台→流程管理→阶段推进器管理。先做全局配置，把"审批类型"改为"阶段跟进审批"；再新建推进器，适用范围勾选商机阶段字段的各个选项；每个阶段下分"阶段详情"和"阶段任务"两块，逐项配。
- **五种任务类型**：① 编辑对象——商机进入该阶段时需要编辑商机本身或商机所关联对象的字段；② 创建关联对象——选关联或新建一个与商机有关的对象，比如商务谈判阶段建报价单、已签约阶段关联销售订单，可选对象只能是"有查找关联商机2.0"的对象；③ 批量编辑从对象——编辑商机的从对象以完善信息，比如信息收集阶段和客户确定意向产品时批量编辑商机明细；④ 操作对象——操作对象的自定义按钮，用于合同收发、快递收发这类线下动作；⑤ 空任务——本阶段无需线上操作。
- **任务设置的四个附加项**：按钮名称（前端执行该阶段任务时看到的按钮叫什么）、可选数据范围（全部数据 / 已关联商机2.0 / 未关联商机2.0，为避免重复报价建议选"未关联商机2.0"）、谁来处理本业务（这项任务由谁完成）、任务停留时长（允许停留多久以及超时提醒）。
- **阶段详情里的开关**：可设当前阶段允许停留时长（提高处理效率）、完成本阶段进入下一阶段时是否需要触发审批、是否允许跳过此阶段、完成条件（结束本阶段进入下一阶段前必须完成某项或多项任务）、进入条件（进入该阶段之前必须满足什么条件）。
- **终结态的审批挂法**：赢单/输单/无效这三个终结态的审批直接挂在对应的终结态阶段上，商机进入该阶段即触发审批。案例要求"变更到输单或无效需填原因"，就在输单、无效阶段都设置进入时必须填写"输单原因"字段；赢单不需要审批。
- **进行中阶段变更的审批挂法**：进行中阶段之间的变更审批挂在前一个阶段上，含义是"完成本阶段、即将进入下一阶段时触发"。比如从"信息收集"推进到"商务谈判"要审批，这条审批就挂在"信息收集"阶段上。
- **阶段跳过**：在阶段详情把"是否允许跳过此阶段"设为"是"，前端在该阶段就会出现"变更为当前阶段"的按钮，可以直接跳到后面允许跳过的阶段。案例2 的特殊场景是二次成交客户不经过需求出现和信息收集，所以这两个阶段都要开跳过。
- **重新激活**：在输单、无效阶段把"进入该阶段后是否支持重新激活"设为"是"（可配触发条件，如关联客户等级为重客），前端就会出现"重新激活"按钮，把商机回退到任意进行中的阶段继续推进。典型场景是客户暂时无需求被判无效、后来重新产生需求。
- **完成条件与强制推进**：在阶段详情的完成条件里勾选"必须完成的阶段任务"，任务没做完就点"推进到下一阶段"，会被系统直接拦住；不勾选则允许强制推进。案例2 要求"未完成阶段任务不允许往下推进"，就在有必做任务的阶段勾上。
- **回退修正**：已完成的阶段发现信息填错了，直接点前面的阶段，选"回退到该阶段"即可，这是系统自带的标准功能，不用额外配置——阶段推进流程本身就是可逆转、可跳过、可重复执行的。
- **案例3（灯光方案商）的阶段与两处审批**：灯具制造厂商按设计公司的设计方案提供灯光封装解决方案——设计公司有采购需求时销售参与投标，投标后销售和产品线技术人员一起调研需求，技术人员出技术方案、销售出报价方案，通过供应商甄选后销售签合同再生产交付；做这套配置是为了规范销售与设计公司的接触动作、看清各阶段商机分布、把控质量时效与风险。配出的阶段是初步接洽（20%）→需求调研（40%）→方案/报价（70%）→合同签订（90%）→赢单（100%）/无效（0%），两处审批都由"商机负责人的部门负责人"审核：初步接洽→需求调研、方案/报价→合同签订，都遵循"挂在前一个阶段"的规则。
- **案例3 的任务按角色拆分**：初步接洽——数据负责人（销售）"明确客户类型"，改的是**客户对象**的客户类型字段；需求调研——销售维护商机金额、记录竞品情况，售前顾问上传客户需求文档、记录客户关键目标；方案/报价——销售创建报价单，售前顾问更新需求文档、上传初步解决方案文档；合同签订——销售创建销售订单、填写预计收款日期。
- **前端视图与报表**：阶段推进器配好后，列表页可按阶段分组看商机分布，支持阶段视图、商机预测、金额汇总，展示字段可自定义，销售和管理者各配各的。报表能出新增商机数量、商机预测金额、销售漏斗、目标完成率、重点项目排行榜、商机阶段分布图、输赢单分析，都支持按业务需要自定义。

## 结构与流程

### 商机管理配置四步法

```
第一步：分析业务诉求
 └ 分几个阶段、各阶段成交概率 → 每阶段关键任务 → 每阶段产出什么结果、是否需要审核 → 每阶段有哪些角色参与

第二步：配置字段
 └ 管理后台 → 预设对象 → 商机2.0 → 添加/修改字段
 ├ 系统预置：商机阶段（单选，改选项即定义阶段名称、赢率、阶段类型）
 └ 自定义：客户名称、联系人、联系电话、预计签约金额、预计进场时间、输单或无效原因等

第三步：配置审批流程
 └ 管理后台 → 审批流程管理 → 新建（发起对象：商机2.0；触发动作：阶段变更）
 ⚠ 审批流必须在第四步挂到阶段推进器的对应阶段才会触发

第四步：配置阶段推进器
 └ 管理后台 → 流程管理 → 阶段推进器管理
  1. 全局配置：审批类型改为"阶段跟进审批"
  2. 新建推进器：适用范围勾选商机阶段的各个选项
  3. 逐阶段配置：
  ├ 阶段详情（停留时长、是否触发审批、是否允许跳过、完成条件、进入条件）
  ├ 阶段任务（任务类型、处理人、按钮名称、可选数据范围、任务停留时长）
  ├ 审批挂载（终结态挂自己，进行中变更挂前一阶段）
  └ 重新激活（输单/无效："进入该阶段后是否支持重新激活"）
  4. 保存后在前端新建商机测试
```

### 阶段任务与审批挂载对照

```
案例2 阶段：需求出现(10%) → 信息收集(30%) → 商务谈判(60%) → 已签约(赢单100%) / 输单(0%) / 无效(0%)

五种任务类型：
  编辑对象 → 商机本身或关联对象的字段（信息收集阶段填预计签约金额、预计进场时间）
  创建关联对象 → 报价单、销售订单等；可选范围建议选"未关联商机2.0"，避免重复报价
  批量编辑从对象 → 编辑商机的从对象/商机明细（如与客户确认意向产品）
  操作对象 → 操作对象的自定义按钮（合同收发、快递收发等线下动作）
  空任务 → 本阶段无需线上操作

审批挂载规则：
  终结态进入审批 → 直接挂在终结态阶段上（输单、无效进入时需填写输单原因）
  进行中变更审批 → 挂在前一个阶段上（如"信息收集→商务谈判"的审批挂在"信息收集"）
```

### 案例三（灯光方案商）阶段任务拆解

```
创建商机（客户名称 / 商机名称 / 商机金额 / 预计成交时间）
 ↓
阶段一 初步接洽（赢率 20%）
 数据负责人（销售） → 明确客户类型（编辑客户对象的"客户类型"字段）
 ↓ 阶段变更审批①：商机负责人的部门负责人
阶段二 需求调研（赢率 40%）
 数据负责人（销售） → 维护商机金额、记录竞品情况（编辑商机对象）
 售前顾问 → 上传客户需求文档、记录客户关键目标（编辑商机对象）
 ↓
阶段三 方案/报价（赢率 70%）
 数据负责人（销售） → 创建报价单（创建关联对象：报价单）
 售前顾问 → 更新需求文档、上传初步解决方案文档（编辑商机对象）
 ↓ 阶段变更审批②：商机负责人的部门负责人
阶段四 合同签订（赢率 90%）
 数据负责人（销售） → 创建销售订单（创建关联对象：销售订单）
 数据负责人（销售） → 填写预计收款日期（编辑商机对象）
 ↓
终结态：赢单（100%）/ 无效（0%）
```

## 术语表

| 术语 | 含义 |
| --- | --- |
| 商机 | 基于对客户的跟进而发掘出的、能产生商业利润的机会，客户有购买产品或服务的意向 |
| 商机管理 | 把客户购买意向转化为交易达成的全过程管理，即对销售过程的管理 |
| 商机2.0 | 承载商机数据的系统对象，字段、商机阶段都在这个对象上维护 |
| 商机2.0明细 | 商机的从对象，记录商机下的产品明细，可用"批量编辑从对象"任务维护 |
| 预设对象 | 管理后台里维护系统预置对象及其字段的入口，商机相关配置从这里进 |
| 阶段推进器 | 定义商机销售流程的核心配置组件，包含阶段、任务、审批、重新激活等；入口在管理后台-流程管理 |
| 阶段推进流程 | 商机在阶段间流转的整体流程，特点为可逆转、可跳过、可重复执行 |
| 商机阶段 | 系统预置的单选字段，每个选项定义一个阶段的名称、赢率和阶段类型 |
| 阶段类型 | 商机阶段选项的归类：进行中、赢单、输单、无效，后三个是终结态 |
| 赢率 | 每个阶段对应的成交概率，赢单 100%，输单和无效 0% |
| 终结态 | 商机的最终状态：赢单、输单、无效，名称可按业务改名（如"已签约"） |
| 进行中阶段 | 除三个终结态外的所有阶段，排序必须在终结态之前 |
| 阶段详情 | 单个阶段的配置面板，含停留时长、是否触发审批、是否允许跳过、完成条件、进入条件 |
| 任务类型 | 五种：编辑对象、创建关联对象、批量编辑从对象、操作对象、空任务 |
| 编辑对象 | 任务类型之一，编辑商机本身或商机关联对象的字段 |
| 创建关联对象 | 任务类型之一，新建或关联报价单、销售订单等与商机有关的对象 |
| 批量编辑从对象 | 任务类型之一，批量编辑商机的从对象（如商机明细）以完善信息 |
| 操作对象 | 任务类型之一，操作对象的自定义按钮，用于合同收发等线下动作 |
| 空任务 | 任务类型之一，本阶段无需线上操作 |
| 可选数据范围 | 创建关联对象时可选全部数据、已关联商机2.0或未关联商机2.0的数据 |
| 阶段跳过 | 阶段详情里勾选"是否允许跳过此阶段"后，前端可直接跳到该阶段 |
| 重新激活 | 从输单/无效等终结态把商机回退到进行中阶段继续推进 |
| 完成条件 | 结束本阶段前必须完成的某项或多项任务，不勾选则允许强制推进 |
| 进入条件 | 进入该阶段之前必须满足的条件 |
| 阶段停留超时 | 阶段或阶段任务可设允许停留时长，超时前可设提醒 |
| 审批触发动作 | 审批流的触发方式，商机场景选"阶段变更"，发起对象为商机2.0 |

## 需要注意的点

1. **任务类型不是三种，是五种**：除了编辑对象、创建关联对象，还有批量编辑从对象（维护商机明细）、操作对象（对象的自定义按钮）、空任务。另外单个阶段的任务上限是 **5 个**，任务拆得太细会被卡住。
2. **审批流单独建好不会生效**：必须回阶段推进器的对应阶段勾上"需要触发审批"并选中这条审批流。建审批流时发起对象要选"商机2.0"、触发动作要选"阶段变更"，选错了同样不触发。
3. **终结态和进行中变更的审批挂载位置不同**：赢单/输单/无效的审批挂在自己身上，进入即触发；进行中阶段之间变更的审批挂在前一个阶段上。搞反的典型症状是"审批提前弹出来"或"根本不弹"。
4. **阶段名不能重复，顺序也不能随便排**：名称重复会提示"选项内容不能相同"；所有进行中阶段必须排在赢单/输单/无效之前。排序靠拖阶段左侧的六个小点。
5. **阶段已经被历史数据用到就删不掉**：某个阶段上有商机数据依赖时，系统不允许删除该阶段，得先处理历史数据。
6. **没开重新激活，点了就改不回来**：赢单或输单阶段如果没设"支持重新激活"，一旦点选结果就无法再更改。要留后路，就得在输单、无效上都勾上。
7. **历史数据不会自动套用新配置**：改完阶段推进器，已有商机不跟着变。课后思考题里"配了重新激活按钮前端却不显示"，原因就是之前删过阶段推进器里的任务，删除过任务之后再配重新激活，这个配置应用不到历史数据——新配置只对新数据生效。
8. **字段要先建、后配任务**：阶段任务要用的字段，必须先在商机2.0或关联对象上建好；阶段要在商机2.0的商机阶段里先改好。顺序反了，任务配置时找不到字段、找不到阶段。
9. **创建关联对象的数据范围建议选"未关联商机2.0"**：默认选全部数据容易对同一个项目重复报价，选"未关联商机2.0"的数据可以挡住重复关联。
10. **菜单叫法以界面为准**：对象叫"商机2.0"，字段配置在"管理后台—预设对象"，阶段推进器在"管理后台—流程管理—阶段推进器管理"，审批流在"审批流程管理"。口播里说的"对象管理""商机对象"都是旧叫法。
11. **赢单不需要审批，输单和无效需要**：输单/无效进入时要填原因字段（多行文本），所以这两个阶段要配"进入时填写输单原因"，同时挂审批流。
12. **审批被驳回不会往下走**：商机停在原阶段，处理人可以改任务的完成情况后再次推进、重新触发审批，直到审批同意才进入下一阶段。
13. **商机的难点不在配置**：课件明确说，难点在于如何划分商机阶段、划定规定动作、设定阶段完成标准——这是业务问题，配置只是把它落进系统。
14. **两个小提醒别漏**：商机设了预计成交时间，系统会自动提醒商机负责人；线索、客户、联系人、商机的批量导入都适配唯一性规则，导入前先把查重口径想清楚。
