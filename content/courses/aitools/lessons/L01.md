## 速览（30 秒看完）

- 发布覆盖项目全生命周期的全套工具与文档
- 区分"必了解"和"需知悉"，让交付团队知道什么必须做、什么可以缓
- 启动、调研、设计、测试、上线五大阶段各有核心工具
- 推动项目应用，建立持续反馈与优化机制
- 完成培训后能在 AI 项目中直接实操使用

## 核心要点

- **分层掌握策略**：※必了解 = 必须会用的核心工具；△需知悉 = 知道存在、需要时查手册
- **启动阶段核心**：《项目启动会 PPT》明确项目目标、范围、干系人，是后续一切的起点
- **需求调研核心**：《需求调研报告》和《验收标准》直接决定项目交付物是否正确；《调研报告》是补充材料
- **方案设计核心**：《黄金用例集》覆盖最关键的业务场景；《场景实现方案》是用例的详细技术实现
- **试点培训核心**：《用户操作手册》是上线培训的必备材料
- **上线验收核心**：《上线试运行报告》记录上线后运行情况；《运营机制方案》保障后续持续运营

## 结构与流程

```
AI 项目全生命周期工具链
├─ 启动阶段
│   └─ ※ 项目启动会 PPT
├─ 需求调研
│   ├─ ※ 需求调研报告
│   ├─ ※ 验收标准
│   └─ △ 调研报告
├─ 方案设计
│   ├─ ※ 黄金用例集
│   └─ △ 场景实现方案
├─ 试点培训 & 测试
│   └─ ※ 用户操作手册
├─ 上线及验收
│   ├─ ※ 上线试运行报告
│   └─ △ 运营机制方案
└─ 持续优化：应用反馈收集 → 工具迭代
```

## 术语表

| 术语 | 含义 |
| --- | --- |
| 黄金用例集 | 覆盖最关键业务场景的核心用例集合，是方案设计的基石 |
| 验收标准 | 项目交付物需要满足的具体条件，是上线验收的依据 |
| 场景实现方案 | 针对黄金用例的详细技术实现方案，包含配置步骤和代码示例 |
| 运营机制方案 | 上线后保障系统持续运行和迭代的运营机制设计 |

## 需要注意的点

1. 不要跳过验收标准的编写——很多项目上线争议就是因为没有白纸黑字的验收标准
2. 黄金用例集不是用例越多越好，10-20 个最关键的场景覆盖 80% 风险才是高效做法
3. 用户操作手册要和实际界面同步更新，上线后再改会陷入重复劳动
